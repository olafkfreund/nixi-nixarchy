# Plan: Open Nixi with a question already asked

## Approved decisions (carried over from the spec)

- **`Ask.qml` `askFromSummon(conversation, payload)`:** trim `payload.prompt`,
  and ignore it if empty. If `conversation.waiting` or the text starts with
  `/`, call `conversation.setPrompt(text)` (fill only). Otherwise call
  `conversation.askQuestion(text)`.
  - A hand-off never runs `/guide`, `/mechanic`, `/tour` or `/learn`, and
    never steers or interrupts a running turn.
- **Callers:**
  - **New card:** in `createConversation`, next to `tour` and `learn`,
    `action === "ask"` calls `askFromSummon`.
  - **Open, unpinned card:** in `open()`, parse the payload before the early
    return, and for `action === "ask"` call `askFromSummon(activeOverlay, …)`.
    Other payloads are unchanged.
  - **Pinned cards:** they are never the target; a new overlay card asks.
- **`Conversation.qml` `setPrompt(text)`:** set the text, focus, and put the
  cursor at the end.
- **`bin/nixi --ask <prompt>`:**
  - A missing or empty argument exits 64.
  - `card_ready || exit 1`.
  - Escape in bash (`\`, `"`, newline, tab), then `exec omarchy-shell shell summon "$PLUGIN" '{"action":"ask","prompt":…}'`.
  - Update the header args line and the usage line.
  - No jq.

## Deviations and results

### Step 6: razer check
- **Build:** the branch was built as the real Nix package on razer (`nix build path:…#default`) instead of copying files. razer's installed Nixi is 0.10.0 from an older commit, and the package patches store paths (for example `bridge/nixi-node`) into the QML, so a file swap would have mixed versions.
- **Plugin code needs a shell restart, not a reload.** Re-pointing the plugin symlink logs "Local plugin changed, reloading", but the reload keeps the old compiled QML, because the component URL is unchanged and Qt caches it. Only `omarchy-restart-shell` loads new files. This first looked like a #37 bug ("hand-offs ignored after a reload"). Temporary `console.log` instrumentation showed the new `Ask.qml` never ran until the shell was restarted. The instrumentation was not committed.
- **Test agent:** razer has no `claude-agent-acp`, so the checks used opencode. `~/.config/omarchy/nixi.json` `agent` was set to opencode with `model` removed; its Claude model is invalid for opencode. It was restored afterwards.
- **Interference:** another session ran Home Manager activation and restarted razer's shell during the first attempts, which re-linked the plugin. Those runs were discarded.

### Results (branch build, fresh shell, opencode)
- **No card open:** `nixi --ask "how do I add a font?"` opened a new card and submitted the question.
- **Open, idle card:** the question was asked in it, and opencode answered. No second card opened.
- **Busy card:** `and a theme?` was only prefilled. Log: `askFromSummon … waiting=true` → `setPrompt`. The running turn was not steered.
- **Slash text:** `/guide` was only prefilled, and `nixi.json` `trust` stayed `mechanic`.
- **Permissions:** the handed-over question went through Nixi's normal "Permission required" dialog (`nixos_nix`).
- **Observed interplay:** text handed over while a permission dialog waits sits in the prompt, so the dialog's Y/N keys need the box cleared first ("Clear the message box to answer with Y or N"). This is Nixi's existing rule for a non-empty prompt, unchanged by #37.
- **Restored:** razer's link, `nixi.json`, `defaults/agent` and a fresh shell.
