# Plan: keep the window token out of server.log

## Decisions (from the approved spec)

- The window loads `http://127.0.0.1:<port>/?native=1`, with no fragment,
  ever.
- It hands the page the token through a WebKit2 4.1 user script:
  `WebKit2.UserScript.new(source, TOP_FRAME, START, ["http://127.0.0.1:<port>/*"], None)`,
  where the source is `window.__nixiT=<json token>;`. Before each load, it
  removes old scripts with `remove_all_scripts()`.
- `token_script(tok, port)` is a pure helper that returns
  `(source, allow_list)`.
- The page reads `window.__nixiT` first and then deletes it. `#t=` and
  `#ticket=` stay.
- `load-failed` on a URI under the server's origin retries after 1 s: it
  reads the token again, hands it over and loads, and returns `True`.
- Console-to-stdout stays on. No ticket, no log scrubber, no stdout
  filtering.

All code is in olafkfreund/nixoarchy-snowflake. Work in a new worktree,
`../nixoarchy-snowflake-181`, on branch `fix/181-token-in-log` from
`origin/main`.

## Deviations

- **Step 1: `load-failed` ignores cancelled loads** (2026-11-04, found in
  review of Codex's diff). WebKit fires `load-failed` with
  `WebKit2.NetworkError.CANCELLED` when a newer `load_uri` replaces a load
  in flight (for example `reauth` during a load). That isn't a failure, so
  the handler returns `False` for it and doesn't schedule a reload. Step 3
  tests it.

- **Step 1: the allow-list is host-only, and the script checks the origin**
  (2026-11-04, Codex's PR review, then confirmed in real WebKit). WebKit's
  user-script allow-list matches the host but never the port:
  `http://127.0.0.1:<port>/*` never ran, so the window would have had no
  token. It's now `["http://127.0.0.1/*"]`, and the source is
  `if(location.origin==="http://127.0.0.1:<port>")window.__nixiT=…;`, so no
  other port on 127.0.0.1 gets the token.
  `tests/test_window_webkit.py` runs the real `token_script` in WebKit
  (an off-screen window). The right port gets the token, another port
  doesn't. It skips without a Wayland session or the typelibs. With the
  port put back, it fails.
- **Step 1: a retry never waits on the main thread** (agy's PR review). A
  `load-failed` retry reads the token once (`_token(tries=1)`). Without
  that, a missing `runtime.json` would freeze the window for 5 s of every
  6. Startup and `reauth` keep the 5 s wait.
