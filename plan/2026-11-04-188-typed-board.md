# Plan: A question typed while the mic is open gets its board

## Decisions (from the approved spec)

Clicking Nixi opens the mic; Return then opens the ask box with the mic still
open, so `stageShow` declines the board and you get a caption.

1. A cancelled recording is gone at once: `stopRec(true)` clears `rec` and its
   own caption. `startRec` ignores whatever it still reports: text, `listening…`,
   sound, `…`, clipping note and mic errors, including the silent-mic one.
2. `transcribing` does not clear early. Whisper can't be interrupted, and the
   server holds `Listen.lock` until it finishes, so the `rec||transcribing` check
   keeps the mic from restarting. `stageShow` doesn't read `transcribing`.
3. Opening the box, sending any question, and anything that waits before it
   sends all drop the recording. `approve` recordings are spared.
4. The `rec` check in `stageShow` stays: a board arriving while you're really
   listening is still a caption.
5. The server keeps the follow-up window shut while the box is open, with one
   `Wake.held` flag read only in `talking_until`. Holding also closes a window
   already scheduled. Ending the hold reopens nothing.
6. Cancelling the follow-up window drops speech being transcribed, unless it was
   "hey Nixi". A window that simply ran out keeps its speech. Speech from before
   a new window is dropped.
7. "Hey Nixi" works with the box open.

Accepted costs (approved in the spec, do not fix): a stray key while talking
throws that speech away; he looks like he's thinking while typing if Whisper is
running, and a click or Space does nothing until it ends; a second Esc in that
time goes on to the next Esc action, which can hide him; a stale
`/api/listen/stop` or a mic restart in the gap needs millisecond timing and loses
a recording, never sends one; hold posts out of order can leave the flag on until
the box next opens and closes or the page reloads; the next approval's voice
answer can overlap the old recording's shutdown, and gives up on voice if the old
one is still transcribing. No recording ids.
