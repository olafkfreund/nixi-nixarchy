# Plan: News clips with previews in the news slip, played in mpv

## Approved decisions (from the spec, so this file stands alone)

- **Code:** `olafkfreund/nixoarchy-snowflake`, branch `feat/174-news-video` from
  `main` `655bbe9`, worktree `../nixoarchy-snowflake-174`. Artifacts in
  nixi-nixarchy, branch `feat/174-news-video`. Line numbers are from
  `655bbe9`; re-find them by the quoted code.
- **Scope:** only the plugin with id `news` may ask for clips.
- **Manifest key `videos`** (bool) in `STAGE_KEYS`. `_check` refuses a non-bool,
  and `videos: true` on any id but `news`.
- **Capability text:**
  - `plugin_caps`: "Can search YouTube for news clips (off in its settings)".
  - The consent card shows the same line. `needs_consent` carries
    `"videos": bool`, and `plugConsent()` renders it.
- **`video_query`** on `headlines`: `_str(…, 60)` (stripped), then 3–60
  characters matching `[A-Za-z0-9 '-]+`; anything else refuses the stage.
  `Store.put()` drops it from the page copy.
- **Settings merge:** `read_config` returns `{**defaults, **user}` for a good
  user file. A missing or bad file still means the defaults, with the same
  note as before.
- **Cache key, from one read of the settings:**
  - New `read_user_config(pid)` returns `(user dict or None, note)`. Only the
    user's file is opened here, with the same checks as now.
  - `read_config(pid, snap_dir, user=None)` merges a given `user` result over
    the snapshot `defaults.json`. Without one, it reads the file itself, as
    today.
  - In `run_stage`, after `_consented(p)`, a `config: true` plugin calls
    `read_user_config` once. Its key adds
    `sha256(json.dumps(user, sort_keys=True))`, and the same `user` result is
    passed down `_launch` to `_run_copy`, which merges it with the snapshot's
    defaults. The file is read once per ask, and the key describes exactly
    what the plugin got. The defaults are fixed by the consented hash, so
    they don't need to be in the key.
- **Search:** `video_search(query, run=…, newest=False)`. `newest=True` uses
  `"ytsearchdate3:"`.
- **The thread:** `plugin_stage()` starts `news_clips(page["copy"],
  st["video_query"])` after showing a `headlines` stage, when the stage has
  `video_query` and the manifest has `videos: true`. It never passes its own
  `query`.
- **`news_clips`:**
  1. waits on a module `threading.Lock()`;
  2. returns if `STAGES.current()` is not this slip (compare `copy`);
  3. runs `video_search(…, newest=True)`;
  4. **returns if there are no results**;
  5. calls `STAGES.add_clips(slip, items)`;
  6. on a page, `BUS.pub(t="stage_update", **stage_event(page))`.
- **`Store.add_clips(slip, items)`:** under the lock it requires all of:
  - `items` is non-empty;
  - the current stage is live;
  - its kind is `headlines`;
  - its page `copy` equals `slip`;
  - it has no `clips` yet.

  Then, on copies of the page and token map:
  - adds `clips` rows `{title, channel, duration, play, thumb}`, with
    `("video", {"url"})` and `("thumb", {"id"})` tokens as in the `video`
    branch of `put()`;
  - rewrites the `copy` token's text to add "Watch:" and one line per clip.
    **The clip line format is shared** with `stageText`: the title, then
    " — " and the non-empty parts of channel and length joined by ", ". The
    title alone if both are empty.

  It keeps `prev`, `vis` and the age (`born`), and returns the page, else
  `None`.
- **Voice:**
  - `_ACT` gains an optional noun group `(?:\s+(one|video|clip))?` after the
    ordinal or after it/that/this. The ordinal group keeps its index.
  - `fast_path`:
    - a video or clip noun on any kind but `headlines` or `video` → `None`;
    - a video or clip noun with any verb but `play` → `None`;
    - on `headlines`, `play` targets `clips`: `n = len(clips)`; `n == 0` →
      `None`; ordinals bounded by `n`; it/that → `("play", 0)` if `n == 1`,
      else `("ask", None)`;
    - on `headlines`, `open` (no video or clip noun) → stories, as today;
    - on `headlines`, copy → `("copy", 0)`, as today.
  - The handler: `play` on `headlines` takes the item from `vis["clips"]`.
  - **`plugins.reserved()`** (`plugins.py` 47) tests a phrase against
    `fast_path` with a kind-less dummy stage. It also tries `{"kind":
    "headlines", "items": [0]*5, "clips": [0]*3}` and `{"kind": "video",
    "items": [0]*3}`, so "play the first video" stays reserved and no plugin
    can claim it.
- **The news plugin:**
  - `run` keeps the whole stdin object, so it can read both `query` and
    `config`.
  - Settings: `videos` (default true), `topics` (default map below) and
    `default_topic` (default `"world"`).
  - The query is lowercased, everything but `[a-z0-9 ]` becomes a space, and
    it is split into words. The first word that is a key of `topics` wins,
    else `default_topic`.
  - The mapped value, if it passes the character rule, becomes `video_query`,
    on the `headlines` branch only. There is none with `videos: false`, a
    non-dict `topics` or a bad value.
  - The default `topics`: world → "world news", uk → "UK news", tech and
    technology → "technology news", business → "business news", science →
    "science news", sport and sports → "sport news".
- **The page:**
  - `stagePress` renders `ev.clips` below the stories:
    - a small-caps "Watch" label over a hairline;
    - per clip, a 96×54 poster `<img>` from the thumbnail route (`alt=""`,
      hidden on `error`), the title (serif, two lines max), and "channel ·
      length" in small caps (no " · " when the length is empty);
    - a Play `<button>` with `aria-label` "Play: <title>" posting `{token,
      act:"play"}`.
  - `stage_update` with `kind === 'headlines'` applies only if `stg.kind ===
    'headlines' && ev.copy === stg.copy && stgState !== 'closed'`. It replaces
    the Watch section only (the stories aren't rebuilt, so focus survives),
    stores the clips on `stg`, and sets `stgUse` to now.
  - The rows fade in 40 ms apart, with no animation under `REDUCED`.
    Contrast ≥ 4.5:1.
  - `stageText` adds "Watch:" and the clip lines.

## Deviations (made during implementation)

- **Step 1:** `_launch` and `_run_copy` take `user=None`, which holds the whole
  `read_user_config` result, `(dict or None, note)`. A bare `None` couldn't
  tell "not given" from "no file". Two existing tests changed to expect the
  merge (`test_good_file_wins` and the settings-on-stdin test), and one fake
  `launch` gained `user=None`. "stdin equals the key" is checked indirectly:
  one read, and the merged stdin.
