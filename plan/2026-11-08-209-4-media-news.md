# Plan: #209 part 4, media and news

The last of the four plans under the approved #209 spec. Media tells a video from music, so headphones stop showing
for a video; news notices new headlines from feeds you chose and offers one quiet line. Media ships after #208, as
the spec orders, because #208 changes the same `playerctl` call; #208's approved scope has no video art (popcorn), so
a video shows no prop until a follow-up draws one (open question 3). News could go earlier if review is easier.

2. Thresholds as written: news every 30 minutes, a seen-set of 5.
3. A video shows no prop for now, because #208 has no popcorn; a #208 follow-up issue covers it.

## Decisions carried over from the approved spec

- **Media, gated by `look_music` as today.** `sense` replaces `playerctl -a status` with one `playerctl -a metadata
  --format` call at the same 5-second step. For each `Playing` line: **video** if the player is `freetube` or
  `grayjay`, or the URL's host is, or ends in `.` plus, one of `youtube.com`, `youtu.be`, `twitch.tv`, `vimeo.com`,
  `netflix.com`; **music** otherwise (today's behaviour, so mpv and VLC count as music unless their URL says
  otherwise). `situation` gains `video`; `music` is `True` only for music; video wins if both play. The URL is used
  only for the host check and isn't kept, sent or logged. A player with no URL stays music.
- **Not verified:** what Firefox, Chromium and mpv report, with several players, and with no metadata. The plan
  starts by checking these on p620.
- **News:** a new setting `"news_watch": False`, its own switch because it runs a network plugin unasked.
  - Only from feeds you chose: the spec says it runs only when `plugins.config_path("news")` exists (the plugin's
    `defaults.json` feeds don't count). The code shows that isn't enough: an unreadable file or `{}` falls back to
    the default feeds (`read_config`, `plugins.py:214-218`). So the plan requires a saved, readable config with a
    non-empty `feeds` list of its own (review finding, tightening the spec's rule, not changing it).
  - Off the sensing loop: every 30 minutes, while `proactive` and `news_watch` are on, Nixi isn't hidden and the
    `news` plugin is enabled, `Ambient` starts one background thread, never two, that calls `plugins.run_stage(p,
    "news", locale)`: same sandbox, consent check, time limit and 5-minute cache as an asked run. It never starts the
    video search. The result is used only if the switch, the plugin and its consent are all still on when it returns.
  - What's new: the last run's items, at most 5, as hashes of source and title, in memory only. The first run, and
    the first after the feeds change (by the config hash `run_stage` uses), only record. New items offer `news`,
    "<n> new headlines.", visual only. Titles aren't spoken, shown in the caption, sent to an agent or logged.
