# Plan: Location — Home, Work and where I am now, set by me

Two code repos, artifacts here:

- **`nixarchy`**, branch `feat/nixi-152-location` from `main`: steps 1 to 3.
- **`nixoarchy-snowflake`**, branch `feat/152-location` from `main`
  `a0c5b31`: steps 4 to 6.
- **Order:** nixarchy ships first. The companion works without it (step 4's
  file fallback), but its settings write through `nixarchy-location`.

The coder agent implements steps 1 to 6, one at a time, and the lead commits
each step. The plan has six editing steps across two repos, which is above
the handoff threshold.

## Approved decisions (from the spec)

- **`weather.json` is the current place**
  (`~/.local/state/omarchy/settings/weather.json`, `{name, latitude,
  longitude}`).
  - Its format and owner (upstream `omarchy-weather-location`) are unchanged,
    and the bar's picker keeps working.
  - **The file existing means you chose the place; a missing file means an IP
    guess.**
  - Wi-Fi writes add `"source":"wifi"`.
- **`places.json`**, next to it: `{home?, work?, wifi?: {<network>:
  "home"|"work"}}`. Each place is `{name, latitude?, longitude?}`.
  - **Migration:** if `weather.json` exists and there's no `home`, copy it
    into `home` once.
- **`nixarchy-location`** (bash, nixarchy `pkgs/`):
  - no arguments: the current place and how it was set;
  - `set home|work <name> [lat,lon]`;
  - `now home|work|auto`;
  - `wifi link home|work` (the current network);
  - `wifi unlink <network>`;
  - `apply`;
  - `--json`.
  - Writes are atomic (temporary file, then `mv`), with the same coordinate
    regex as upstream. The command never touches the network.
- **`apply`:**
  - on a linked network: write that place with `"source":"wifi"`;
  - on an unlinked network: clear `weather.json` only if it has
    `"source":"wifi"`. A place you picked is never touched.
- **Watcher:** a user service runs `nixarchy-location watch`, which follows
  `nmcli -t monitor` and calls `apply` when a connection comes up. It's
  event-driven.
  - **One refinement of the spec's "started only when a link exists":**
    `watch` exits at once (status 0) when the machine has no Wi-Fi device,
    and `apply` does nothing when there are no links. `wifi link` runs
    `apply` itself, so adding the first link takes effect without a restart.
  - The aim is the same: a wired desktop never runs it.
- **Companion:**
  - `location()` runs `nixarchy-location --json` (argv, 2 s timeout) and
    caches the result for 60 s. If the command is missing, it reads the two
    files directly. It never makes a network call of its own.
  - **The agent note** gets `The user is in <name>.` only when `weather.json`
    exists, plus the `@home` / `@work` rule for directions.
  - **`dest` `@home` or `@work`:** the server swaps in the stored place. If
    it isn't set, the card says "Set Home in Nixi's settings", with a
    Settings button and **no Google token**.
  - **The map's start point:** `origin=` (coordinates if present, otherwise
    the name) only when `weather.json` exists. The footnote reads "From
    <place>".
  - **Never sent:** an IP guess, `places.json` itself, the Wi-Fi network
    names.
- **Settings, a "Location" section:**
  - **Now:** Home, Work or Auto, with the resolved line;
  - **Home** and **Work:** a field with Open-Meteo suggestions (`count=5`),
    fetched by the server, not the page;
  - **Wi-Fi** (only when there's a Wi-Fi device): "Link <network> to Home /
    Work", and the existing links with ✕.
- **Menu:** Setup → Location opens the bar's weather panel for people without
  Nixi. Home, Work and Wi-Fi stay in Nixi plus the command.
- **No Google "Home" button.** The spec's open question 1 wasn't answered,
  and nothing depends on it. It can be added later as a deviation.

## Steps

**1. nixarchy: `pkgs/location.sh` → `nixarchy-location`**
- **New `pkgs/location.sh`**, implementing the command above:
  - its paths are under `${XDG_STATE_HOME:-$HOME/.local/state}/omarchy/settings/`;
  - it reads the current network with
    `nmcli -t -f TYPE,STATE,CONNECTION device`, taking the first
    `wifi:connected:<name>` line.
- **Package:** add `nixarchy-location = final.writeShellApplication { … }`
  to the overlay in `flake.nix`, beside `nixarchy-explain` (~`:681`), with
  `runtimeInputs` `coreutils jq networkmanager`.
- **Install:** beside `nixarchy-explain` in `modules/apps.nix:1209`.
- **Test:** add `pkgs/location.test.sh`. It sets a temporary `HOME` and puts
  a fake `nmcli` on `PATH`. Run it as a flake check, the way the repo runs
  its other script checks.
  - Cases: `set` / `now` / `--json` round-trip; migration happens once;
    `apply` on a linked network, and on an unlinked one, for both a Wi-Fi
    place and a picked place; a bad coordinate is refused and the file is
    unchanged; `omarchy-weather-location` still reads the place (stub it if
    it isn't on `PATH` in the check).
- **Verify:** `nix build .#checks.x86_64-linux.<location check>`, then
  `nix flake check`, or the repo's documented subset.
- **Traps:**
  - Read `pkgs/AGENTS.md` first. Every tool the script calls must be in
    `runtimeInputs`: the "vainfo trap".
  - `writeShellApplication` runs shellcheck.
  - Never write `weather.json` keys other than `name`, `latitude`,
    `longitude` and `source`.

**2. nixarchy: the watcher service**
- Add `nixarchy-location-watch` to `systemd.user.services` in
  `modules/home.nix` (~`:1283`):
  - `After` and `PartOf` `graphical-session.target`;
  - `ExecStart = nixarchy-location watch`;
  - `Restart=on-failure`, with `RestartSec=30`.
- **`watch`:**
  - exit 0 when `nmcli -t -f TYPE device` has no `wifi`;
  - otherwise run `apply` once, then read `nmcli -t monitor` lines and call
    `apply` on lines that say a connection is in use or connected (match
    loosely, and test it with captured sample lines);
  - debounce to one `apply` per 2 s.
- **Verify:** extend `location.test.sh` with a fake `nmcli monitor` that
  prints sample lines, then evaluate the module the way the repo's tests do.
- **Trap:** a user unit doesn't inherit the login `PATH`. Use the store path
  of the command, as `omarchy-theme-gnome` does.

**3. nixarchy: the menu row**
- Add `setup.location` to `overrideSpec` in `modules/apps.nix` (~`:334`):
  label "Location", with a pin icon.
  - **Action:** open the bar's weather panel if upstream has a command or
    IPC call for it. Search the upstream shell for one.
  - **Otherwise:** `omarchy-launch-floating-terminal-with-presentation
    nixarchy-location`, where `nixarchy-location` with no arguments also
    prints the usage lines. If you take this fallback, record it as a
    deviation.
- **Verify:** `.github/scripts/check-menu-mapping.py`, or the repo's menu
  check, passes.

**4. Companion: reading the location; the map and the note**
- **`app/server.py`:** `location()` beside `Ambient` (`:1048`), as above.
  It returns `{"now": {...}|None, "chosen": bool, "home", "work", "how"}`.
- **`app/stages.py`:**
  - `validate` accepts the place `dest` `@home` or `@work` (`:107`);
  - `maps_url(dest, mode, origin=None)` (`:250`) adds
    `&origin=<quote_plus>` only when it's given.
- **`Store.put` for a place:**
  - resolve `@home` and `@work` through a resolver passed in by the server;
  - when the place is unset, send the page `{unset: "home"|"work"}`, with no
    open token, only a copy token if any;
  - when a place is chosen, pass `origin` from `location()`, and add
    `from: <name>` to the page event.
- **`run_bridge` note** (`:3800`): add the location line and the `@home` /
  `@work` rule as decided.
- **Tests:** in `tests/test_stages.py` and `tests/test_stage_actions.py`,
  every Verification bullet for the companion in the spec.
- **Verify:** `python3 -m unittest` on `tests/test_stage*.py` (there's no
  pytest).

**5. Companion: the Location settings section and API**
- **Server:**
  - `GET /api/location` returns `location()` and `wifi: <current network
    or null>`, plus whether there's a Wi-Fi device.
  - `POST /api/location` takes `{act: "set"|"now"|"link"|"unlink", …}`. Each
    one runs `nixarchy-location` as argv, after validating the place
    (`home` or `work`), the name (at most 120 characters, no control
    characters) and the coordinates (the same regex). Clear the cache
    afterwards.
  - `GET /api/location/suggest?q=` calls Open-Meteo geocoding
    (`count=5&language=en&format=json`, 4 s timeout) and returns
    `[{name, admin, country, latitude, longitude}]`.
  - All three need the usual window token.
- **`app/static/index.html`:** a "Location" section in the settings, near
  the Answer stages toggle (`:726`):
  - the Now segmented control (Home, Work, Auto) and the resolved line;
  - the Home and Work fields, with a suggestion list (arrow keys and Enter);
  - the Wi-Fi block.
  - Everything is set with `textContent`.
- **The map card** (`stageMap`, `:1985`):
  - the footnote is "From <from>" when present;
  - the `unset` state shows the text with a **Settings** button that opens
    the Location section.
- **Tests:** API validation (bad place, name or coordinates are refused, and
  no argv is built), plus `stages_fit.mjs` cases for the section and for the
  unset card.
- **Trap:** the page is GPU-sensitive. Previews only in headless Chromium
  with `--disable-gpu`; no `backdrop-filter`.

**6. Companion: the headless preview**
- The lead takes previews of the Location section and the "From <place>" and
  unset map cards, GPU-free, and checks `journalctl -k` afterwards.

**7. Review, PRs, deploy, live check** (the lead)
- **Review:** a fresh Opus review of each repo's diff against this plan, plus
  `codex review --base`.
- **PRs:** nixarchy first. CI must be green, then merge. Then the companion.
- **Deploy:** bump `nixarchy` and `nixi-companion` in nixos_config, build
  p620, open and merge the PR, pull, post on the agent bus, then deploy p620
  and razer. Restart Nixi on both.
- **Live:** the spec's checks. On p620: Home, then Now = Home, then "From
  Home" on the map. On razer: link `home`, toggle Wi-Fi, then a hotspot →
  Auto.

## Rollback

- **Companion:** revert its merge. Nixi goes back to no location, and the
  stored files are left alone.
- **nixarchy:** revert its merge. `weather.json` keeps working with the bar.
  `places.json` is left behind, unused and harmless.
- Then bump nixos_config and deploy p620 and razer the usual way.

## Deviations

- **Step 1** (2026-11-03, nixarchy `feat/nixi-152-location`).
  - **The test** is `tests/location.nix`, registered as `checks.location`,
    because that's this repo's pattern for script checks. It is not
    `pkgs/location.test.sh`.
  - **`apply` with no links** still clears a Wi-Fi-written place. Otherwise
    a stale place would stay after the last `unlink`.
  - **`wifi unlink` also runs `apply`.**
  - **`--json`** returns `{now, chosen, how, home, work}`. The Wi-Fi details
    come from step 5's API.
  - **`set home|work`** rewrites `weather.json` when it holds that place's
    old value, and keeps `source`. Changing Home while you're at Home then
    updates the bar straight away.
