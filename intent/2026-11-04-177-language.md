# Intent: Let each user choose Nixi's language

## Problem

Nixi works in English only, and a user who speaks another language can't
change it:

- **Listening:** speech recognition uses Whisper's English-only models
  (`tiny.en`, `base.en`, `small.en`, `medium.en`; `app/server.py` ~143,
  ~2511). `CFG["language"]` is `"en"` and is passed to the transcriber
  (~2551), but the `.en` models can't recognise anything else, and Settings
  only allows `.en` models (~5521).
- **Speaking:** the presets are English voices (Kokoro `af_*`/`am_*`, piper
  `en_US-*`, espeak `en-us`). An English voice reading French sounds wrong.
- **Answering:** the agent answers in whatever language the question came
  in, but nothing tells it the user's language. A misheard English
  transcript of French speech starts the whole chain wrong.
- **Wording:** the page and his own fixed lines ("Here you go.", "Opening
  it.", "Which one?…") are English, and the voice shortcuts ("open the first
  one", "close", "go back") are matched in English.

Different people use the same machine, or the same setup on different
machines, in different languages.

## Proposed outcome

- Settings has a **Language** choice. It defaults to the system locale, then
  English.
- With a language chosen:
  1. **He understands it:** speech recognition uses a multilingual Whisper
     model set to that language.
  2. **He speaks it:** the voice list offers voices for that language. An
     engine with no voice for it says so and suggests one that has.
     ElevenLabs voices are multilingual (#176).
  3. **He answers in it:** the agent is told the user's language and replies
     in it.
  4. **His fixed lines and voice shortcuts work in it,** for the languages
     that have a translation. The rest fall back to English and say so in
     Settings.
- Each user (each login on each machine) has their own choice, like the other
  settings.

## Affected users and systems

- Fork `olafkfreund/nixoarchy-snowflake`:
  - `app/server.py`: speech recognition model and language, voices, the
    prompt note, fixed lines;
  - `app/stages.py`: voice shortcut matching;
  - `app/static/index.html`: Settings, page wording.
- Whisper models: multilingual models are bigger, and the first use
  downloads one.
- p620 and razer (and any user of the companion).

## Constraints

- **Must:** English users see no change unless they pick another language.
  The `.en` models stay the default for English, because they're faster
  and more accurate in English.
- **Must:** changing language never leaves him deaf or mute. If the model or
  voice for the new language isn't ready, he says so and keeps the old one
  until it is.
- **Must:** nothing leaves the computer for this. Models download from the
  same places as today, and translations are shipped in the app.
- **Must not:** translate the user's content (news headlines, file names,
  answers) by machine. Only Nixi's own fixed text is translated.
- Plugins keep receiving `locale` as they do today (`run_stage(…, locale=…)`),
  now set from this choice.

## Open questions

1. **Which parts of "language" are in scope now?** Recommended: all four
   (listening, speaking, answering, his fixed lines and shortcuts), with the
   page's labels in a later step. Settings is large; translating it first
   would delay the parts that make him usable in another language.
2. **Which languages first?** Recommended: English plus the languages the
   users here need. The user to name them (e.g. Norwegian, Polish, German,
   Spanish). Each needs a Whisper language, at least one local voice, and
   translated fixed lines.
3. **Per user or per machine?** Recommended: per user, saved with their other
   settings, so two people on one machine can differ.
4. **Mixed languages?** Recommended: one chosen language at a time, with
   Whisper's auto-detect available as an "Automatic" choice for people who
   switch. Automatic is less accurate on short commands.
