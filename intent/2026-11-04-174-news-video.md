# Intent: News clips with previews in the news slip, played in mpv

## Problem

"Show me the latest world news" answers with the news slip (#167): up to five
stories with a source, an age and an Open button that opens the article in the
browser. The slip has no video. The user wants YouTube news clips in the same
list, each with a preview picture, and a way to play one directly in mpv (or a
similar player) instead of a browser tab.

Nixi can already do every part of this, but not on the news slip:

- `stages.video_search()` asks `yt-dlp` for up to three YouTube results
  (8 s limit), and `video_stage()` in `app/server.py` runs it off the turn for
  the cinema set;
- the cinema set shows each result's poster through a server token (the page
  never fetches from YouTube itself);
- the `play` action opens the clip in `mpv` when it is installed and in the
  browser otherwise (`app/server.py`, `act == "play"`).

The news plugin can't search YouTube itself. It runs in the sandbox without
`yt-dlp`, and its network rule is for feeds.

## Proposed outcome

- Asking for news shows the stories first, as today. A "Watch" section of up to
  three YouTube clips about the same topic appears below them as soon as the
  search returns. Each clip has a preview picture, title, channel and length.
- Pressing a clip's Play starts it in mpv (in the browser if mpv isn't
  installed). Voice works as on the cinema set: "play the first video".
- If the search fails or finds nothing, the stories stay as they are and the
  Watch section doesn't appear. The news itself never waits for the clips.
- The topic follows what was asked: "world news" searches world news, "tech
  news" searches tech news, and a bare "news" searches a default topic.

## Affected users and systems

- Fork `olafkfreund/nixoarchy-snowflake`:
  - `app/server.py`: the news plugin's stage gets clips after it is shown;
  - `app/stages.py`: `headlines` may carry clips with play and poster tokens;
  - `app/static/index.html`: the press set's Watch section.
- The `news` plugin: possibly a setting to turn clips off, in its settings file.
- p620 (and razer, which has the companion): `mpv` and `yt-dlp` are installed
  on p620.

## Constraints

- **Must:** the stories appear as fast as today. Clips are added afterwards,
  only if the slip on screen is still the same one (the pattern `video_stage`
  already uses).
- **Must:** the page never contacts YouTube. Posters go through the existing
  thumbnail token, and Play is a server action that receives only a token.
- **Must:** the plugin stays as sandboxed as it is. The search runs on the
  server with the existing `video_search()`, not inside the plugin.
- **Must:** the agent's own `<<stage>>` block can't add clips, because
  `headlines` stays plugin-only.
- **Must not:** start playing anything without a press or a spoken "play".
- Reduced motion, contrast ≥ 4.5:1, Tab to every Play, and Esc and the 30 s
  collapse all behave as on the rest of the press slip.

## Open questions

1. **Where the topic comes from.** Recommended: the words the user said, with
   "news" kept and filler like "show me the latest" stripped. A bare "news"
   uses a default topic from the news settings file ("world news"). The other
   option, searching each headline's own title, means three searches per ask
   and slower answers.
2. **How many clips.** Recommended: three, the number `video_search` already
   returns. The slip grows by about 3 × 64 px.
3. **On by default?** The search sends the topic to YouTube through yt-dlp.
   Recommended: on, because you asked for it, with `"videos": false` in the
   news settings file to turn it off. The consent card should say that it
   searches YouTube.
4. **Only on the news slip?** Recommended: yes, for now. Other plugins can't ask
   for clips; that can wait until one needs it.
