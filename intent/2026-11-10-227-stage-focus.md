# Intent: one thing on stage — a Linux terminal for working agents, and no more stacked reactions

## Problem

Nixi shows everything he senses at the same time. With agents working, music or a YouTube video playing and a mail
arriving, the screen holds the agent terminal sheet, the mail envelope and its card, floating music notes, the pink
boombox, the equalizer on his screen face, and coding glasses over his eyes. Each piece is fine alone; together they
are unreadable, and at small sizes they become a smudge next to the editor.

The agent terminal itself does not read as a terminal. It is a rounded, tilted paper card with a speech-bubble tail
and rows of grey ▒ blocks, and after a minute it shrinks to a thin grey strip. It names one agent only, though
Claude, Codex and agy often run at once.

Codex (gpt-6-sol) and agy (model not reported) reviewed snowflake `origin/main` 587d18b, read-only; the causes below
were checked against the code:

- Sustained reactions (music, video, high load, low memory) are always painted together with the one-off reaction
  that is playing (done, ask, notice) — `app/static/index.html:1779` `rxPaint`. Their art stays mounted, frozen, while
  another one plays.
- Situational looks (glasses, shades, tie, hats, scarf, the notification chat/feed props) are drawn per frame on
  their own and check neither the reactions nor the terminal; only the headphones give way, to the boombox —
  `index.html:2421-2433`. Reaction props also wear things: party shades on `done`, a beanie on `snow`, a headband on
  `workout`, a headset on `meeting` — so two things can sit on his eyes or head at once.
- Mail is not a reaction: it is its own pop-out card (`#mailPop`, `index.html:164-180`), placed beside him in the same
  space as the terminal and the answer stages (`#stg`), none of which check each other.
- The terminal only hides the work chip (`index.html:755`); reactions do not step back for it (`rxBase`,
  `index.html:1774`).
- The terminal tracks one agent (`ag`, `index.html:4874-4883`): each `working` event overwrites the agent it names, so
  whichever agent sent the latest heartbeat closes the sheet when it finishes, while another still works.
- An agent that asks you something keeps its looping sheet; only `done` ends it (`index.html:2829`).
- The `working` event's project name reaches the page but is dropped (`index.html:2828`), so the sheet can't say where
  the agent works. Nixi's own tool run replaces another agent's sheet and doesn't bring it back (`index.html:4822`).
- 20 s after you last touched him he shrinks to peek (`index.html:4649-4658`); a working agent doesn't count as
  something showing, so the sheet shrinks away with him.

## Proposed outcome

- At any moment Nixi shows **one focus**, chosen by a fixed priority:
  1. something that needs your answer: an approval card, the password card, an agent asking you, ai-mirror asking
     for control, a notification card with buttons
  2. a short event: mail, an agent finished, a nudge, a calendar warning (a few seconds)
  3. agents working, including his own tool runs
  4. music or video
  5. ambient looks: glasses, tie, weather, night, high load, low memory
- Short events (2) briefly take the stage over a working terminal and then give it back; they are not queued, so a
  missed one still falls back to the desktop popup as today. Sustained states (3–5) wait and return when the
  stage is free.
- A focus may bring its own small cues (the agent icons, the ♪ chip, the attention mark); nothing from another focus
  is drawn at the same time.
- On his body: at most one thing on his eyes, one on his head, one at his neck, and one thing beside him (terminal,
  mail card, answer stage). Shades before glasses; never glasses with the boombox.
- While agents work: a Linux-style terminal (square, dark, solid title bar, monospace, prompt; no tail, no tilt)
  with an icon for **each** agent that is working — Claude, Codex, agy, and a plain mark for any other — and one true
  status line per agent and project. Two sessions of the same agent in different projects are two lines; one
  finishing leaves the other. It stays readable at every size Nixi can have (no shrink to a strip), and he does not
  shrink to peek while agents work. Nixi's own tool runs use the same terminal and give it back to the other agents
  afterwards.
- While agents work, Nixi types on a keyboard and his eyes become a small screen of scrolling code. No glasses,
  boombox or notes at the same time; music shows only as the small ♪ chip.
- Never more than one thing over his eyes (shades before glasses), and never glasses together with the boombox.
- An agent that asks you something ends its working sheet; the question takes the stage.

## Affected users and systems

- `nixoarchy-snowflake`: `app/static/index.html` (reactions, situational looks, terminal sheet, agent marks, face
  drawing of all four characters). Possibly `app/server.py` only if the `working` event needs a field it lacks
  (today it sends the agent and a project name, `server.py:1496`).
- Everyone using Nixi with reactions, situational looks or the code panel switched on. Hosts: wherever the companion
  runs; no NixOS module change expected.

## Constraints

- Must keep: approval cards and their click targets, the attention/ask cues and click-to-jump, bar / hover / calm /
  peek behaviour, `prefers-reduced-motion`, the user's existing switches (`code_panel`, `reactions`, `look_*`).
- Must not show invented text as an agent's real output: anything decorative must look decorative.
- No new per-frame DOM writes; animations in CSS where possible (the sheet already measures layout every frame).
- Agent icons are original marks (the existing `#amC` / `#amX` / `#amA` art), not vendor logos.
- Tests must not import the server under the real HOME (use `nixi_env`).
- Code on snowflake branch `feat/227-stage-focus`; artifacts here on `docs/227-stage-focus`.

## Decisions (owner, 2026-11-10: "approved, use the recommendations that make most sense and usability")

1. Scrolling-code eyes for **all four characters** (the owner asked for the eyes to become a terminal); every
   character also types on the keyboard.
2. The terminal shows one true status line per agent and project, and below it a dim scroll that is plainly
   decorative (no words that could be read as real output).
3. While agents work, music shows only as the ♪ chip.
4. Calm mode hides the agent terminal.
5. Notch (bar) mode stays as today: the terminal's text inside the notch, no keyboard, normal notch eyes.
