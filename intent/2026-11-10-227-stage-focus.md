# Intent: one thing on stage — a Linux terminal for working agents, and no more stacked reactions

## Problem

Nixi shows everything he senses at the same time. With agents working, music or a YouTube video playing and a mail
arriving, the screen holds the agent terminal sheet, the mail envelope and its card, floating music notes, the pink
boombox, the equalizer on his screen face, and coding glasses over his eyes. Each piece is fine alone; together they
are unreadable, and at small sizes they become a smudge next to the editor.

The agent terminal itself does not read as a terminal. It is a rounded, tilted paper card with a speech-bubble tail
and rows of grey ▒ blocks, and after a minute it shrinks to a thin grey strip. It names one agent only, though
Claude, Codex and agy often run at once.

Codex (gpt-6-sol) and agy (model not reported) reviewed snowflake `origin/main` 587d18b, read-only; the causes below
were checked against the code:

- Sustained reactions (music: boombox, notes, equalizer) are always painted together with the one-off reaction that
  is playing (mail, done, ask) — `app/static/index.html:1779` `rxPaint`.
- Situational looks (glasses, headphones, tie, hats) are drawn per frame on their own and check neither the
  reactions nor the terminal — `index.html:2421-2426`.
- The terminal only hides the work chip (`index.html:755`); reactions do not step back for it (`rxBase`,
  `index.html:1774`).
- The terminal tracks one agent (`ag`, `index.html:4874-4883`): a second agent takes over its title, and the first
  one finishing can close the sheet while the second still works.
- An agent that asks you something keeps its looping sheet; only `done` ends it (`index.html:2829`).

## Proposed outcome

- At any moment Nixi shows **one focus**, chosen by a fixed priority. Lower ones wait and return when it ends:
  1. an approval card or an agent asking you something
  2. agents working
  3. a notification (mail, done, a nudge)
  4. music or video
  5. ambient looks (glasses, tie, weather, night)
- While agents work: a Linux-style terminal (square, dark, solid title bar, monospace, prompt; no tail, no tilt)
  with an icon for **each** agent that is working — Claude, Codex, agy, and a plain mark for any other. Its first
  line is true (which agent, which project); it stays readable at every size Nixi can have.
- While agents work, Nixi types on a keyboard and his eyes become a small screen of scrolling code. No glasses,
  boombox or notes at the same time; music shows only as the small ♪ chip.
- Never more than one thing over his eyes (shades before glasses), and never glasses together with the boombox.
- An agent that asks you something ends its working sheet; the question takes the stage.

## Affected users and systems

- `nixoarchy-snowflake`: `app/static/index.html` (reactions, situational looks, terminal sheet, agent marks, face
  drawing of all four characters). Possibly `app/server.py` only if the `working` event needs a field it lacks
  (today it sends the agent and a project name, `server.py:1496`).
- Everyone using Nixi with reactions, situational looks or the code panel switched on. Hosts: wherever the companion
  runs; no NixOS module change expected.

## Constraints

- Must keep: approval cards and their click targets, the attention/ask cues and click-to-jump, bar / hover / calm /
  peek behaviour, `prefers-reduced-motion`, the user's existing switches (`code_panel`, `reactions`, `look_*`).
- Must not show invented text as an agent's real output: anything decorative must look decorative.
- No new per-frame DOM writes; animations in CSS where possible (the sheet already measures layout every frame).
- Agent icons are original marks (the existing `#amC` / `#amX` / `#amA` art), not vendor logos.
- Tests must not import the server under the real HOME (use `nixi_env`).
- Code on snowflake branch `feat/227-stage-focus`; artifacts here on `docs/227-stage-focus`.

## Open questions

1. Scrolling-code eyes: for all four characters (snowflake, terminal, robot, devil), or only the monitor-faced
   **terminal** character, with the others just typing?
2. The terminal's body under the true first line: a clearly decorative dim scroll (my recommendation), or only the
   real status lines (agent, project, how long) and nothing that scrolls?
3. During agents working, music: the ♪ chip only (recommended), or headphones allowed as the single extra?
4. Calm and peek modes: hide the agent terminal there too (agy's point; recommended), or keep it?
5. The shrink-to-strip after one minute: drop it (recommended), or keep a smaller but readable size?
