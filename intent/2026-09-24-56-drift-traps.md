# Intent: Three claims nothing checks

## Problem

Three places assert something no test, build or assertion verifies. Each is free
to drift, and one already has, with a real behavioural consequence.

**The systemd units are defined twice and have drifted.**
`systemd/nixi-watch.service` says `WantedBy=default.target` and `RestartSec=5`;
`nix/hm-module.nix:233-247` says `graphical-session.target`, with
`PartOf`/`After`, and `RestartSec=2`.

The file version is the broken one. Starting at `default.target` with no
`After=graphical-session.target` runs the watcher before the Omarchy shell
exists, so `bin/nixi-watch`'s calls to `omarchy-notification-wait`/`-send` have
no session to reach. `Restart=on-failure` then fires until `start-limit-hit` and
the unit is dead for the whole session. `install.py` is the only reader of these
files, so this is the plugin-manager path -- exactly the path CI does not
exercise for unit behaviour.

`CONTRIBUTING.md:52` already makes this parity an explicit rule *and* asks for a
CI job to check it. There is no such job.

**`flake.nix:35` describes an assertion that does not exist.** It says
`installCheckPhase` checks "assets non-empty". `grep -n assets flake.nix
nix/package.nix` returns that comment and nothing else. A comment describing a
guarantee the build does not make is worse than none: it is what a reader trusts
instead of checking.

**`button/manifest.json:5` carries a version nothing reads.** `manifest.json:5`
is the single source `nix/package.nix:26` derives from; the button's copy is
hardcoded separately and will silently go stale at the next release.

## Proposed outcome

- The watcher starts after the shell exists on both install paths, and the two
  definitions cannot drift again without something failing.
- Every comment in the flake describes an assertion that exists.
- The button's version cannot diverge from the package's unnoticed.

## Affected users and systems

- Anyone installing through `omarchy plugin add` rather than Home Manager --
  their tip watcher is dead for the session today.
- `systemd/nixi-watch.service`, `flake.nix`, `nix/package.nix`,
  `tools/test_nixi.py`.

## Constraints

- `ExecStart` and `PATH` must stay different between the two definitions: one
  points at `~/.local/bin`, the other at a store path. Parity means the
  ordering and restart policy, not the whole file.
- The parity check must live where CI already runs, not in a new job.
- Must not change the Home Manager path's behaviour, which is correct today.

## Open questions

None. All three are corrections with one obvious shape.
