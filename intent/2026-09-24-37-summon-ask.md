# Intent: Open Nixi with a question already asked

## Problem

Other parts of nixarchy can open Nixi, but they can't hand it a question.

- **Summon accepts only two actions.** `omarchy-shell shell summon io.github.olafkfreund.nixi '<json>'`
  handles `{"action":"tour"}` and `{"action":"learn"}` (`Ask.qml:422-425`).
  Anything else opens an empty card, and `Conversation.open()` ignores the
  payload (`Conversation.qml:184`).
- **A summon to an already-open card is dropped.** `Ask.open()` returns early
  when an unpinned card is open (`Ask.qml:430-433`), so the payload is lost.
  `toggle` would close the card instead.
- **`bin/nixi` has no way to pass a question.** `--tui` runs `claude "<prompt>"`
  in a terminal, which bypasses the card and only works with Claude.

**Why it matters now.** nixarchy-menu (olafkfreund/nixarchy-menu#4) is
deleting its own Codex-only chat and handing quick questions to Nixi, which
runs claude, codex and opencode over ACP with nixarchy's skills. Without this,
the menu can only open an empty Nixi card and ask the user to paste their
question.

## Proposed outcome

- **Summon with a prompt:**
  `omarchy-shell shell summon io.github.olafkfreund.nixi '{"action":"ask","prompt":"…"}'`
  opens Nixi with that question asked, using the user's agent and skills,
  exactly as if they had typed it and pressed Enter.
  - **No card open:** a new card opens and asks.
  - **Open, idle card:** the question is asked in it.
  - **Open card mid-answer:** the question is only put in the prompt box, so
    it neither interrupts nor steers the running turn. The user sends it when
    ready.
- **CLI:** `nixi --ask "<question>"` does the same from a shell. It summons
  rather than toggles, so an open card is never closed. When the card is off,
  it prints the same "turn it on" notice as `nixi` does today.
- **Empty or missing prompt:** `--ask` with no argument is a usage error. A
  payload with an empty `prompt` just opens Nixi.

## Affected users and systems

- **This repo:** `Ask.qml`, `Conversation.qml` (a small `setPrompt`),
  `bin/nixi`, `tools/test_nixi.py`, and `docs/testing.md` (the manual
  checklist). About 20 lines of code plus tests, by the research estimate.
- **Callers:** nixarchy-menu#4's "Ask Nixi" row, and any script that wants
  to hand Nixi a question.
- **No change** to the bridge, the harness policy, or which agents Nixi
  supports.

## Constraints

- **Asking is the same code path as typing.** It uses the existing
  `askQuestion()`, which already queues until the bridge is ready (as
  `teachNext` does after a summon), so tools still go through Nixi's normal
  permission prompts.
- **A running turn is never interrupted or steered by a hand-off.**
- **`bin/nixi` keeps its bash-only runtime.** `nix/package.nix` pins only bash
  for it, so the JSON escaping is done in bash: backslash, quote, newline and
  tab are escaped. Other control characters are an accepted limit for typed
  questions.
- **The existing `tour` and `learn` actions behave exactly as before.**

## Open questions

1. **Submit or prefill?** Proposed: **submit** when the card is new or idle;
   **prefill only** when a turn is running. The menu's user already chose
   "Ask Nixi" explicitly.
2. **Should `--ask` also work when the card is pinned?** Proposed: **yes**.
   A pinned card is open, so the same idle/busy rule applies.
