# Intent: News gets its own popout and animation

Code: the companion (`nixoarchy-snowflake`: `app/plugins.py`, `app/stages.py`,
`app/server.py`, `app/static/index.html`, a stage plugin). Artifacts: this
repo. Sibling: #166 (system board), which needs the same kind of change.

## Problem

- **Asking for the news gives you a note.** "headlines", "the headlines" and
  "what is the news" run the `rss-headlines` example plugin (#149 slice B). It
  returns up to five titles as `facts`, so they land on the cream notebook as
  a numbered list, with the feed's address under it. There's no sense of "the
  news", and no source or time on each story.
- **Plugins can only fill the notebook.** A stage plugin may return only
  `facts` (`app/plugins.py:702`). However good a news plugin's data, it can't
  look like news.
- **You can't get to a story.** The notebook lists titles, not links, so to
  read one you go and search for it.
- **He doesn't tell you the news.** A plugin's answer is always spoken as
  "Here you go." (`app/server.py:4648`).
- **One feed, and few ways to ask.** The example reads a single feed URL from
  its own `config.json`, and answers three exact phrases.
- **It arrives like any other card.** Same entrance as every notebook stage.

## Proposed outcome

1. **Asking for the news opens a news popout, not the notebook.** Each story
   shows its headline, its source and how long ago it was published (or "time
   unknown").
2. **It has its own animation** when it opens (a "news" moment, not the
   notebook's), and a still version under reduced motion.
3. **A story can be opened in the browser with a click,** as the day desk
   opens an issue today. Saying "open the first one" would be new (the day
   desk doesn't do it); whether it's in v1 is open question 4.
4. **He says it briefly.** The spoken answer names the top few headlines and
   their sources, and never claims to have read an article.
5. **It's supplied by a plugin,** as the user asked. The plugin supplies the
   stories as data; the page draws the popout.
6. **It's honest when it can't fetch.** A feed that fails says so; old stories
   say how old they are.

## Affected users and systems

- **Everyone with the companion and a news plugin on,** on every host.
- **The plugin format (#149):** what a stage plugin may return grows beyond
  `facts`. Existing `facts` plugins keep working.
- **The stage frame (#144):** a new look, and the rules that decide which
  addresses a stage may open.
- **The feeds' sites,** which see requests from this machine.

## Constraints

- **The plugin sandbox and consent model stay as they are** (#149). The news
  plugin reaches the network through the existing sandbox, and the consent
  card says it does. No plugin markup, script or styles in Nixi's window.
- **Feed content is untrusted.** Headlines and sources are shown as text, and
  are never treated as instructions, whether by the page or by the agent.
- **The page never loads anything from a news site.** No remote images,
  scripts or fonts in Nixi's window.
- **Only safe links open.** A story opens only if its address is a plain
  `https` web page: no other schemes, no addresses on this machine, the local
  network or the tailnet, no user names or passwords in it. A link coming from
  the user's own feed is no exception. The page never holds a raw link.
- **No article scraping in v1.** Titles, sources and times only; no reading
  pages behind paywalls, no summarising an article it hasn't fetched.
- **Fetch only when asked.** Feeds are fetched when you ask, and a result is
  reused for a few minutes (the example caches for 300 seconds), so asking
  twice doesn't fetch twice. Nothing polls in the background.
- **Within the sandbox's time limit.** A slow or failing feed must not stop
  the others from showing.
- **Accessible.** Story links work from the keyboard and have clear names;
  times are readable; contrast as in #155; reduced motion honoured.
- **It fits beside him** within the stage frame's size limits.

## Open questions

1. **What's in v1?** The core is the popout, source and time per story, and a
   click to open. Codex suggests approving that first; which of these also go
   in: several feeds merged, voice opening ("open the first one"), a spoken
   summary?
2. **Thumbnails?** Pictures make it look like news, but the page must not load
   them from the sites, so the server would have to fetch and check them.
   Both reviewers recommend text only in v1.
3. **Which feeds, and where are they set?** The example uses Hacker News.
   Should there be a default list (for example BBC, Reuters, Hacker News)?
   Today the feed is in the plugin's own `config.json`, inside the hashed
   folder, so editing a feed switches the plugin off ("Changed") until you
   allow it again. agy suggests keeping the feed list outside the hashed
   folder so changing feeds needs no new consent; Codex suggests keeping it in.
4. **Topics?** "News about NixOS" or "tech news" would need a topic per feed,
   or a search. In v1, or later?
5. **What does the animation say?** Codex suggests a folded "press slip" that
   slides out and opens once; agy a broadsheet that unfolds. How much motion
   is welcome next to a busy screen?
6. **Replace `rss-headlines` or keep it?** Keep it as the simple `facts`
   example and add a new news plugin, or turn it into the news plugin?
