# Intent: News gets its own popout and animation

Code: the companion (`nixoarchy-snowflake`: `app/plugins.py`, `app/stages.py`,
`app/static/index.html`, a stage plugin). Artifacts: this repo. Sibling: #166
(system board), which needs the same kind of change.

## Problem

- **Asking for the news gives you a note.** "headlines" runs the
  `rss-headlines` example plugin (#149 slice B). It returns up to five titles
  as `facts`, so they land on the cream notebook as a numbered list, the same
  card any other fact gets. There's no sense of "the news", and no source or
  time next to a story.
- **Plugins can only fill the notebook.** A stage plugin may return only
  `facts` (`app/plugins.py:702`). However good a news plugin's data, it can't
  look like news.
- **You can't get to a story.** The notebook lists titles, not links, so to
  read one you go and search for it.
- **One feed only.** The example reads a single feed URL from its own
  `config.json`. "What's the news?" deserves more than one source, and
  `what is the news` is the only natural phrasing it answers (beside
  `headlines`).
- **It arrives like any other card.** Same entrance as every notebook stage.

## Proposed outcome

1. **Asking for the news opens a news popout, not the notebook.** Each story
   shows its headline, its source and how long ago it was published. Stories
   from several feeds are merged, newest first, without duplicates.
2. **It has its own animation** when it opens (a "news" moment, not the
   notebook's), and a still version under reduced motion.
3. **A story can be opened** in the browser with a click, or by saying "open
   the first one", the same way the day desk opens an issue today, without the
   page ever holding a raw link.
4. **He says it briefly.** The spoken answer names the top few headlines and
   their sources, and never claims to have read an article.
5. **It's a plugin.** A news plugin supplies the stories as data; the page
   draws the popout. Plugins still ship no HTML, CSS or script. The feeds are
   the plugin's own configuration, covered by its consent and hash check.
6. **It's honest when it can't fetch.** A feed that fails says so; old stories
   say how old they are.

## Affected users and systems

- **Everyone with the companion and a news plugin on,** on every host.
- **The plugin format (#149):** a new data kind beside `facts`, validated and
  size-limited. `rss-headlines` either moves to it or is replaced by the new
  plugin.
- **The stage frame (#144):** a new set, and the link-opening rules that
  decide which addresses a stage may open.
- **The feeds' sites,** which see one request per refresh from this machine.

## Constraints

- **The plugin sandbox and consent model stay as they are** (#149). The news
  plugin uses the network through the existing sandbox, and the consent card
  says it does.
- **The page never loads anything from a news site.** No remote images,
  scripts or fonts in Nixi's window. A headline is text from an untrusted
  feed and is shown as text.
- **Links stay server-side.** The page gets a token, as the day desk does
  (#144 slice 4), and only addresses the user's feeds point at can be opened.
- **No article scraping in v1.** Titles, sources and times only; no reading
  pages behind paywalls, no summarising an article it hasn't fetched.
- **Light on the network.** Results are cached; asking twice in a minute
  doesn't fetch twice.
- **It fits beside him** within the stage frame's size limits and stays
  readable (#155).

## Open questions

1. **Thumbnails in v1?** Pictures make it look like news, but the page must not
   load them from the sites, so they'd have to be fetched and checked by the
   server (size, type, redirects). Codex recommends text only in v1.
2. **Which feeds by default, and where are they set?** The example uses Hacker
   News. Should there be a default list (for example BBC, Reuters, Hacker
   News)? Today the feed lives in the plugin's own `config.json`, inside the
   hashed folder, so editing a feed switches the plugin off ("Changed") until
   you allow it again. agy suggests keeping the feed list outside the hashed
   folder (Settings, or a separate file) so changing feeds doesn't need a new
   consent; Codex suggests keeping it in the hashed config.
3. **Topics?** "News about NixOS" or "tech news" would need a topic per feed,
   or a search. In v1, or later?
4. **What does the animation say?** Codex suggests a folded "press slip" that
   slides out and opens once. Another option is Nixi reading a paper. How
   much motion is welcome next to a busy screen?
5. **Replace `rss-headlines` or keep it?** Keep it as the simple `facts`
   example and add a new news plugin, or turn it into the news plugin?
