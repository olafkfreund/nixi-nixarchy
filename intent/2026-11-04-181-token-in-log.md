# Intent: keep the window token out of server.log

## Problem

The companion window loads its page as `…/?native=1#t=<window token>`
(`app/window.py:1252`, `_authed_url`). WebKit's console-to-stdout option is on
(`app/window.py:378`), and it prefixes every console message with the
script's source URL. For the page's inline script, that's the URL the page
was loaded with, token included; the page's later `history.replaceState`
doesn't change it. So each console message (for example "slow frames — glow
off") writes the full window token into `~/.local/share/nixi-companion/server.log`.

The window token can do everything the companion can: answer approvals, run
the agent, change settings. The design keeps it out of Claude's environment
and out of the page the server serves (`app/server.py:56`). The log is mode
600, but `nixi-companion log` and `nixi-companion diagnostics` print its
tail, and people paste that into bug reports and chats.

Found in the #168 live check on p620: 19 lines. They were redacted and the
companion was restarted, so that token is dead. The leak itself remains.

## Proposed outcome

- No window token ever appears in `server.log`, or anything else WebKit
  prints, during normal use, a page reload (`reauth`), or after a server
  restart.
- Console messages still reach `nixi-companion log`, because page errors are
  debugged from there.
- The window still gets the token, as it does today, with no change the user
  can see.
- A test fails if the URL the window loads ever contains the token.

## Affected users and systems

- Every Nixi companion user (nixoarchy-snowflake: `app/window.py`, the
  `tokenReady` intake in `app/static/index.html`, `Tickets` in `app/server.py`).
- p620 and razer run the companion: they get the fix on the next bump. p510
  has no companion.
- Logs written before the fix keep their lines. Each server run makes a new
  token, so those tokens stop working after a restart.

## Constraints

- Must not weaken the auth model: the window token stays out of any process's
  arguments, environment and served page, and stays in runtime.json (0600).
- Must keep the browser fallback (`#ticket=`) and the `reauth` flow working.
- Must not lose the console logging that `nixi-companion log` relies on.
- Smallest correct change (no new auth scheme).
- Deploy: p620 and razer only, after the user approves.

## Open questions

1. **What goes in the URL?** Recommended: the window asks the server for a
   one-time ticket (`/api/ticket`, 60 s, single use) and loads `#ticket=…`.
   The page already claims tickets. A logged ticket is spent within a second.
   The other option is to keep `#t=` and turn console-to-stdout off, but that
   loses page-error logging.
2. **Should existing logs be scrubbed** of old `#t=` lines on start?
   Recommended: no. A token dies with its server run, so a scrubber would be
   code for a value that's already dead.
