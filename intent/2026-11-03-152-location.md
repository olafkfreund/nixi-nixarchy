# Intent: Location — Home, Work and where I am now, set by me

Code: the companion (`nixoarchy-snowflake`) for the settings, the map and the
agent line; `nixarchy` for the shared location file and a menu entry.
Artifacts: this repo.

## Problem

- **Your location is guessed from your IP address, and the guess is often
  wrong.** A VPN, a phone hotspot or an ISP that routes through another city
  all move you. On p620 today the guess returns nothing at all.
- **The only way to correct it is a terminal command**
  (`omarchy weather location --set`), and only the weather reads it. Nixi has
  no idea where you are:
  - the map stage sends Google no start point, so Google guesses again;
  - the agent can't answer "nearest station" or "weather here" without
    asking or guessing.
- **There are no named places.** "Directions home" or "how long to work"
  can't work, because Nixi doesn't know Home or Work.
- **The obvious shortcuts don't exist** (checked):
  - Google Maps' saved Home and Work can't be read; there is no API.
  - The phone's location can't be had from Google. Timeline has lived on
    the phone since 2024, and location sharing has no API.

## Proposed outcome

1. **Home and Work, set once.** Nixi's settings have a **Location** section:
   - **Home** and **Work**: a place name, with optional coordinates;
   - **Now**: Home, Work or Auto, with a line showing what that resolves to
     ("Auto: Oxford (approximate)").
2. **One location for the whole desktop.** The places live in the shared
   nixarchy location file. The bar's weather, Nixi and the coming sky stage
   all read the same one, so they never disagree. Users without Nixi can set
   it from the nixarchy menu.
3. **"Where am I now" without GPS or Google:**
   - **a desktop** (p620) is pinned to Home with one setting;
   - **a laptop** (razer) recognises Home and Work by the Wi-Fi network it
     joins, once you've linked each network to a place;
   - **anywhere else** it falls back to the IP guess, labelled approximate.
4. **Nixi uses it:**
   - the map stage understands "directions home" and "to work", and starts
     from your current place when it's one you set;
   - the agent gets one line saying which city you're in;
   - the weather and the sky stage read it automatically.
5. **Correcting it is quick:** a wrong place is fixed in the settings, or with
   a quick Home / Work / Auto switch, without a terminal.

## Affected users and systems

- **Everyone using the weather** (bar) and **Nixi users** (map, agent, sky).
- **Hosts:** p620 (desktop, pinned to Home) and razer (laptop, Wi-Fi
  recognition). Both deploy the usual way.
- **Repos:**
  - `nixoarchy-snowflake`: the settings section, map start point, agent line;
  - `nixarchy`: the location file grows Home, Work and Wi-Fi links, plus a
    menu entry.
- **Depends on it:** #144 slice 3 (sky) and slice 4 (the day desk).

## Constraints

- **Privacy:**
  - only places you set (Home, Work or a typed place) are ever sent to the
    agent or to Google, never an IP guess;
  - a place is a name, with coordinates only when you enter them yourself;
    nothing more precise than you chose leaves the machine;
  - Wi-Fi recognition matches network names locally. No network list is sent
    anywhere.
- **It must keep working when nothing is set.** With no places, everything
  behaves exactly as today (IP for the weather, no start point for the map).
- **It must not stall anything.** Reading the location is a file read. No
  network call is added to a Nixi answer.
- **The existing command keeps working.** `omarchy weather location --set`
  and `--clear` behave as today, and an existing stored place is kept as
  Home.
- **Out of scope:**
  - GPS or geoclue;
  - Google's paid Geolocation API;
  - following the laptop on the move beyond Wi-Fi recognition;
  - more named places than Home and Work.

## Open questions

1. **Phone location through Home Assistant**, later? It would need Home
   Assistant enabled on a host and the companion app on the phone. My
   suggestion: leave it out, and design the location so it can be added as
   one more source.
2. **Does a Google Maps link with `destination=Home` open your saved Google
   home** when you're signed in? If it does, "directions home" could even work
   before you set Home. I'll test it in your browser before the spec.
3. **The p620 pin:** should a host be pinned to a place in its nixos_config
   (declarative), in the settings (one click), or both? My suggestion: the
   settings, since a place is personal and not a system setting.
