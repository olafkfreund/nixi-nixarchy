# Spec: News clips with previews in the news slip, played in mpv

Code: `olafkfreund/nixoarchy-snowflake` `main` `655bbe9` (#167 merged). Line
numbers are from that commit.

## Design

### 1. The plugin names the search; the manifest declares the capability

- **New stage key `videos`** (bool) in `app/plugins.py` `STAGE_KEYS` (line 29),
  checked in `_check` like `network`. `_check` also refuses `videos: true` for
  any plugin whose id isn't `news`, because the approved scope is the news slip
  only. The manifest is hashed, so turning this on is a change the user
  re-allows. The `news` manifest declares it.
- **The capability is shown in both places the user looks:**
  - `plugin_caps()` (`app/server.py` ~1804) adds "Can search YouTube for news
    clips (off in its settings)" for a stage with `videos: true`. It shows
    under the plugin in Settings → Plugins for Nix and Folder plugins alike.
  - The consent card is built from the separate `needs_consent` dict in
    `plugins_act()` (~1881), not from `plugin_caps`. So `needs_consent` gains
    `"videos": bool(stg.get("videos"))`, and `plugConsent()` in `index.html`
    adds the same line when it is set.
- **`headlines` gains an optional `video_query`** (`stages.validate`): taken
  with `_str(…, 60)` (stripped), it must then be 3–60 characters matching
  `[A-Za-z0-9 '-]+`, else the whole stage is refused. `Store.put()` drops it from the page copy (the page never needs it).
  The server uses it only when the plugin declares `videos: true`; otherwise
  it is ignored.
- **The `news` plugin** reads three new settings, with defaults in
  `defaults.json`:
  - `"videos": true`
  - `"topics"`: `{"world": "world news", "uk": "UK news", "tech": "technology
    news", "technology": "technology news", "business": "business news",
    "science": "science news", "sport": "sport news", "sports": "sport news"}`
  - `"default_topic": "world"`

  `run` keeps the whole stdin object, so it can read both `query` and
  `config`. It lowercases the query, replaces everything but `[a-z0-9 ]` with
  spaces (as `plugins.norm` does, so "tech?" matches), splits it into words,
  and takes the first word that is a key of `topics`, else `default_topic`. The value it maps to, checked
  against the same character rule, becomes `video_query`. With `videos: false`,
  or a bad `topics`, there is no `video_query`. Only the `headlines` branch
  carries it, never the one-line `facts` card. The user's words are never
  copied into the search; only a value from the settings file is.
- **Settings merge with the defaults** (`plugins.read_config`, #167): the
  user's file is laid over `defaults.json` key by key (`{**defaults,
  **user}`). An existing `news.json` with only `feeds`, made by Edit before
  this change, still gets `videos`, `topics` and `default_topic` from the
  defaults. A bad file still means the defaults alone, with the note.
- **The plugin cache follows the settings** (`plugins.run_stage`, the cache key
  at ~768): for a `config: true` plugin the key also holds a hash of the
  settings it was given. Setting `"videos": false` takes effect on the next
  ask instead of after up to five minutes of cached results.

### 2. The server searches once, then updates the slip in place

- **`stages.video_search(query, run=…, newest=False)`**: with `newest=True` the
  search argument is `"ytsearchdate3:" + query` (yt-dlp's newest-first search)
  instead of `"ytsearch3:"`. The cinema set keeps the default.
- **`plugin_stage()`** (`app/server.py` 4665): after `STAGES.put(st, …)` shows a
  `headlines` stage, if `st.get("video_query")` is set and the plugin's
  manifest has `videos: true`, it starts a daemon thread,
  `news_clips(page["copy"], st["video_query"])`. It passes the stage's
  `video_query`, never `plugin_stage`'s own `query` parameter, which is the
  user's words. The `copy` token is unique to that slip, so it identifies it.
- **`news_clips(slip, search)`**:
  - waits for a module lock, so only one search runs at a time and a newer
    slip's search waits instead of being dropped;
  - once it has the lock, returns at once if `slip` is no longer the current
    slip (an older ask's search doesn't run for nothing);
  - runs `video_search(search, newest=True)`;
  - with results, calls `STAGES.add_clips(slip, items)`;
  - if that returns a page, publishes `BUS.pub(t="stage_update", …)` as the
    gauges refresh does (`server.py` 4757). The page checks the slip's
    identity before applying it (section 4), because a `put`, `back` or
    `close` can be published between `add_clips` and this event.
- **`Store.add_clips(slip, items)`** (`app/stages.py`, beside `replace()` at
  478): under the lock it accepts only when
  - the current stage is live,
  - its kind is `headlines`,
  - its `copy` token equals `slip`,
  - and it has no clips yet.

  It then builds `page = {**cur_page, "clips": [...]}`. It also rewrites the
  `copy` token's text to add "Watch:" and the clip lines, so Copy matches
  `stageText()`. One row per item:
  `{title, channel, duration, play, thumb}`. It adds `("video", {"url"})` and
  `("thumb", {"id"})` tokens exactly as the `video` branch of `put()` does
  (lines 421–429), into a copy of the current token map. Finally it sets
  `self.cur = (page, toks, born)`.

  `prev` and `vis` are untouched, the story tokens are kept, and the age is
  kept. Otherwise it returns `None`: a late result for a slip that has gone, or
  that ← has replaced, is dropped and nothing old comes back. `back()` swaps
  whole entries, so a slip restored by ← keeps whatever clips it had.
- **Previews:** the page asks for them through the existing thumbnail route
  (`server.py` 5267, `stages.fetch_thumb`, `i.ytimg.com` only, ≤ 200 KB). The
  page never sees a YouTube URL. Play goes through the existing `play` action:
  `mpv` if installed, else the browser (`server.py` 4832).

### 3. Voice: clips and stories apart

- **`_ACT`** (`stages.py` 602) accepts an optional noun after the ordinal or
  "it/that": `(?:\s+(one|video|clip))?`, a new group. The ordinal group keeps
  its number, so "play the first video" and "play the second clip" parse.
- **`fast_path()`**:
  - **video or clip named, on any set but `headlines` or `video`:** `None`.
    The phrase goes to the agent, so "open the first video" on a calendar or
    map never opens the calendar or map.
  - **video or clip named with any verb but `play`:** `None` everywhere.
    "open/copy/run the first video" goes to the agent and never starts a
    player; only a spoken "play" plays.
  - **On `headlines`, `play`** (with "one", video, clip or no noun) targets the
    clips: `n = len(stage.get("clips") or [])`.
    - With `n == 0` it returns `None`, so "play it" doesn't answer "which
      one?".
    - Otherwise ordinals are bounded by `n`, and "it/that" is `("play", 0)`
      when `n == 1`, else `("ask", None)`.
  - **On `headlines`, `open`** without video or clip keeps targeting the
    stories, as today.
  - **On `headlines`, copy** keeps returning `("copy", 0)`.
  - **The cinema set** keeps its behaviour; "play the first video" now parses
    there too.
- **The handler** (`server.py` 5809): for `play` on a `headlines` stage it takes
  the item from `vis["clips"]`, not `vis["items"]`. Every other set is
  unchanged.

### 4. The page: a Watch section on the press slip

- **`stagePress()`** (`index.html`) renders `ev.clips`, when present, below the
  stories:
  - a small-caps "Watch" label over a hairline;
  - one row per clip: a 96×54 poster `<img>` from the thumbnail route (alt
    empty, decorative), the title (serif, two lines max), and "channel ·
    length" in small caps (no " · " when a live stream has no length);
  - a poster that fails to load is hidden, not shown as a broken image;
  - a Play `<button>` named "Play: <title>" posting `{token, act: "play"}`.
- **On `stage_update` for `headlines`** (`index.html` 2116, which today calls
  `gaugeUpdate`): a new branch first checks that the slip on screen is this
  one: `stg.kind === 'headlines'`, `ev.copy === stg.copy` and `stgState !==
  'closed'`. Otherwise it ignores the event. It then replaces only the Watch
  section. The story rows
  aren't rebuilt, so focus and hover survive. It sets `stgUse = now`, because
  clips arriving count as new content for the 30 s collapse. The rows fade in
  40 ms apart; under `REDUCED` there is no animation.
- **`stageText()`**: the headlines branch adds "Watch:" and one line per clip,
  "title — channel, length".
- **Look:** the same paper, ink and contrast as the stories (≥ 4.5:1), and a
  Play button styled like Open. The slip grows by about 3 × 64 px within the
  existing fit rules.

## Alternatives rejected

- **Search each headline's title** (three to five searches per ask): slower,
  more YouTube traffic, and the clips would often not match.
- **Let the plugin run yt-dlp in its sandbox:** it would need `yt-dlp` bound
  in and YouTube reachable from the sandbox, a larger sandbox for one feature.
  The server already has a vetted search.
- **Show clips with a second `STAGES.put()`**, as `video_stage` does: it
  replaces the slip, regenerating the story tokens (Open fails as `gone`),
  overwrites ← and resets visibility (both reviews of the intent).
- **Derive the search from the user's words:** when the agent starts the
  plugin, `query` is the whole prompt. Only values from the settings file are
  searched.
- **Embed playback in the page** (an iframe or `<video>`): the page would
  contact YouTube. mpv is a real player, and the user asked for it.
- **A separate cinema card for the clips:** two popouts for one question, and ←
  would step between them.

## Risks

- **Search time.** `yt-dlp` takes 2–8 s (8 s limit). The stories are already on
  screen and the clips arrive later, or never. On p620 and razer.
- **Clip quality.** Newest-first can surface low-effort uploads. The topic
  searches end in "news", and three rows are cheap to ignore. If it's poor in
  practice, a later change can prefer known channels.
- **Previews leave the machine.** Up to three `i.ytimg.com` downloads per news
  slip, done by the server and only when clips are shown. Off with
  `"videos": false`.
- **The news manifest changes** (`videos: true`), so the user's News plugin
  shows "Changed — check it again" once after the update. This is expected,
  and the card now lists the YouTube line.
- **Cached plugin results.** With `cache_seconds: 300`, asking again within 5
  minutes reuses the stories but searches for clips again. Accepted: the
  search is serialised and cheap. Changed settings bypass the cache (section 1).
- **Defaults merging changes #167 behaviour slightly:** a settings file
  missing a key used to mean "no such key". It now means the default. That's
  what an older `news.json` needs, and no key had a meaningful "absent" before.
- **Two players.** Pressing Play twice starts two mpv windows, as on the cinema
  set today. Unchanged.

## Verification

- **Unit** (`tests/`, run from `tests/`):
  - `test_stages`: `video_query` accepted and refused (2 chars, 61 chars, `;`)
    and absent from the page;
  - `add_clips`:
    - accepts only for the matching live `headlines` slip;
    - keeps story tokens, `prev`, `vis` and age;
    - refuses a second call, another slip, an expired one, and the slip after
      ← swapped it out;
  - `video_search(newest=True)` sends `ytsearchdate3:` (a fake `run`);
  - `fast_path`:
    - "play the first video" / "play the second clip" / "play the first one"
      → clips;
    - "open the first one" → stories;
    - "play the first video" or "play it" without clips → `None`;
    - "open the first video", "copy the first clip", "run the first video" on
      `headlines` → `None`;
    - regressions on the other sets: "open the first video" on `calendar`,
      `place`, `status` → `None`; their existing run/copy/open/play phrases
      unchanged; the cinema set plays "play the first video".
  - `add_clips` rewrites the copy text with the Watch lines;
- **Handler** (`test_stage_actions`, through `ask()`): "play the second video"
  on a slip with clips runs `mpv <url of clip 2>` (Popen mocked).
- **Plugins** (`test_plugins`, `test_plugin_stage`):
  - `_check` refuses `videos: 1`, and `videos: true` on a plugin not named
    `news`;
  - `read_config` merges: a file with only `feeds` gets the default `videos`
    and `topics`;
  - the cache: `"videos": false` written after a cached run with clips →
    the next ask has no `video_query` and starts no search;
  - `plugin_caps` shows the YouTube line, and the `needs_consent` dict carries
    `videos`;
  - a plugin without `videos: true` returning `video_query` starts no search;
  - with it, `news_clips` gets the stage's `video_query`, never the raw query;
  - two asks: the second waits for the first search, the first search's
    clips are dropped (its slip is gone), and the second slip gets its own.
- **News plugin** (`test_news_plugin`):
  - topic choice: "latest world news" → "world news", "What's the tech
    news?" → "technology news", "news" → default, "the news about my bank" →
    default;
  - no stories (the `facts` card) → no `video_query`;
  - `videos: false` → no `video_query`;
  - the query never contains a word not in the settings.
- **Page** (`test_stages_fit`, headless Chromium `--disable-gpu`):
  - a slip without clips, then a `stage_update` with clips: the Watch rows
    appear, the focused story Open keeps focus, `stgUse` is reset;
  - a `stage_update` whose `copy` differs from the slip on screen, or that
    arrives after close, changes nothing;
  - a clip with an empty length shows no trailing " · ", and a poster that
    fails to load is hidden;
  - the consent card shows the YouTube line;
  - Tab reaches each Play;
  - the posters come from the page's own origin;
  - no request leaves for youtube.com or ytimg.com;
  - reduced motion has no animation.
- **Full suite and build:** `python3 -m unittest discover -s .` and
  `nix build .#nixi-companion`.
- **Live on p620:**
  1. re-allow News (the card shows the YouTube line);
  2. "show me the latest world news": stories at once, Watch with three
     recent clips a few seconds later;
  3. Play starts mpv; "play the second video" plays clip 2;
  4. "open the first one" still opens a story;
  5. with `"videos": false` in `news.json`, no Watch section and no
