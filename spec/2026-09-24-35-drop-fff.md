# Spec: Drop the `@ff-labs/fff-node` native index from `@` file search

## Design

### 1. `bridge/files.js` loses the indexed path

Delete the `@ff-labs/fff-node` import and everything that exists only to serve
it: `created`, `finder`, `ready`, `initialize()` and its call, `usefulFuzzyMatch()`,
`strictFileMatch()` (its only callers are the two FFF branches), the whole
indexed half of `search()`, and `finder?.destroy()` in `shutdown()`.

`search()` becomes: short query -> empty result; otherwise
`emitProgressively(message, query, await fallbackFiles(query, signal))`.
`message.focused` stops being read -- the caller may keep sending it.

Nothing else moves. `discoverRepos()`, `repoResult()`, `fuzzyScore()`,
`emitProgressively()`, cancellation and the readline loop are untouched.

### 2. `fallbackFiles()` asks plocate for the user-facing roots first

The intent measured a real ordering regression: plocate answers in database
(path-alphabetical) order, so `--limit 300` is exhausted inside `.agents/` and
`.claude/` before it ever reaches `Documents/`. Re-sorting the 300 results
cannot fix this -- verified directly, the priority-root paths are not in the
first 300 at all.

plocate takes several PATTERNs and requires a path to match all of them, so one
extra pattern restricts a query to a root. Issue the priority-root queries and
the unrestricted query together, concatenate in that order, and de-duplicate:

```js
const locate = (patterns) => execFileAsync("plocate",
  ["--ignore-case", "--limit", "300", ...patterns],
  { timeout: 1200, maxBuffer: 2 * 1024 * 1024, signal })
  .then((value) => value.stdout).catch(() => "");
const priorityOutputs = await Promise.all(
  priorityFileRoots.map((root) => locate([`${root}/`, query])));
const located = await locate([query]);
const locatedPaths = [...new Set(
  [...priorityOutputs, located].flatMap((out) => locatedUnderBase(out, false)))];
```

This is the preference `fd` scanning and `discoverRepos()` already apply, using
the roots list (`priorityFileRoots`) that already exists in the file. The
`complete` flag keeps reading the unrestricted output, as before.

### 3. `bridge/files.js` becomes importable so it can be tested

The file has no tests because everything in it is either a top-level side
effect or a closure. Two changes make the parts worth testing reachable:

- Guard the side effects: `discoverRepos()` and the `readline` loop run only
  when the file is the entry point
  (`process.argv[1] === fileURLToPath(import.meta.url)`). Behaviour under
  `node files.js` is unchanged; `import` no longer scans the home directory.
- Extract the `fd` pattern builder out of `fallbackFiles()` into a named
  `filePattern(query)`, and `export { locatedUnderBase, filePattern }`.

`basePath` is derived from `process.env.HOME` at module load, so a test sets
`HOME` to a temporary tree and then `await import()`s the module.

### 4. `nix/package.nix` loses the native-build machinery

- Drop the `autoPatchelfHook` and `stdenv` function arguments.
- Drop `nativeBuildInputs = [ autoPatchelfHook ]` and
  `buildInputs = [ stdenv.cc.cc.lib ]` from `bridgeModules`, with the comment
  that explained them.
- Drop the `binaryExists()` installCheck (`nix/package.nix:255-258`).
- Regenerate `npmDepsHash` for the new lockfile.

Every other installCheck assertion is re-read: the only file-existence list is
`manifest.json Ask.qml ... bridge/bridge.js bridge/grounding.js
bridge/trust-policy.js bridge/nixi-node`, none of which this change deletes.
`bridge/files.js` is still installed by the `for js in bridge/*.js` loop and its
`fd` call is still pinned by the `--replace-fail` on `execFileAsync("fd"`, which
this change must not disturb -- the bare-`fd` grep check would catch it.

### 5. `bridge/package.json` / `package-lock.json`

`npm uninstall @ff-labs/fff-node`, which also removes the nine
`@ff-labs/fff-bin-*` platform packages and `@yuuang/ffi-rs`.

### 6. New `bridge/files.test.js`

- `locatedUnderBase()` -- the security boundary. A temporary `HOME` with a file
  inside it, a file outside it, a `node_modules/` path, a `.cache/` path, a
  path that no longer exists, a directory when a file was asked for, and the
  `$HOME`-prefix confusion case (`/tmp/home-evil/x` must not pass for
  `HOME=/tmp/home`).
- `filePattern()` -- shell/regex metacharacters stripped, terms joined with
  `.*`, empty result for a query that is entirely punctuation.
- End to end: spawn `files.js` with a temporary `HOME` and a `PATH` whose
  `plocate` and `fd` are stubs, send one JSON line, and assert the emitted rows
  have `name`, `relativePath` and an absolute `path`, that the priority root is
  queried before the unrestricted query, and that a stale plocate answer
  naming a path outside `HOME` never reaches the rows.

## Alternatives rejected

- **Keep FFF, delete only the dead branches.** Nothing in it is dead; the whole
  point of the change is to remove the native dependency and the Nix machinery
  it drags in.
- **Vendor a small fuzzy matcher to preserve typo tolerance.** A new dependency
  or new hand-written scoring code to replace a dependency is not a removal.
  The user accepted losing typo tolerance; adding it back in another form
  contradicts the decision.
- **Sort plocate's 300 results by a priority score.** Measured and rejected:
  the priority-root paths are not inside the first 300, so sorting changes
  nothing. The limit has to be applied per root.
- **Raise `--limit` to several thousand and sort.** Works, but multiplies the
  `statSync` calls in `locatedUnderBase()` over a 3.1M-file home for the same
  result the multi-pattern query gets in one extra plocate call.
- **Test `files.js` only through a subprocess, like `math.test.js`.** That is
  the existing convention, and one such test is included, but it cannot cover
  `locatedUnderBase()`'s rejection cases without fabricating a stale plocate
  database. The boundary deserves a direct test.

## Risks

- **Typo-tolerant `@` search is gone.** Accepted and quantified in the intent:
  `confguration` and `pakcage` return 48 and 70 rows from the index and 0 from
  the fallback. Substring and multi-term `fd` matching are unaffected.
- **`npmDepsHash` must be regenerated.** A stale hash fails `nix flake check`
  loudly, so this cannot ship silently broken.
- **The `isMain` guard could disable the bridge.** `MenuSearch.qml` and
  `Conversation.qml` launch it as `node .../files.js`, so `process.argv[1]` is
  the resolved script path and the guard holds. Covered by the end-to-end test,
  which spawns it exactly that way and would emit nothing if the guard were
  wrong.
- **The extra plocate calls cost time.** One process per priority root that
  exists (at most five), run concurrently, each with the existing 1200 ms
  timeout. Measured fallback latency today is 135-568 ms.
- Nothing here touches the compositor, the agent, trust policy or private state.

## Verification

- `node --test bridge/*.test.js` -- 86 tests today, more after, all passing.
- Each new assertion is proven to fail when the thing it checks is broken, by
  temporarily inverting the code under test and recording the message.
- `nix flake check`.
- `nix build .#nixi`, then re-read the built plugin: `bridge/files.js` present,
  no `@ff-labs` under `bridge/node_modules`, `fd` still pinned.
- Re-run the intent's measurement harness against the final `files.js` and
  confirm the ordering regression is gone.
