# Spec: Open Nixi with a question already asked

## Design

### 1. One entry point: `Ask.qml` `askFromSummon(conversation, payload)`

A small function decides how a handed-over question lands:

```qml
// A hand-off asks like typing, but never runs a slash command (/guide,
// /mechanic change trust; /tour, /learn start flows) and never interrupts
// a running turn: in those cases it only fills the prompt.
function askFromSummon(conversation, payload) {
  var text = payload && typeof payload.prompt === "string" ? payload.prompt.trim() : ""
  if (text === "") return
  if (conversation.waiting || text.charAt(0) === "/") conversation.setPrompt(text)
  else conversation.askQuestion(text)
}
```

- **Why a slash is never submitted.** `Conversation.submit()` treats
  `/guide` and `/mechanic` as trust changes. Its comment says that must be
  "a typed, deliberate command — never a stray click". It also treats
  `/tour` and `/learn` as flows. A hand-off must not be able to trigger any
  of them, so slash text is only prefilled and the user has to press Enter
  themselves.
- **Why a busy card only prefills.** With `waiting` set, `submit()` either
  sends a *steer*, which interrupts the running turn, or returns without
  sending. Neither is right for a hand-off.

### 2. Where it is called

- **New card:** in `createConversation` (`Ask.qml` ~422-425), next to `tour`
  and `learn`, add `else if (payload && payload.action === "ask")
  root.askFromSummon(conversation, payload)`.
  - `askQuestion` → `submit()` already queues until the bridge is ready
    (`queuedPrompt` / `sendQueuedPrompt`, `Conversation.qml` ~1130-1148),
    exactly as `teachNext` does after a summon.
- **Open, unpinned card:** in `open()` (`Ask.qml` ~430-433), parse the
  payload before the early return. For `action === "ask"`, call
  `askFromSummon(activeOverlay, payload)`, then return. Other payloads keep
  today's behaviour, which is to ignore them when a card is open.
- **Pinned cards:** a pinned card is never `activeOverlay`. The
  `pinnedChanged` handler clears it, so a summon opens a **new** overlay
  card that asks, and the pinned card is untouched.
  - This refines intent question 2, which said "same rule". The pinned
    card is simply not the target, which is today's behaviour for every
    summon.

### 3. `Conversation.qml` `setPrompt(text)`

`prompt` is an internal id, so this is a three-line function: set the text,
focus, and put the cursor at the end.

### 4. `bin/nixi --ask <prompt>`

- **The new case** sits next to `--tour`:
  1. Require a non-empty second argument, else print usage and exit 64.
  2. Run `card_ready || exit 1`.
  3. Escape for JSON in bash: `\`, then `"`, then newline `\n`, then tab
     `\t`, in that order.
  4. Run `exec omarchy-shell shell summon "$PLUGIN" '{"action":"ask","prompt":"…"}'`,
     using **summon**, never toggle.
- **Other text:** update the header `# omarchy:args=` and the usage line.
- **Limits:** jq is not assumed, because `nix/package.nix` pins only bash
  for the script. Other control characters are an accepted limit.

## Alternatives rejected

- **Submit slash text too:** a hand-off could switch Nixi to Mechanic.
- **Steer a running turn:** it interrupts the user's current answer.
- **Open a second overlay card when one is busy:** that is bigger, and it
  conflicts with the single-active-overlay and pin logic.
- **Use jq in `bin/nixi`:** it adds a runtime dependency for four escapes.
- **Add `--ask` to `nixi --tui`:** that path is Claude-only and bypasses the
  card.

## Risks

- **Control characters other than newline and tab** in a typed question
  produce invalid JSON, so the summon's payload parse fails and Nixi opens
  empty. This is the same as today, with no crash.
- **Summon when the shell is not answering:** `card_ready` already reports
  it.

## Verification

1. **`tools/test_nixi.py` `test_nixi_launcher`**, extended:
   - `--ask 'say "hi"<newline>now'` with the card enabled: exit 0, one
     `shell summon <card>` call, and the logged JSON round-trips through
     `json.loads` to the same prompt.
   - `--ask x` with the card off: exit 1 and no summon.
   - `--ask` with no argument: exit 64.
2. **The existing CI** runs `shellcheck bin/nixi` and the Python tests. Both
   pass.
3. **Manual checks** (added to the `docs/testing.md` checklist), on razer:
   - With no card open, `nixi --ask "how do I add a font?"` opens a card
     and answers.
   - With the card open and idle, it asks there.
   - With the card busy, the question appears in the box only, and the
     running answer continues.
   - `nixi --ask "/mechanic"` only prefills, and the trust level is
     unchanged.
   - `tour` and `learn` still work.
