# Spec: choose a different body for Nixi

All code is in olafkfreund/nixoarchy-snowflake. Line numbers come from
`mockups/178/code-map.md` (approximate: re-find them by name). The artwork
is agy's, from `mockups/178/agy-characters.html`, which the user chose.

## Design

### 1. A character is a body template plus a few numbers

`index.html` gets one registry, `CHARACTERS`, with four entries
(`snowflake`, `terminal`, `robot`, `devil`). Each entry holds only:

| Field | What it is |
|---|---|
| `label` | "Snowflake", "Terminal", "Robot", "Devil" |
| `back`, `front` | static SVG markup strings: the body behind the eyes, and anything in front of them (screen glare, brows). Fixed, built-in strings only, never from settings or plugins. |
| `ball` | the silhouette path `d`. It is drawn as `path.ball` (fill) and as `#rim` (stroke), so every reader of `#body > .ball` keeps working. |
| `reach` | the half-width that `cardPlace` and the bubble's `geo()` use today, from the width of `.nix` |
| `anchors` | `{head, face, neck, base}` as `[x, y]`. Snowflake: head `[0,-58]`, face `[0,-4]`, neck `[0,50]`, base `[0,76]`. |
| `pivot` | the squash pivot y (today a literal 76) |
| `fits` | which accessories and props it can wear: a set of skin and sit ids. Anything else is hidden on this character, never drawn oddly. |
| `touch` | the class of its one animated part: `.tCursor`, `.tAntenna` or `.tTail`, or none |

**The Snowflake entry is today's markup, moved, not redrawn:**
- `snowPath()` and `nixLambdas()` still build it;
- `.nix` stays inside its `back`;
- the gloss ellipses stay in its `front`.

It must render pixel-identically to `main`. The verification section says
how that's checked.

### 2. Swapping bodies

`setCharacter(id)` replaces the children of two new groups inside `#body`:
- `#bodyBack`, which takes the place of `path.ball` and `g.ball.nix`;
- `#bodyFront`, which takes the place of the gloss and `#rim`.

`#face` is never touched. It then sets `BODY = CHARACTERS[id]`, which the
code below reads.

### 3. Literals become `BODY` reads, only where the map found them

- **The squash pivot:** `76*(1-sy*pump)` becomes `BODY.pivot*(…)`.
- **Skins** (halo, crown, sprout, bow): anchored at `BODY.anchors.head`
  instead of `y=-58`. The halo stays relative to head. The sprout's wobble
  pivot is `BODY.anchors.head`.
- **Situational props** (`drawSit`, the frame anchors at 1775–1790):
  - hats → head;
  - glasses, shades and headphones → face (the face doesn't move between
    characters, see 4);
  - scarf and tie → neck;
  - base props → base.

  Each group gets one `translate(anchor − snowflakeAnchor)`, so the existing
  literals inside each prop stay unchanged, and Snowflake's offset is zero.
- **Plugin `PROP_BOX`** (1130): each box is shifted by its anchor's offset in
  the same way.
- **Frost** (circles at the lambda tips): Snowflake only. Other characters
  `fits` without frost, and the cold shows through the weather props.
- **Tears** (x ±36): eye-relative, so they stay.
- **zz, qmark, think, anger, rings and orbs:** unchanged. They sit around the
  same 340 × 460 surface, and every body stays inside the Snowflake's
  bounding box ±10 % (verified).
- **Reach readers** (`cardPlace` 2652, bubble `geo()` 3631–3637, the glint
  2115): read `BODY.reach` and `#body > .ball`. The glint is Snowflake only,
  since it lights the lambdas.
- **`sendRegion`** (3497) already takes `#body`'s bounding box. Nothing
  changes.

### 4. The eyes stay one shared rig

`EYE`, `R=76`, `sph()`, the moods, blink, gaze and the talk swell are
untouched. agy's mockups keep the same eye geometry for all three
characters, with the eyes in the same place: the terminal's screen, the
robot's visor and the devil's face are drawn around them. So there's no
per-character eye offset. If a body ever needs one, it's a later change,
not a field added now (nobody needs it).

### 5. Each character's one moving part

- CSS `@keyframes` from agy's mockup: `cursor-blink`, `antenna-pulse`,
  `tail-swish`.
- The animations use only `transform` and `opacity`, never `filter`, so the
  slow-frame budget is unchanged.
- They pause when he's been still for 60 s: `body.still .tCursor,…
  {animation-play-state: paused}`. The page has no idle class today (#140's
  idle mode works through the window shrinking), so the frame loop sets
  `body.still` when nothing has happened for 60 s: no mouse (`lastMouse`),
  not `busy`, not talking or listening. It clears the class on the next
  event, and toggles it only when the state changes, so it's one cheap
  check per frame.
- Under `@media (prefers-reduced-motion: reduce)` (the same query as
  `REDUCED`, line 1484), they don't animate.

### 6. Colours

`applyLook` already sets `--body0..2` and `--rim`. Each new body's fills
reference those variables, as agy's mockup does with `var(--white)` and
`var(--pupil)` for the eyes, so the user's body colour applies to every
character. A character's fixed accents (the terminal's green phosphor, the
devil's gold horns, the robot's antenna light) are its own colours. They
must keep 3:1 contrast against the user's body colour range (verified on
the default and the darkest and lightest presets).

### 7. The setting

- **`server.py` `look()`** (266–280) accepts `character` in
  `{"snowflake","terminal","robot","devil"}`, defaulting to `"snowflake"`.
  Today it silently drops unknown keys; an unknown `character` value is
  dropped the same way, so it stays snowflake.
- **`state_info`** (5206) sends `look.character` and the list of characters.
- **Settings → Look:**
  - a "Character" row of four previews, before Skin;
  - picking one calls `setCharacter` live and saves `look.character`.
- **`miniNixi()`** (1162–1175) draws its preview from the same `CHARACTERS`
  entry and the live `EYE` constants. That also fixes its eye `cx` of 25.5
  against the live 27.5. Its callers (`drawPreview`, the skin grid) keep
  working.
- **This step waits for #175 and #176 to merge**, since they rewrite the
  Settings window and the Voice tab in `index.html`. Steps 1–6 don't touch
  Settings and can go first.

### 8. Plugin characters: not in this issue

Intent Q1's answer was "built-in now, plugins later". The registry is the
extension point: a later issue adds a `body` slot to the plugin props
mechanism, drawn as a sanitised image (`plugins.py` 388–490), never as
markup. Nothing here builds that.

### 9. Voice

Unchanged (intent Q3). The Character row shows a one-line hint, e.g. "Robot
pairs well with the Robot voice (Voice tab)", but changes nothing itself.

## Alternatives rejected

- **A separate SVG file per character, loaded at runtime:** adds fetches, a
  loading state and a new trust path for files. The bodies are a few hundred
  bytes of fixed markup each, so inline strings are smaller and need no
  sanitising.
- **Replacing every coordinate literal with named constants:** the map found
  dozens. One translate per prop group, by anchor offset, gets the same
  result with a diff a reviewer can check, and leaves Snowflake's numbers
  exactly as they are.
- **A per-character eye rig:** the intent forbids duplicating the face
  logic, and agy's designs don't need it.
- **Character-specific props** (a robot hat): not asked for. `fits` hides
  what doesn't fit.
- **Plugin characters now:** the intent deferred them.

## Risks

- **Snowflake drifting from today's look.** Moving the markup into a template
  could reorder layers or lose a class. This is caught by the pixel test
  below, on the same headless Chromium the `*_fit` tests use.
- **Props on other bodies.** A translate can push a prop off the 340 × 460
  surface. `accessories_fit.mjs` is extended to run every skin and anchor on
  every character.
- **Contrast of the fixed accents** on unusual body colours: the contrast
  check below.
- **Merge conflicts with #175/#176/#177** in `index.html`. Steps 1–6 touch
  only `#body`, `drawSkin`, `drawSit`, the frame anchors and `miniNixi`, not
  Settings. The Settings row waits for their merge (see 7).
- **Performance:** CSS transform and opacity animations only, paused when
  idle. The slow-frame watcher still applies.

## Verification

- **Pixel test** (`tests/character_fit.mjs` plus `test_character_fit.py`, on
  the `*_fit` harness): Snowflake rendered at three moods on the branch is
  pixel-identical to `main`, in at most a 1 % anti-aliasing tolerance.
- **For each character, the same test checks that:**
  - it renders with `#face` present;
  - `#body`'s box is within the 340 × 460 surface through a bounce;
  - its touch animation runs, and is paused under `body.still` and reduced
    motion.
- **`accessories_fit.mjs`:** extended to every character, with every skin
  and plugin anchor it `fits`.
- **Unit test:** `look()` accepts the four characters, drops anything else,
  and defaults to snowflake.
- **Contrast:** each fixed accent against the default, darkest and lightest
  body presets is at least 3:1 (in the fit test, computed from the CSS
  values).
- **Full suite and the build.**
- **Live on p620,** after the merge and a deploy the user approves:
  - pick each character in Settings → Look;
  - he blinks, talks and listens;
  - a hat and the scarf sit right;
  - the touch pauses when idle;
  - Snowflake looks as it did.
