# Spec: News gets its own popout and animation

Code: `olafkfreund/nixoarchy-snowflake` (the companion). File and line
references are to `main` after PR #32. The system board (#166) is built at the
same time. **Only part 1 (`say`) is shared, word for word in both specs:**
whichever lands first adds it, and the other finds it there. Each spec adds
only its own kind to `run_stage`, `validate()` and `Store.put()`.

## Design

### 1. A plugin may give a spoken line, `say` (shared with #166)

- **Every plugin kind may carry `say`:** at most 200 characters, no control
  characters (`_str`). `validate()` keeps it.
- **`Store.put()` drops it from the page copy** (`page.pop("say", None)`; the
  stage dict itself is left alone, so the copy in `plugins._cache` keeps it
  for the next cached ask).
- **The phrase path speaks it.** `plugin_stage()` (`app/server.py:4631`)
  returns `st.get("say") or "Here you go."` in place of the fixed
  "Here you go." (`server.py:4648`). As today, that text is spoken and shown as
  his caption (`_said`, `server.py:5681`). It never goes into a prompt, and
  Nixi doesn't log it.
- **The agent path doesn't.** When the agent asks for a plugin
  (`plugin_stage_thread`, `server.py:4651`) the agent has already spoken its
  own sentence, so `say` is not used there (unchanged).
- `facts` gains `say` too, so existing plugins can use it.

### 2. The `headlines` kind

`app/plugins.py:702` accepts `got["kind"] in ("facts", "headlines")` (#166
adds `gauges`).

```json
{"v": 1, "kind": "headlines", "title": "News", "say": "Top stories: … from BBC News; … from Hacker News.",
 "source": "3 feeds · 1 couldn't be reached",
 "items": [{"title": "…", "source": "BBC News", "at": 1793780000, "url": "https://www.bbc.co.uk/news/…"}]}
```

`validate()` (`app/stages.py:76`), unknown keys dropped, anything else wrong
→ `None`:

| Field | Rule |
|---|---|
| `title` | `_str(…, 80)`, required |
| `say`, `source` | optional, `_str(…, 200)` / `_str(…, 120)` |
| `items` | list of **1–5** (the voice ordinals and `plugins.reserved()` already cover five) |
| `item.title` | `_str(…, 160)`, required |
| `item.source` | `_str(…, 40)`, required |
| `item.at` | `type(at) is int and at > 0` (so `True` isn't 1970), or `null` ("time unknown"); more than 10 minutes in the future becomes `null` |
| `item.url` | optional; kept only if `news_url_ok()`, otherwise dropped (the story shows with no Open) |

**`news_url_ok(u)`** (new, beside `item_url_ok`, `stages.py:189`):
- a string of at most 400 characters, no whitespace or control characters;
- scheme `https`; `":"` not in the netloc and no `"@"` (so no port, no user
  info, no IPv6 literal);
- host = `hostname.lower().rstrip(".")`, made of labels `[a-z0-9-]+` (1–63
  each, no empty label), at least two labels, and a last label of letters
  only (`[a-z]{2,63}`), which also refuses every numeric, octal and hex IPv4
  form (`2130706433`, `0x7f.0.0.1`);
- not `localhost`, and not ending in `.localhost`, `.local`, `.lan`,
  `.home`, `.internal`, `.home.arpa` or `.ts.net`.

Feed links are untrusted even from the user's own feeds (intent constraint).

**What this does and doesn't promise.** A story opens only if its link, as
written, is a public-looking `https` web address. Nixi doesn't resolve it or
follow it: the browser opens it with `xdg-open`, as it would any link in a
feed reader, and a site that redirects, or a public name that points to a
private address, is the browser's to handle (its own private-network
protections apply). This is the same trust as clicking the link in the
feed's own website.

**`Store.put()`** gets a `headlines` branch: each item with a URL gets an
`open` token (`("link", {"url": …})`), and the page gets the item without
`url`. One copy token for the whole list (titles and sources as text) under
`page["copy"]` (the key the voice handler falls back to when an item has no
token of its own, `server.py:5705`).

### 3. Voice: "open the first one", "copy that"

- **Opening:** no new routing. `fast_path` (`stages.py:429`) counts a stage's
  `items`, and the handler (`server.py:5704`) uses an item's `open` token, so
  "open the first one" up to "open the fifth one" work once items carry
  `open`. A story without a safe link answers "I can't do that yet." as today.
  The day desk's exclusion (`stages.py:440`) is untouched.
- **Copying:** `fast_path` returns `("copy", 0)` for "copy that / it / this"
  on a `headlines` stage (one list-wide copy token), where today more than one
  item would ask "Which one?".

### 4. Feed list outside the plugin's folder (`app/plugins.py`, `server.py`)

- **A new stage key `config`** (`STAGE_KEYS`, `plugins.py:27`; checked in
  `_check`, `plugins.py:145`): `true` or absent. With `true`, the plugin
  folder must hold `defaults.json`: inside the folder (`_inside`), a regular
  file, a JSON object of at most 16 KiB. It is part of the folder, so it is
  hashed.
- **The settings file:** `CONFIG_DIR = $XDG_CONFIG_HOME (or ~/.config)
  /nixi-companion/plugin-config`, file `<id>.json`. Nixi opens it
  `O_NOFOLLOW | O_NONBLOCK`, requires a regular file of at most 16 KiB holding
  a JSON object, and passes it on stdin as `config`. Missing → `config` is the
  plugin's `defaults.json`; unreadable or bad → also the defaults, and
  Settings shows "settings file unreadable".
- **Not hashed.** Editing feeds doesn't switch the plugin off. It grants
  nothing new: a network plugin can reach the internet whatever its config
  says (the approved decision).
- **The consent card** (`index.html:3129`) qualifies its promise when `config`
  is true: "Nixi checks it again if any of its files change. Its settings
  (~/.config/nixi-companion/plugin-config/news.json) aren't checked: change
  them freely."
- **Settings → Plugins** shows the path under the plugin and an "Edit" button.
  If the file is missing, Nixi creates it from `defaults.json` with
  `O_WRONLY | O_CREAT | O_EXCL | O_NOFOLLOW`, mode `0600` (never through a
  planted symlink), then opens it with `xdg-open`. No feed editor in v1.

### 5. The news plugin (`plugins/examples/news/`)

- **New example**, beside `rss-headlines`, which stays as the simple `facts`
  example. Manifest: id `news`; phrases `news`, `the news`, `what's the news`,
  `what is the news`, `headlines`, `the headlines`; `network: true`;
  `config: true`; `cache_seconds: 300`.
- **`rss-headlines` changes its phrases** to `rss headlines` and `rss feed`, so
  the two don't share one (a shared phrase works, but asks "Which one?",
  `server.py:5714`).
- **Feeds:** `config.feeds`, a list of at most 8 `{name, url}`; defaults
  (`defaults.json`): BBC News `https://feeds.bbci.co.uk/news/rss.xml`, The
  Guardian `https://www.theguardian.com/uk/rss`, Hacker News
  `https://hnrss.org/frontpage`.
- **Feed URLs are checked in the plugin** with the same rules as
  `news_url_ok` (https, a public-looking host name); a bad one is skipped and
  counted as failed. Redirects are followed only to URLs that pass the same
  check (a redirect handler, as `_NoRedirect` does for thumbnails,
  `stages.py:243`). The sandbox already blocks this computer's own addresses
  (#149); this keeps a feed from pointing at the local network.
- **Fetching:** all feeds at once (threads), each with a 2.2 s timeout and a
  2 MiB read cap, inside the 3 s plugin limit (`TIME_DEFAULT`,
  `plugins.py:429`). A failed feed is counted in `source` ("1 couldn't be
  reached"); the rest still show. All failed → a one-line `facts` card saying
  so (a `headlines` stage needs at least one item).
- **Parsing:** RSS 2.0 and Atom with `xml.etree` (stdlib). Titles are
  unescaped and stripped of tags; `pubDate` (`email.utils`) and Atom
  `updated` / `published` (ISO 8601) become `at`.
- **Merging:** dedupe by link with the fragment and `utm_*` parameters
  removed, then by normalised title (lowercase, no punctuation); newest
  first, undated last; the first 5.
- **`say`:** "Top stories: " + the first three titles with their sources,
  cut to 200 characters at a word boundary. Never "I read…".
- **The parsing and merging are functions** in `run` that the tests import
  directly (outside the sandbox).
- **README:** what it fetches, how to change the feeds (Settings → Plugins →
  Edit), and that it needs this Nixi version.

### 6. The `press` set: the popout's look (`index.html`)

- **A new stage set `press`,** chosen for kind `headlines`.
- **Newsprint:** an off-white paper (lighter than the notebook, no ruled
  lines), dark ink, a thin double rule under a small masthead ("News" and the
  date). Headlines in a serif face (`Georgia`, then `serif`); source and age
  in small capitals below each (`BBC NEWS · 2 h ago`, or `time unknown`).
- **Rows:** each story is a row with an "Open" button when it has a token; a
  hairline between stories.
- **Age** is computed by the page from `at` and the page clock, refreshed each
  minute while open.
- **Entrance, "press slip":** the card starts as a folded strip (about 18 px
  high) sliding out from his side (220 ms), then unfolds once to full height
  (`rotateX` from 70° to 0° about its top edge, 260 ms); rows fade in 40 ms
  apart. Under reduced motion it simply appears.
- **Accessible:** each Open is a real `<button>` named "Open: <title>"
  (keyboard reachable, Enter opens); text contrast ≥ 4.5:1 (#155); Esc
  closes; `stageText()` (`index.html:2336`) gets a `headlines` branch
  ("headline — source, age" per row).
- **Size:** within the frame's budget (about 340 px wide, `stagePlace`,
  `index.html:2214`). As an interactive stage it collapses to its tab after
  30 s without use, like the others.

## Alternatives rejected

- **Checking the link's DNS at open time:** a redirect after the browser
  opens it defeats it (Codex), and doing it right needs a thread timeout and
  IPv4-mapped address handling (agy) for little gain. The written-form check
  in part 2, stated honestly, is simpler.
- **Up to 8 stories:** voice ordinals stop at "fifth" (`stages.py:421`), and
  `reserved()` checks five. Five fits the card too.
- **Thumbnails:** the page may load nothing from news sites, so they'd need a
  server-side fetcher with type, size and redirect checks. Out of v1.
- **Feeds in the plugin's hashed folder** (Codex): every feed edit would
  switch the plugin off and ask again, for no gain in safety. The user chose
  outside.
- **Turning `rss-headlines` into the news plugin:** the plain `facts` example
  is the simplest stage plugin to copy; it stays.
- **An allowlist of news hosts per plugin** (agy): the user's feeds are the
  list, and a feed can link anywhere. The written-form check protects this
  machine and the network without limiting which sites can be news.
- **A feed editor in Settings in v1:** a list editor with validation is a
  feature of its own; the file and an Edit button cover it.
- **The broadsheet unfold** (agy): more motion next to a busy screen; the
  user chose the press slip.

## Risks

- **Hostile or huge feeds.** The 2 MiB cap and the sandbox's memory and
  output caps bound them. `xml.etree` relies on expat's entity-amplification
  limits (expat ≥ 2.4, bundled with Python 3.14); a feed that trips them
  counts as failed.
- **A headline that reads like an instruction.** It is shown and spoken as
  text only; plugin output never reaches a prompt (`server.py:4633`). `say`
  is read aloud as written, so it can say odd things, but it can't act.
- **Redirects and DNS** after the browser opens a link are the browser's to
  handle (part 2).
- **Feeds' terms and rate limits:** at most one fetch per feed per 5 minutes
  per machine (`cache_seconds: 300`, fetch only when asked).
- **Phrase change for `rss-headlines` users:** "headlines" moves to the news
  plugin; with news off, it goes to the agent as before #149.

## Verification

- **Unit (fork):**
  - `validate()` for `headlines`: a full example passes; 6 items, a
    161-character title, a missing source, `at: True`, `at: 1.5` refused; a
    future `at` becomes `null`; an unsafe URL is dropped, not refused.
  - `news_url_ok()`: accepts a normal news URL; refuses `http:`,
    `javascript:`, user info, a port, `[::1]`, `127.0.0.1`, `2130706433`,
    `0x7f.0.0.1`, `localhost`, `localhost.`, `box.ts.net.`, `.local`,
    `.home.arpa`, a one-label host, an empty label, a 401-character URL.
  - `Store.put` for `headlines`: items carry `open` tokens and no `url`; the
    page has no `say`.
  - `fast_path("open the second one", headlines)` → `("open", 1)` and the
    handler opens item 1's token; `fast_path("copy that", headlines)` →
    `("copy", 0)` and copies the list.
  - `config`: a missing file → the defaults; a symlink, a FIFO, over 16 KiB,
    or not an object → the defaults and the Settings note; editing it leaves
    the plugin on (not hashed); `_check` refuses `config: true` without a
    valid `defaults.json`; Edit never writes through a symlink.
  - The news plugin's functions: RSS and Atom samples parsed; two feeds
    merged, newest first, a duplicate (by link with `utm_*`, and by title)
    removed; a bad feed URL and a redirect to `http://192.168.1.1/` refused;
    `say` present and ≤ 200 characters.
  - The news plugin in the real sandbox (`tests/test_plugin_sandbox.py`) with
    no reachable feeds: returns the one-line `facts` card within the time
    limit.
- **Page (headless Chromium, `--disable-gpu`):** a `headlines` stage renders
  in the `press` set with source and age per row; Open buttons are reachable by
  Tab; reduced motion shows no animation; no request leaves the page for a
  news site (request log).
- **Live on p620** (real HTTPS feeds, which the sandbox fixture can't cover):
  "what's the news" shows the press slip with stories from the three default
  feeds within the time limit; he reads the top three; Open opens the article
  in the browser; "open the second one" opens the second; with one feed URL
  made unreachable the others still show and `source` says so; editing
  `plugin-config/news.json` to one feed changes the list on the next ask after
  the cache, and the plugin stays on.
