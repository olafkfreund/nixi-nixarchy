# Spec: the phone in Nixi, through Flux

Code paths are in `nixoarchy-snowflake` unless marked Flux. The Flux side is olafkfreund/nixarchy-flux#57 (spec
`spec/2026-11-13-57-call-approval-state.md` there). It adds per-device `call`, `missedCall` and `dnd {on, by, at}`, a
top-level `approvals`, the `dnd` capability in `plugins`, and `dnd.set`.

## Decisions

From the intent's open questions (owner, 2026-11-13: "use your recommendations"):

- "Send this" covers the clipboard and a screenshot, not the focused browser tab. Copying a URL covers the tab.
- The phone is silenced for any meeting Nixi senses: Meeting Mode, or a calendar meeting from a minute before its start
  to its end. Nixi gives the phone back only if nobody changed it in between.
- Outgoing calls ("talking") make Nixi quiet too.
- Phone Do Not Disturb goes through Flux's `dnd.set`. The desktop's Do Not Disturb is never touched.

From review:

- **Replying to app notifications is left out of v1.** Flux sends a notification reply with no outbox or delivery state
  (Flux `notifications.go:488`), so Nixi couldn't say whether it went. Texts only. `notification.reply` isn't in the
  call list.
- **Nixi doesn't hide Flux's call popup.** The popup stays the one visual. Nixi adds only the spoken line and suppresses
  the popup's category speech, so nothing is shown or said twice. That way Nixi can never hide a call it failed to
  announce.

## Design

### 1. `app/phone.py`: the Flux client

A new module, imported by `server.py` like `stages` and `quick`.

**Socket checks.**
- The path is `$FLUX_SOCKET`, else `$XDG_RUNTIME_DIR/flux/fluxd.sock`, else `/run/user/<uid>/flux/fluxd.sock` (Flux
  `docs/ipc.md:8-10`).
- Before connecting:
  - `os.lstat` the socket: it must be a socket (not a symlink) owned by our uid.
  - The parent folder must be owned by our uid and not group- or world-writable.
- After connecting, `SO_PEERCRED` must give our uid. That is Flux's own client check (`internal/ipc/peer.go:56-114`)
  plus the peer check.
- Any failure counts as "Flux isn't running", logged once.

**Threads.**
- A reader thread (daemon, in the style of `Mirror.start`, `server.py:691-694`) only reads lines:
  - `state` events replace `Phone.snap` and wake the worker.
  - Replies resolve their waiting `Future` by id.
- A worker thread runs `Phone.tick` and every handler. All `Phone.call` requests are made from the worker or from HTTP
  handler threads, never from the reader, so a reply can always be read.
- `Phone.call` waits up to 10 s for its reply.
- The read timeout is 30 s, and a timeout only checks whether `phone_on` is still on. Flux sends no heartbeat, so
  silence is healthy.
- EOF or a socket error drops `snap`, and the reader reconnects after 1, 2, 4… up to 30 s.

**The fixed call list.** `Phone.call(method, **params)` refuses any other method:

```
ring  share.url  share.text  share.files  clipboard.send  sms.refresh  sms.send  dnd.set
```

- `phone.py` is the only code that opens the socket. A test greps the code to check that.
- `share.files` accepts only paths in `Phone.outgoing`, a set of files Nixi registered itself (§4). The check is on
  `os.path.realpath`, and each path must be a regular file that isn't a symlink.

**The clean view.** `Phone.devices()` returns, per paired device:
- id, name, online, lastSeen, battery `{charge, charging}`
- `can`: a set built from Flux's `plugins`: `findmyphone` → ring, `share`, `sms`, `dnd`
- `call`, `missedCall` and `dnd` when present

`Phone.approvals()` returns the top-level list. Notification text, conversations, clipboard and settings stay inside
`phone.py`. The one exception is `sms_threads()`, which only the messages board calls.

**Records, not edges.** A snapshot can skip short transitions (Flux spec "Snapshot semantics"), so Nixi acts on
records with stable keys:

| Record | Key |
|---|---|
| call | device + `since` |
| missed call | device + `at` |
| approval | device + kind + `since` |
| transfer | id |

`Phone.seen` holds the keys Nixi has handled, and it survives reconnects. At the first snapshot after Nixi starts,
every record already present is marked seen without acting. Nixi doesn't announce a call that was ringing before he
came up.

`Phone.call_active` is a level: some device has a `call`.

**Old Flux.** When the snapshot has no `approvals` key, Flux predates #57: calls (§6), meeting silence (§8) and
approvals (§9) stay off.

### 2. Settings

- `DEFAULTS["phone_on"] = False` (`server.py:240-244`), in the bool allowlist and coercion (`:7993-7999`), echoed at
  `:7596-7597`.
- Switching it off runs `phone_reset()`, which is modelled on `mail_reset` (`:6794-6802`):
  - closes phone boards and drafts, and bumps `PHONE_GEN`
  - clears `Phone.outgoing` and deletes its files
  - closes the socket
- Settings UI: a row like Mail's (`index.html:921/929`, handler `:4514-4517`), "Phone (Flux)", with one status line
  under it:
  - "Connected: Pixel, iPad"
  - "Flux isn't running"
  - "Update Flux for calls and meeting silence" (old Flux)
  - "Turn on Sync Do Not Disturb on the Pixel for meeting silence" (`dnd.on` is null)

### 3. Find my phone

- **Phrases.**
  - The `phone_find` lang list ("where's my phone", "find my phone", "ring my phone", "ring my {name}") gets a branch in
    `quick.handle` before `quick.py:352`. It returns `{"phone": {"do": "ring", "name": …}}`.
  - `quick.matches` (`:325`) knows it too.
  - The server answers next to `server.py:8115`.
- **Which device:**
  - A named device that matches is rung.
  - One online device that can ring is rung.
  - With several, a card shows one button per device. A button calls `/api/phone/ring {id}` (token only; ringing sends
    nothing private).
  - With none online: "Pixel isn't connected, last seen 20 minutes ago".
- **The reply** is "Ringing your Pixel." A `not_supported` error gives "Your iPad can't ring".

### 4. Send to phone or tablet

- **Phrases** (`phone_send`): "send this to my phone", "send this to my {name}", "send the clipboard to …", "send a
  screenshot to …".
- **What is sent:**
  - "Screenshot": `capture("window")` (`server.py:1340`) writes under `SHOTS` (`:1288`). Nixi copies the file to
    `$XDG_RUNTIME_DIR/nixi-companion/phone/<random>.png` (mode 0600), registers that path in `Phone.outgoing`, then
    calls `share.files`.
  - A clipboard that is a single http(s) URL goes as `share.url`.
  - Other clipboard text goes as `share.text` (Flux caps it at 256 KiB).
  - A clipboard image is saved and registered like the screenshot, then sent as `share.files`.
- **Feedback:**
  - A link or text gets "Sent to your Pixel." Flux gets no receipt for those (Flux `share.go:907-931`).
  - A file is followed by its transfer id in `snap.transfers`:
    - done gives "On your Pixel."
    - `waiting` gives "Waiting for your Pixel; it goes when it's back."
    - failed gives "That didn't reach your Pixel."
  - A registered file is deleted when its transfer ends, or after 10 minutes, and removed from `outgoing`.
- **Device choice** is as in §3, with `can.share`.

### 5. Phone status and battery

- **Board.** `phone_stage()`, next to `mail_stage` (`server.py:6813`), builds a `gauges` stage with one gauge per paired
  device: battery percent, a charging mark, and "online" or "last seen 20 min". It opens on the `phone_status` phrases.
  It holds no private text, so it may stay in Back history.
- **Nudge.**
  - `phone_battery` goes into `Nudge.COOL` (`:2657-2658`) with 1800 s.
  - The worker offers it (`Nudge.offer`, `:2678`) when an online device's charge crosses from ≥15 to <15 while it isn't
    charging.
  - A per-device latch re-arms on charging or on ≥20.
  - The existing gates (`:2864/:2881`) keep it out of meetings, calls, the lock, Do Not Disturb and fullscreen.
- **Plugin input `phone-status`.**
  - It joins the `reads` tuple (`plugins.py:215`), and like `system-status` it is refused with `network: true` (`:219`).
  - It is fed on stdin (`:922/:926`) as `[{name, online, battery, charging}]`, with no ids, numbers or text, and is part
    of the cache key like `peer-status` (`:858`).
  - The sandbox mounts don't change, and the socket is never bound (`:657`).

### 6. Calls

- **Quiet.** `Ambient.phone_call = Phone.call_active` is added to `situation()` (`server.py:2196-2197`) and to the
  page's `SIT` and `quietNow()` (`index.html:2967-2968`). `meeting` isn't reused, because it drives the tie look.
- **When `phone_call` turns true**, the worker does what the stop and listen-cancel routes do (`:7856`, `:7860`):
  - `Speaker.stop()` (`:5314-5334`) drops playing and queued speech.
  - The follow-up window is cancelled, and an open `Listen` (`:8341-8355`) ends.
  - Wake listening holds while it is true, as it does in meetings (`:4411`).
- **Speech gates** take `phone_call` next to `meeting`: `mail_may_speak` (`:6671`), the unasked-speech block (`:7851`),
  and the Nudge gates (`:2864/:2881`).
- **The announcement.** For a call record not yet seen with `state == "ringing"`, Nixi speaks once in the normal voice
  (ElevenLabs, owner decision): "Anna is calling on your Pixel", or "A call on your Pixel" when there's no caller.
  - This speech bypasses the call quiet; it is the one exception.
  - Nixi stays silent when the desktop is locked, in a meeting, under Do Not Disturb, or with `proactive` off.
  - A call first seen as `talking` (answered within the coalescing window) isn't announced.
- **Popup speech only once.** In `Inbox.rows` (`server.py:3155-3176`), before details are blanked (`:3168`), a row is
  marked `phone_call: true` when all of these hold:
  - its app is a Flux device's name (`telephony.go:172`)
  - its title starts with Flux's "Call from " or "Missed call from "
  - Phone is connected to a #57 Flux

  `notifyIn` (`index.html:3045`) skips category speech for marked rows. The row itself is shown as before. A row that
  isn't matched only risks a second spoken word, never a hidden call.
- **Text back.**
  - A missed-call record not yet seen, with a `number`, on a device with `can.sms`, gives a card "Missed call from Anna"
    with a Text back button. It opens §7's draft with that number and the lang default "Sorry I missed your call, I'll
    call you back."
  - With no number, there's no button.
  - The card is held while locked, in a meeting, under Do Not Disturb or in a call. It shows afterwards if the record
    is still in the snapshot.

### 7. Messages

- **Read.**
  - The `phone_read` phrases call `sms.refresh`, then build a board from `sms_threads()`: up to 5 threads, each with its
    newest message.
  - The text goes through `mail_scrub` (`server.py:6615`), which blanks code-shaped tokens near one-time-code words. It
    is best effort, as the intent says.
  - Nixi reads them aloud through the mail speech path: `Speaker.say` with a playback re-check like `mail_play_ok`
    (`:6675-6681`), gated by the lock, a meeting and a call.
- **Privacy.**
  - The board is kind `phone_sms`. `stages.Store._keep` (`stages.py:428-430`) excludes it as it does `mail`.
  - `phone_on_screen()` joins `mail_on_screen()` in the `/api/capture` refusal (`server.py:8198-8202`), and is true
    while a messages board, draft card or missed-call card is up.
  - Message text and numbers never reach the agent or logs.
- **Draft.**
  - The `phone_reply` phrases ("reply to Anna, …", "text Anna …") match the name against the thread list. A Text back
    button opens a draft directly.
  - The server holds `PHONE_DRAFT = {id, device, number, name, created, gen}`. The recipient is fixed there, and the
    page can't change it.
  - The card shows the name, the number and an editable text field.
- **Send** (`/api/phone/send {draft, text}`):
  - It refuses unless all of these hold:
    - `click_ok(X-Nixi-Click)` (`server.py:80-82`, as at `:8188`)
    - the draft id is live, under 600 s old, and from the current `PHONE_GEN`
    - the text is 1-1000 characters
  - The page sends the header only from a trusted click (`index.html:1099`, `e.isTrusted`, `:3535-3549`).
  - The text in the request is what is sent. The click on the card that shows that text is the confirmation, so edits
    need no separate save.
  - The draft is consumed atomically before the Flux call (pop under a lock, as Mail does at `:6985`), so a second click
    or replay finds nothing.
  - It then calls `sms.send {device, addresses: [number], body}`.
  - The worker follows the outbox entry for that body:
    - gone with no failure gives "Sent."
    - still pending after 30 s gives "Still waiting on your Pixel."
    - failed gives "That text didn't go."
- **The agent can't send through Flux.** `click_only` (`server.py:867-871`) gains `_is_flux(text)`. It is true for:
  - any `flux-cli` invocation
  - `flux` followed by any of `send`, `clip`, `url`, `sms`, `ring`, `ping`, `notify`, `share` (the real verbs,
    Flux `cmd/flux/main.go:140-237`)
  - any mention of `fluxd.sock`

  It is checked on the raw, cleaned and default-expanded text, as the existing rules are. The same rule goes into the
  JS twin (`nixi-nixarchy bridge/send-policy.js`, `server.py:828`), with shared test cases.

### 8. Phone silent in meetings

- **When it applies.** `Phone.meeting_now()` is true when either holds:
  - Meeting Mode's flag file exists (as at `server.py:2206-2208`)
  - a timed calendar item with a meeting link (`stages.meeting_link`) has `start - 60 s ≤ now < end`, from
    `Ambient.cal_items` (`:2042-2057`, which keeps `end`)

  This is separate from `Ambient.meeting`, which keeps its current meaning. Calendar use needs `ambient_calendar`, as
  today.
- **When a meeting starts**, for each online device with `can.dnd` and `dnd.on == false`, Nixi:
  - calls `dnd.set {on: true}`
  - waits for the `dnd` report with `by: "set"` and `on: true` (up to 10 s)
  - records `Phone.silenced[device] = report.at`
- **When the meeting ends**, for each device in `silenced`:
  - it calls `dnd.set {on: false}` only if the device's `dnd` still has `on: true`, `by: "set"` and the recorded `at`.
  - Any other `at` means someone changed the phone since, so it's left alone.
  - Then `silenced` is cleared.
- A device with `dnd` absent or `on: null` is never touched.
- `silenced` is in memory. A Nixi restart mid-meeting leaves the phone silent, erring on the quiet side.
- Meeting Mode's own Sync Do Not Disturb keeps working. When it silenced the phone first, `dnd.on` is already true and
  Nixi does nothing.

### 9. Approve on the phone

- For an approval record not yet seen, a caption card says "Approve on your Pixel (sudo)", or "(ssh)". It isn't spoken,
  since the user just ran the command. It closes when the record leaves the snapshot.
- It has no buttons. Flux's helper and the phone do the approving.

### 10. Text and look

- Every phrase list and line goes in `app/lang/{en,nb,pl}.json` with the same slots (`tests/test_lang.py`).
- Existing card and board styles; no new props.

## Alternatives rejected

- **A sandboxed plugin, or a new plugin capability for Flux**: the sandbox can't reach the socket, and the socket can't
  be scoped (intent).
- **`flux-cli` subprocesses**: they give no events except `watch`, and every action forks.
- **Mail's send gate**: it doesn't check the click key on the server (`server.py:6964-7004`, `:8141`).
- **Reusing `Ambient.meeting`** for calls or silence: it drives the tie look, and it ends when the calendar meeting
  starts (`:2207`).
- **Dropping Flux's call popup**: if Nixi failed to announce a call, it would be hidden.
- **Turning on the desktop's Do Not Disturb** for calendar meetings: it silences the desktop and races Meeting Mode.
- **Speaking the approval hint**: the user just started the command.

## Risks

- **Privacy.** Message text and caller names reach ElevenLabs by owner decision. The lock, meeting and call gates, the
  playback re-check and the best-effort scrub are the net.
- **Socket power.** The client inside Nixi is as powerful as any local process. The boundary is the fixed list, the
  only-opener grep, and the `outgoing` path rule. Tests cover all three.
- **The agent path.** If the Python and JS `click_only` rules drift, an agent may send on one side. Shared cases are
  run against both.
- **Live checks need a host with fluxd and the new Android app.** fluxd isn't installed on p620. The owner names the
  host, and nothing is deployed without the owner's OK.
- **Older Flux**: §6, §8 and §9 are off, and the Settings line says so.

## Verification

### `tests/test_phone.py`

A fake fluxd serves a unix socket in `tests/nixi_env.py`'s run dir. It speaks JSON lines, sends scripted `state`
events and records the requests it gets. Each case gives inputs and the expected result.

**Socket checks.** Each of these is refused with "Flux isn't running", and no request is sent:
- a symlinked socket
- a socket owned by another uid (faked with a stubbed `lstat`)
- a parent folder with mode 0775

**Reader.** Two states arrive before the subscribe reply, and `snap` is the second. EOF reconnects after 1 s, then 2 s.
45 s of silence keeps the connection. A handler that calls `dnd.set` while the reader runs gets its reply.

**Call list.** `Phone.call` refuses all of:
- `commands.run`, `settings.set`, `automation.add`, `pair.accept`, `notification.reply`
- `share.files` with each of these paths:
  - `../x`
  - a sibling-prefix path
  - a symlink into `outgoing`
  - a folder
  - a file in the folder that isn't registered

A grep finds no `AF_UNIX` or `fluxd.sock` outside `phone.py`.

**Ring.** Device choice gives the expected request or card for:
- one device online: it rings
- two devices: a card with 2 buttons
- "ring my iPad": it rings the iPad
- no device online: the last-seen line
- `not_supported`: the can't-ring line

**Send.** Each input gives the expected request and line:

| Input | Request | Line |
|---|---|---|
| URL on the clipboard | `share.url` | sent |
| text on the clipboard | `share.text` | sent |
| "screenshot" | `share.files` with a registered run-dir path | follows the transfer |

The transfer goes `waiting`, then done, giving the waiting line, then the done line. The file is deleted after.

**Battery.**
- 16 → 14 gives one nudge, and 14 → 13 none.
- Charging, then 14 again, gives one more nudge.

**Calls:**
- a new ringing record stops speech and the follow-up window
- ringing → talking within one snapshot gives no announcement
- a call present at startup gives no announcement
- locked, meeting or Do Not Disturb gives no speech
- a Flux "Call from" row is marked before redaction with details off, and isn't marked with old Flux
- a missed call with a number gives the Text back card; without a number, no button
- a reconnect during the same ringing call doesn't announce it again

**Messages:**
- the board isn't kept in Back
- `/api/capture` gives 403 while it's up
- a one-time code is scrubbed

`/api/phone/send` is refused for each of:
- no click key
- a wrong click key
- an expired draft
- a draft from before Phone was switched off
- a replay after a success
- two parallel sends (exactly one `sms.send`)

An edited text is sent as edited.

**Silence:**

| Case | Expected |
|---|---|
| meeting start with `dnd.on == false` | `dnd.set on`; `silenced` records the report's `at` |
| meeting start with `dnd.on == true` | nothing |
| meeting end with the same `at` | `dnd.set off` |
| meeting end with a later `at` (user toggled, or another computer) | nothing |
| `dnd` absent or null | nothing |
| a calendar item from start-60 s to end | silent across the whole span, restored after `end` |

**Approvals.** A record shows the caption once. A record added and answered within one snapshot shows nothing.
