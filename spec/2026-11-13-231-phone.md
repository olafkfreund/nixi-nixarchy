# Spec: the phone in Nixi, through Flux

Code paths are in `nixoarchy-snowflake` unless marked Flux. The Flux side is olafkfreund/nixarchy-flux#57 (spec
`spec/2026-11-13-57-call-approval-state.md` there).

## Decisions carried from the intent's open questions (owner, 2026-11-13: "use your recommendations")

- "Send this" covers the clipboard and a screenshot, not the focused browser tab. Copying a URL covers the tab.
- Any meeting Nixi senses (Meeting Mode or a calendar item, `Ambient.meeting`) silences the phone. Nixi turns it back
  on only if he silenced it.
- Outgoing calls ("talking") make Nixi quiet too.
- Phone Do Not Disturb goes through Flux's new `dnd.set`. The desktop's Do Not Disturb is never touched.

## Design

### 1. `app/phone.py`: the Flux client

A new module, so `server.py` (8 700 lines) doesn't grow by the client. It is imported by `server.py` like `stages`
and `quick`.

**Connection** (`Phone.loop`, a daemon thread in the style of `Mirror.start`/`loop`, `server.py:682-694`):

- Socket path: `$FLUX_SOCKET`, else `$XDG_RUNTIME_DIR/flux/fluxd.sock`, as Flux resolves it (Flux `docs/ipc.md:8-10`).
- Before connecting, `os.stat` the folder and the socket, and refuse unless both are owned by our uid, the folder is
  `0700`, the socket isn't a symlink, and `SO_PEERCRED` on the connected socket gives our uid. These are the same
  checks Flux's own client makes (Flux `internal/ipc/peer.go:56-114`).
- Send `{"id":1,"method":"subscribe"}`, then read lines without pause. Every `state` event replaces `Phone.snap`. The
  first one may come before the reply (Flux `docs/ipc.md:87`).
- One request id counter. Replies are matched by id under a lock, with a 10 s wait each.
- The socket has a 30 s read timeout, so the loop notices the Phone switch going off.
- On EOF or error: drop `snap` and back off 1, 2, 4… up to 30 s. With no socket, check again every 30 s.
- Runs only while `CFG["phone_on"]` is true.

**The fixed call list.** `Phone.call(method, **params)` refuses any method outside:

```
ring  share.url  share.text  share.files  clipboard.send
sms.refresh  sms.thread  sms.send  notification.reply  dnd.set
```

Nothing else in the code path reaches the socket. `share.files` paths must be files Nixi made (its own screenshot under
its run dir), never a path from a phrase or the agent.

**The clean view.** `Phone.devices()` returns, per paired device:

- id, name, type, online, lastSeen, battery `{charge, charging}`
- `can`: a set built from `plugins` (ring, sms, share, dnd)
- `call`, `missedCall` and `dnd` when present
- `approvals` from the top level

Notification text, conversations, clipboard and settings never leave `phone.py`, except `sms_threads()`, which the
messages board alone calls.

**Changes.** Each new snapshot is diffed against the last view in `Phone.tick` (called by the loop after each state).
The changes go to the handlers in §3-§7. Like `Mirror.publish` (`server.py:611-618`), only real changes are published,
and `BUS.pub(t="phone", …)` carries the clean view for the page.

### 2. Settings

- `DEFAULTS["phone_on"] = False` (`server.py:240-244`), in the bool allowlist and coercion at `:7993-7999`, echoed at
  `:7596-7597`.
- When it goes off, `phone_reset()` runs, a copy of `mail_reset` (`:6794-6802`): it closes phone boards and drafts,
  bumps a generation, and stops the thread's subscription.
- Settings UI: a row like Mail's (`index.html:921/929`, handler `:4514-4517`), "Phone (Flux)", and below it one status
  line:
  - "Connected: Pixel, iPad"
  - "Flux isn't running"
  - "Flux is too old for calls and meeting silence"

  The last one shows when the snapshot has no `approvals` key, meaning no #57.

### 3. Find my phone

- **Phrases.** `quick.handle` (`quick.py:334`) gets a branch before `:352` for the lang list `phone_find` ("where's my
  phone", "find my phone", "ring my phone", "ring my <name>"). It returns `{"phone": {"do": "ring", "name": …}}`.
  `quick.matches` (`:325`) knows it too. The server answers in a sibling of `server.py:8115`.
- **Which device:**
  - a named device that matches → ring it
  - one paired device that is online and can ring → ring it
  - several → a card with one button per device. Each button calls `/api/phone/ring {id}`; ringing needs no click key,
    since it sends nothing private.
  - none online → "Pixel isn't connected, last seen 20 minutes ago", from `lastSeen`.
- The reply is spoken: "Ringing your Pixel." For a `not_supported` error he says the device can't ring.

### 4. Send to phone or tablet

- **Phrases** `phone_send`: "send this to my phone", "send this to my <name>", "send the clipboard…", "send a
  screenshot to…".
- **What is sent:**
  - "screenshot" → `capture("window")` (`server.py:1340`) to a file in Nixi's run dir → `share.files`. The file is
    deleted when the transfer ends, or after 10 minutes.
  - clipboard text that is a single http(s) URL → `share.url`
  - other clipboard text → `share.text` (Flux caps it at 256 KiB)
  - an image on the clipboard → saved like the screenshot → `share.files`
- **Feedback:**
  - Link and text: "Sent to your Pixel." That is the truth: Flux gets no receipt for those (Flux `share.go:907-931`).
  - File: Nixi follows that transfer in `snap.transfers`, and says "On your Pixel." when it's done, "Queued; it goes
    when your Pixel is back." when queued, and "That didn't reach your Pixel." when failed.
- Device choice works as in §3, with `can.share`.

### 5. Phone status and battery

- **Board.** `phone_stage()`, next to `mail_stage` (`server.py:6813`), builds a `gauges` stage (`stages.py`) with one
  gauge per paired device: the battery percent, a charging mark, and the label "online" or "last seen". The `phone_status`
  phrases ("how's my phone", "phone battery") open it.
- **Nudge.** Add a `phone_battery` kind to `Nudge.COOL` (`server.py:2657-2658`), with a 1800 s cooldown.
  - `Phone.tick` offers it (`Nudge.offer`, `:2678`) when an online device's charge goes from ≥15 to <15 while it isn't
    charging.
  - A per-device latch re-arms only when charging starts or the charge goes back to ≥20.
  - The nudge gates at `:2864/:2881` already keep it out of meetings, the lock, Do Not Disturb and fullscreen.
- **Plugin input.**
  - `"phone-status"` joins the `reads` tuple (`plugins.py:215`) and is refused with `network: true`, as `system-status`
    is (`:219`).
  - Its stdin value is `[{name, online, battery, charging}]` from `Phone.devices()`: no ids, numbers or text.
  - It goes into the cache key the way `peer-status` does (`:858`) and is fed at `:922/:926`.
  - The sandbox mounts don't change. The socket is never bound into a plugin (`:657`).

### 6. Calls

- **Quiet.** `Ambient.phone_call` is true while any device has `call`. It joins `situation()` (`server.py:2196-2197`)
  and the page's `SIT` and `quietNow()` (`index.html:2967-2968`). `meeting` isn't reused, since it also drives the tie
  look.
- **On the edge from no call to a call**, Nixi does what the stop route does (`/api/say/stop`, `:7856`):
  - `Speaker.stop()` (`:5314-5334`) drops what is playing and queued.
  - The follow-up window is cancelled and an open listen ends (the `/api/listen` cancel path, `:7860`, and
    `Listen`, `:8341-8355`).
  - Wake listening holds while `phone_call` is true, as it does in meetings (`:4411`).
- **The speech gates** take `phone_call` next to `meeting`: `mail_may_speak` (`:6671`), the unasked-speech block
  (`:7851`), and the Nudge gates (`:2864/:2881`).
- **The announcement.** On the edge into `call.state == "ringing"`, Nixi speaks once, through the normal voice (owner
  decision: ElevenLabs), "Anna is calling on your Pixel", or "A call on your Pixel" with no name. He doesn't when the
  desktop is locked, in a meeting, under Do Not Disturb, or with `proactive` off. He also shows a short caption.
- **No second alert.**
  - In `Inbox.rows` (`server.py:3155-3176`), a row whose app is the Flux device's popup (Flux names it after the
    device, `telephony.go:172`) is dropped. It is matched by the device name and a "Call from" or "Missed call from"
    title, read from the same strings Flux uses.
  - The drop happens only while Phone is on and connected, so it never hides a call when Nixi can't announce it.
  - Its category speech goes too, since the row never reaches `notifyIn`.
- **Text back.**
  - On a new `missedCall` with a `number` on a device with `can.sms`, a card says "Missed call from Anna" with Text
    back.
  - The button opens the reply draft of §7 with the number and the lang default "Sorry I missed your call, I'll call
    you back."
  - With no number, the card has no button.
  - Like the announcement, the card is held while locked, in a meeting, or under Do Not Disturb, and shown afterwards
    if the missed call is still there.

### 7. Messages

- **Read.**
  - `phone_read` phrases ("read my texts", "any new messages") call `sms.refresh` and then build a `phone` board from
    `sms_threads()`: up to 5 threads with the newest message each, scrubbed by `mail_scrub` (`server.py:6615`).
  - Nixi reads them aloud through the Mail speech path: `Speaker.say` with a playback re-check like `mail_play_ok`
    (`:6675-6681`), gated by locked, meeting and call.
  - The board has kind `phone`. `stages.Store._keep` (`stages.py:428-430`) excludes `phone` as it does `mail`.
  - `phone_on_screen()` joins `mail_on_screen()` in the `/api/capture` refusal (`server.py:8198-8202`).
- **Draft.**
  - `phone_reply` phrases ("reply to Anna, …", "text Anna …") match a name against the thread list.
  - The draft card shows the recipient's name and number and an editable text. It is held server-side with an id, a
    600 s expiry and the exact text, as `mail_draft` holds them (`:6880`).
- **Send, click-only, checked by the server.**
  - `/api/phone/send {draft, text}` refuses unless `click_ok(X-Nixi-Click)` (`server.py:80-82`, as at `:8188`) and
    the draft is live and the text matches.
  - The page sends the header only from a trusted click (`index.html:1099`, `e.isTrusted`, `:3535-3549`).
  - It then calls `sms.send`, or `notification.reply` when the draft came from a notification with a reply id.
  - Nixi follows the outbox entry and says "Sent." on success, "Still waiting on your Pixel." while pending, or "That
    text didn't go." on failure.
- **The agent can't send.** `click_only` (`server.py:867-871`) gains `_is_flux_send`, which matches `flux-cli` with
  `sms`, `notify`, `share` or `ring`, and any `fluxd.sock`. The same rule goes into the JS twin
  (`nixi-nixarchy bridge/send-policy.js`, `server.py:828`). An agent Bash call to them needs a click like a `gog`
  send.

### 8. Phone silent in meetings

- On the edge into `Ambient.meeting`, for each online device with `can.dnd` and `dnd == false`: call `dnd.set
  {on:true}` and record the device in `Phone.silenced`.
- On the edge out of the meeting, for each device in `silenced` whose `dnd` is still `true`: call `dnd.set
  {on:false}`. Then clear `silenced`.
- A device with no `dnd` reported (an old app, or its sync off) is left alone. Nixi doesn't set what he can't see.
- If the user turns Do Not Disturb on or off on the phone during the meeting, Nixi drops that device from `silenced`
  and leaves its state alone.
- Meeting Mode's own sync still runs. When both silence the phone, Nixi's restore only happens if the phone is still
  silent. It's harmless either way.
- `silenced` lives in memory only. After a Nixi restart mid-meeting, Nixi doesn't restore that phone, which errs on the
  silent side.

### 9. Approve on the phone

- On a new entry in `approvals`, Nixi shows a caption card: "Approve on your Pixel (sudo)", or "(ssh)". Nixi doesn't
  speak it, because the terminal or git command is what the user just ran. It closes when the entry goes.
- No buttons. Nothing here answers an approval; Flux's helper and the phone do.

### 10. Text and look

- Every phrase list and line goes in `app/lang/{en,nb,pl}.json` with the same slots (`tests/test_lang.py`).
- The phone board and cards use the existing card styles. New props are none.

## Alternatives rejected

- **A sandboxed plugin, or a new plugin capability for Flux**: the sandbox can't reach the socket, and the socket
  can't be scoped (owner decision in the intent).
- **`flux-cli` subprocesses instead of the socket**: there's no event stream except `watch`, and every action forks.
  Flux's own docs prefer the socket for continuous clients.
- **Mail's send gate for texts**: it doesn't check the click key on the server (`server.py:6964-7004`, `:8141`).
- **Reusing `Ambient.meeting` for calls**: it changes the tie look and the meeting copy.
- **Speaking the approval hint**: noisy for an action the user just started.
- **Turning on the desktop's Do Not Disturb for calendar meetings**: it silences the desktop the user may want, and it
  races Meeting Mode.

## Risks

- **Privacy.** Message text and caller names reach ElevenLabs by owner decision. The gates (lock, meeting, call,
  playback re-check) and the scrub are the safety net. The scrub is best effort.
- **A Flux socket client inside Nixi** is as powerful as any local process. The fixed list is the boundary. A bug that
  bypasses `Phone.call` is the main risk. Tests check that the list refuses everything else, and grep checks that no
  other code opens the socket.
- **The Inbox drop** matches Flux's popup text. If Flux changes its wording, Nixi shows a duplicate rather than missing
  a call, which is the safe direction.
- **Live checks**: `fluxd` isn't installed on p620. Live checks need a host with Flux and a paired Android phone. The
  owner names the host, and nothing is deployed without the owner's OK.
- **Older Flux**: everything in §6, §8 and §9 is off without the #57 fields, and the Settings line says so.

## Verification

- **`tests/test_phone.py`**: a fake fluxd on a unix socket under `tests/nixi_env.py`'s run dir. It speaks JSON lines,
  sends scripted `state` events and records requests. It checks:
  - the folder and socket checks: wrong owner, a symlink and mode 0755 are each refused
  - subscribe and newest-state handling, and reconnect after EOF with backoff
  - `Phone.call` refuses `commands.run`, `settings.set`, `automation.add` and `pair.accept`
  - ring device choice: one, several (card), named, offline with last seen, and `not_supported`
  - send:
    - a URL goes as `share.url`, text as `share.text`
    - a screenshot goes as `share.files` with a run-dir path only
    - transfer done, queued and failed lines
  - the battery nudge comes once below 15% and re-arms only on charging or ≥20
  - calls:
    - the edge stops speech and the follow-up window
    - the announcement is skipped when locked, in a meeting or under Do Not Disturb
    - the Flux call popup row is dropped only while connected
    - Text back appears only with a number
  - messages:
    - the board is excluded from Back
    - capture is refused while it's up
    - `/api/phone/send` without the click key is refused, and with a stale draft or changed text too
    - one-time codes are scrubbed
  - silence:
    - set on meeting start only when `dnd == false`
    - restored only when Nixi set it and the phone is still silent
    - a user change in between is respected
    - unknown `dnd` is left alone
  - approvals: the card appears and goes with the entry
