# Spec: Three claims nothing checks

## Design

### 1. The unit file gains the module's ordering, and a test holds them together

`systemd/nixi-watch.service` gains `PartOf=graphical-session.target`,
`After=graphical-session.target`, `WantedBy=graphical-session.target` and
`RestartSec=2`.

`ExecStart` and `Environment=PATH` stay different, deliberately: one path
installs to `~/.local/bin` and the other to a store path, and no parity rule can
or should collapse that.

`tools/test_nixi.py` gains a check comparing the two definitions on the fields
that must match -- `Type`, `Restart`, `RestartSec`, `PartOf`, `After`,
`WantedBy` -- by parsing the `.service` file and grepping the module. It runs
inside `checks.selfcheck`, which CI already builds, so it needs no new job. That
is what `CONTRIBUTING.md:52` asks for, in the cheapest place that satisfies it.

The manual service and timer are already consistent; the test covers them too so
they stay that way.

### 2. The flake comment says what the build actually asserts

`flake.nix:35`'s "assets non-empty" becomes a description of what
`installCheckPhase` really checks at `package.nix:203-211`: the manifest, the
QML, the shared JS and the bridge files are all present and non-empty.

### 3. The button's version is asserted, not duplicated in hope

`installCheckPhase` gains a check that `button/manifest.json`'s `version` equals
the package version, which is already derived from `manifest.json`. A mismatch
fails the build naming the file.

Asserting rather than generating: the file is otherwise hand-maintained and
generating one key would make it half-generated, which is harder to reason about
than a one-line check.

## Alternatives rejected

**Generate the unit files from the module.** The right long-term shape, and too
large for this: the two paths install to different prefixes, so generation needs
a parameterised writer and a build step `install.py` can consume. A test that
fails on drift gets the safety now.

**A new CI job for parity.** `checks.selfcheck` already runs on every PR and
already contains this class of invariant (`test_rebrand_is_complete`,
`test_old_widget_stays_gone`). A second job would be slower and no stricter.

**Delete `flake.nix:35`'s clause entirely.** Describing the real assertions is
more useful than describing none, and costs the same.

**Generate `button/manifest.json`.** See 3.

## Risks

- **Changing `WantedBy` orphans the old symlink.** A machine that already
  enabled the unit has `default.target.wants/nixi-watch.service`; installing the
  new file does not remove it, so the unit may still start early until
  re-enabled. `install.py` already runs `systemctl --user daemon-reload` and
  enable; worth confirming it re-enables rather than assuming, or the fix does
  not reach existing machines.
- **The parity test is string-matching a Nix file.** It will need updating if
  the module is restructured, and a careless update could weaken it to vacuity.
  Asserting on specific expected values rather than on equality of two parsed
  blobs keeps a weakened version visible.
- Host-specific risk: the unit change affects only the `install.py` path.

## Verification

1. `nix flake check` -- `checks.selfcheck` runs the new parity test;
   `checks.package` runs the new `button/manifest.json` assertion.
2. `python3 tools/test_nixi.py` directly.
3. Deliberately break each: change `RestartSec` in the file only, and bump
   `button/manifest.json`'s version. Both must fail, naming the file. **A test
   that cannot be made to fail is not a test** -- this is the step that proves
   these three are checks rather than three more claims.
4. Runtime, plugin-manager path: after `install.py`, `systemctl --user show
   nixi-watch.service -p WantedBy -p After` reports `graphical-session.target`.
