# Spec: one thing on stage — a Linux terminal for working agents, and no more stacked reactions

All code is in `nixoarchy-snowflake`, branch `feat/227-stage-focus` from `origin/main` 587d18b. Line numbers are
against that commit and only `app/static/index.html` changes, plus one new browser test. No server change: the
`working` event already carries the agent and a project name (`app/server.py:1490-1496`).

## Design

### 1. One focus, derived — not a new state machine

A single function `stageFocus(now)` returns one of `answer | event | work | media | ambient`, computed from state that
already exists. No queue and no new event plumbing; every painter asks it.

| Focus | True when (existing state) |
| --- | --- |
| `answer` | `pendingAppr`, the password card (`pwEl.on`), the approval card (`apEl.on`), `MIR.owner==='pending'`, an agent `ask` mark live (`AM&&AM.kind==='ask'`), or a notification card with buttons showing (`notifyRow&&notifyRow.card`) |
| `event` | a one-off reaction playing (`RX` and not in `RXS`), the mail pop-out on (`#mailPop.on`), a chat/feed prop live (`propOn&&now<propOn.until`), or a notification row showing (`notifyRow`) |
| `work` | `CP.working()`: his own tool run or at least one agent in the new agent map (§3) |
| `media` | `sitOn.music \|\| sitOn.video` |
| `ambient` | otherwise |

The result is written to `document.body.dataset.focus` only when it changes (one attribute write, not per frame),
so CSS can hide layers with `body[data-focus=…]` rules.

### 2. Each painter obeys the focus

- **Reactions** (`rxPaint`, `index.html:1777-1787`): stop the union. Paint the one-off `RX` alone if there is one;
  otherwise at most **one** sustained id, and only if its focus is current — `video`/`music` when focus is `media`,
  `load`/`memory` (load first) when focus is `ambient`. `rxPaint` already short-circuits on an unchanged key, so a
  focus change just becomes part of that key. Sustained ids stay in `RXS` and come back when the focus returns.
- **Situational looks** (frame block `index.html:2417-2433`): the targets for glasses, shades, tie, hats, scarf and
  weather marks get `&& focus==='ambient'`; headphones keep their rule and get `&& focus==='media'`. The chat/feed
  props are part of `event` and keep their own timing. Per slot: eyes = shades > glasses; head = the one hat rule that
  exists today; neck = tie > scarf. Since reaction props that wear things (`done` shades, `snow` beanie, `workout`
  headband, `meeting` headset) only show in `event`, and looks only in `ambient`, they can no longer meet.
- **Music** while not in `media`: the boombox and notes are not painted; the ♪ chip (`musSync`, `index.html:1800`)
  keeps showing, so music stays reachable. `musBox()` (`1799`) is redefined as "boombox painted", so headphones and
  chip logic keep working.
- **Beside him** (one thing at a time): approval/password card > answer stage `#stg` > mail pop-out > agent terminal.
  The terminal is hidden with a class (`#code.away`, opacity 0, no layout change) while anything above it is out, and
  comes back unchanged. `mailPop` and `stageShow` keep their own logic; the terminal is the one that yields.

### 3. The agent terminal

- **Agents**: `ag` (one object, `index.html:4871-4883`) becomes `ags`, a `Map` keyed `from + '|' + project`, value
  `{from, name, project, t0, last}`. `CP.agent(ev)` takes the whole event (the handler at `2828` passes `ev`, so the
  project is no longer dropped). `agentEnd(from, project)` deletes that key; the sheet hides only when the map is
  empty and his own turn is not running. `ask` ends the entry too (the handler at `2829` calls `agentEnd` for every
  non-`working` kind). Entries without a heartbeat for 15 minutes are pruned, as today.
- **Own runs**: `open()` (`4822`) no longer calls `agStop()`. When his own run ends (`run()`, `4866`) and the map is
  not empty, the sheet goes back to the agents view instead of hiding.
- **Look** (CSS `index.html:722-753`): `border-radius:6px`, solid dark background from the theme (`--tbg`, falling
  back to `#0d1117`), 1px border, soft shadow, no `::before/::after` tail, no tilt (the `rotate(...)` in the sheet
  transform at `4790` is removed). The title bar is solid, monospace, with three small window dots on the left and,
  on the right, one 14px icon per distinct `from` in the map — clones of the existing original marks `#amC` (claude),
  `#amX` (codex), `#amA` (agy) from `index.html:829-835`; any other agent gets a rounded square with its initial.
- **Body**: one status line per entry, real data only: `$ <agent> · <project> · <m>m`, with the minutes updated by
  the existing 900 ms timer (text change only, no new lines). Below a dashed rule, a fixed-height block of dim bars
  (CSS gradients, no characters) that scrolls with a CSS `@keyframes` animation — plainly decorative, never text.
- **Size**: a fixed height for the agents view (status lines grow it, max 4 lines then `+N more`), so the
  `MutationObserver → fitSheet → sizeWindow` chain (`4805`) no longer runs every 900 ms. The one-minute `mini` class
  and its CSS go.
- **Calm**: `CP.agent` does not show the sheet while `body.calm`; the map still updates, so it appears when calm ends.
- **Peek**: `idleShowing()` (`index.html:4656-4658`) gains `CP.working()`, so he doesn't shrink to peek while agents
  work.

### 4. Nixi while agents work (focus `work`, not in bar or hover)

- **Code eyes**: a new `<g id="codeEyes">` inside `#face` (after `#eR`, `index.html:814-817`), so it follows his gaze,
  tilt and size like the eyes. It is one rounded dark screen spanning both eye positions with 4–5 short coloured bars
  in a clip path, scrolled by a CSS `@keyframes` (steps), and a blinking cursor. CSS
  `body[data-focus=work]:not(.bar):not(.hover) #eL, … #eR {opacity:0}` and `… #codeEyes {display:inline}`. The same
  group works for all four characters because `#face` is shared; its width follows `EYE_HALFW`/`EYE.cx` once at
  `applyLook`, not per frame.
- **Keyboard**: a new `<g id="kbd">` after `#accFront` (`index.html:823`): a small flat keyboard at his base plus two
  paw nubs that tap with a CSS animation (the `.nub` pattern from the `open` reaction). Its y comes from the
  character's `shadow` value in `CHARACTERS` (`index.html:1347-1365`), set at `applyLook`.
- **Mood**: the working focus uses the existing `running` mood so blinks and gaze stay natural; the code panel's
  `gazeHook` is not needed while code eyes show.
- **Reduced motion**: the scroll, cursor and paws stop; the existing `@media (prefers-reduced-motion:reduce)` rule
  only covers `#stage *`, so the new `#code` scroll gets its own rule.
- **Bar mode**: unchanged (decision 5): `body.bar` hides `#kbd` and `#codeEyes`, and the notch keeps today's
  terminal text.

## Alternatives rejected

- **A scene manager that owns every layer** (reactions, looks, cards, terminal rewritten around it): the right shape
  long-term, but it rewrites ~1,000 lines of tuned drawing code for the same visible result. The derived
  `stageFocus()` gets one focus with a few guards per painter.
- **Queueing short events until agents finish**: notifications expire at 4 s by design (`index.html:3008`) and the
  server hands them to the desktop popup at 5 s; a queue would show stale mail minutes late.
- **Server-side arbitration**: the server doesn't know about cards, mail pop-outs or answer stages on the page;
  the page is the only place that sees all of them.
- **Fake code text in the terminal**: rejected in the intent decisions — it reads as real agent output.
- **Separate code-eye art per character**: four times the art for a group that already sits in the shared `#face`.

## Risks

- **Approval and card clicks** (`sendRegion`, `index.html:4606`): hiding the terminal with opacity must not leave
  its region clickable or remove the card's region. The browser test checks the region list with a card open.
- **Window sizing**: `sheetWant` (terminal) and `popWant` (mail) both ask for room; with the terminal yielding, its
  `sheetWant` must drop while `.away` or the window stays wide.
- **Keyboard placement per character**: the four bodies have different bottoms; the y offset needs a screenshot check
  for each (headless, `--disable-gpu` only: Chrome previews hung the GPU before).
- **Focus flicker**: `sitOn` already debounces 3 s on / 8 s off (`index.html:2957-2959`), and `RX` lasts 3–4 s; focus
  only changes on those, so the body attribute changes at that rate, not per frame.
- **Hosts**: page only; every host that runs the companion picks it up on the next deploy. Folder plugins are not
  touched.

## Verification

- New `tests/stage_focus_fit.mjs` + `tests/test_stage_focus_fit.py` (the existing pattern: server in `nixi_env`,
  headless Chromium with `--disable-gpu`), checking:
  1. music on + a `working` event: focus `work`, no boombox or notes in `#rxFront`/`#rxSky`, ♪ chip visible,
     `#codeEyes` shown, eyes hidden, glasses target 0 with `coding` on.

  3. claude and codex `working` in two projects: two status lines and two icons; codex `done` leaves claude's line;
     claude `ask` ends the sheet.
  4. an approval card during work: focus `answer`, the card's region present, the terminal's absent.
  5. `body.calm`: no sheet; `body.bar`: no `#kbd`/`#codeEyes`.
  6. reduced motion: no running animations on `#code` or `#codeEyes`.
- The existing fits still pass: `react_fit`, `notify_fit`, `mail_fit`, `agent_approve_fit`, `accessories_fit`,
  `character_fit`, `stages_fit` (some pin the old stacking and are updated where they assert it, in the same commit).
