# Spec: one thing on stage — a Linux terminal for working agents, and no more stacked reactions

All code is in `nixoarchy-snowflake`, branch `feat/227-stage-focus` from `origin/main` 587d18b. Line numbers are
against that commit. Only `app/static/index.html` changes, plus one new browser test and updates to existing fit
tests that pin the old stacking. No server change: the `working` event already carries the agent and a project name
(`app/server.py:1490-1496`).

## Design

### 1. One focus, derived from what is on screen

`stageFocus(now)` returns one of `answer | event | work | media | ambient`. It is computed in `frame()` (a few
boolean reads per frame); `focusSync()` acts only when the value changes: it sets `document.body.dataset.focus`, then
calls `rxCheck()`, `CP.sync()` and `musSync()`. That is the single transition point — the class-only
`MutationObserver` at `index.html:1820` is not relied on.

| Focus | True when |
| --- | --- |
| `answer` — you're using it or it needs your answer | `pendingAppr`; `pwEl.classList.contains('on')`; `apEl.classList.contains('on')`; `MIR.owner==='pending'`; a notification card with buttons drawn (`notifyRow&&notifyRow.card&&notifyRow.span.isConnected`); the answer stage open (`stgOpen()`); the music card open (`#musCard` not hidden) |
| `event` | `now < evUntil` |
| `work` | `CP.working()`: an agent entry exists (§3), or his own **tool** run is active (`running \|\| q.length>0` inside CP — not `busy`, so a plain spoken reply is not `work`) |
| `media` | `sitOn.music \|\| sitOn.video` |
| `ambient` | otherwise |

`evUntil` is one variable, pushed forward by a helper `evHold(ms)` where short events already start:
`notifyDrain` (5 s, 7 s for a card — `index.html:3007`), `mailPop` (5 s, `3034`), `nudgeDrain` (4 s, `2933-2951`),
an agent `done` or `ask` (2.5 s, handler at `2829-2837`), and `rxPlay` for event reactions (their duration).
No queue: an event that arrives during `answer` simply doesn't show its props, as today when a card is open.

The agent **ask** mark (`AM`, live 60 s, `index.html:2726-2730`) and the attention cue stay what they are — small cues
that may accompany any focus, with click-to-jump. They are deliberately not part of `answer`, so a question already
answered in the terminal can't hold the stage for a minute.

### 2. Each painter obeys the focus

- **Reactions** (`rxPaint`, `index.html:1777-1787`): every reaction id gets a focus: `music`, `video` → `media`;
  `load`, `memory`, `rain`, `snow`, `wind`, `meeting` → `ambient`; all others (`done`, `ask`, `notice`, `open`,
  `error`, `soon`, `workout`) → `event`. `rxPaint` paints **one** id: the playing `RX` if its focus is current, else
  the sustained id for the current focus (`media`: video > music; `ambient`: load > memory). `r-<id>` is added only for
  that one. Focus becomes part of `rxKey`. Ids stay in `RXS` and come back with their focus. Event reactions call
  `evHold` in `rxPlay`.
- **Situational looks** (frame block `index.html:2417-2433`): glasses, shades, tie, hats, scarf targets get
  `&& focus==='ambient'`; headphones keep their rule and get `&& focus==='media'`. Per slot: eyes = shades > glasses;
  neck = tie > scarf; head = today's single hat rule. Weather marks (`wxStep`, `2162-2228`, called at `2443`) are
  drawn only in `ambient`. Small one-off kicks (party confetti, the meeting jelly, `index.html:2958`) stay: they are
  motion, not things he wears.
- **Music chip**: `musBox()` (`1799`) keeps its meaning (music is on), so the ♪ chip shows in every focus except
  `answer`; the headphones' "boombox stands in" check (`2426`) uses a new `boomPainted()` = music painted by
  `rxPaint`.
- **Beside him**, one at a time: everything in `answer` > mail pop-out (`event`) > agent terminal (`work`). The
  terminal shows only in focus `work` (`CP.sync()` adds or removes `#code.on`, keeping its content), so `dropSync`
  (`3917`) and `sizeWindow` (`4596`) see it gone and `sheetWant` returns to `[0,0]`. `mailPop` doesn't pop out in
  `answer` (its row and caption still show). `#code` has `pointer-events:none` and no click region of its own
  (`index.html:724`, `4606`); the region work is the mail, card and stage regions, which are unchanged.

### 3. The agent terminal

- **Agents**: `ag` (`index.html:4871-4883`) becomes `ags`, a `Map` keyed `from + '|' + project`, value
  `{from, name, project, t0, last}`. The handler at `2828` passes `ev`; `CP.agent(ev)` updates the map **always**
  (also during his own run and in calm), then calls `sync()`. Every non-`working` kind (`done`, `ask`) calls
  `CP.agentEnd(ev.from, ev.project)`; an empty project removes every key of that agent. Entries with no heartbeat
  for 15 minutes are pruned.
- **His own runs**: `hide()` (`4806`) no longer clears the map (`agStop()` only stops the timer when the map is empty).
  `open()` (`4822`), `answer()` and `done()` (`4888-4889`) end in `sync()`, which shows the agents view when the map
  is not empty and his own run is over, and hides the sheet otherwise.
- **Look** (CSS `index.html:722-753`): a terminal window — `border-radius:6px`, fixed dark colours (`#0d1117`
  background, `#c9d1d9` text, `#30363d` border; the theme's `--tbg` can be light, `index.html:1163`), soft shadow, no
  `::before/::after` tail, no tilt (the `rotate(...)` in the sheet transform at `4790` goes). Solid title bar,
  monospace: three small dots on the left; on the right one 14px icon per distinct `from` in the map. Icons are made
  once at start from the original marks `#amC`, `#amX`, `#amA` (`index.html:829-835`) by cloning their children and
  stripping `id` and `display` (a `<use>` would inherit the `display="none"` that `agentMark` sets); any other agent
  gets a rounded square with its initial.
- **Body**: one status line per entry, real data only: `$ <agent> · <project> · <m>m`; at most 4, then `+N more`.
  A timer every 15 s rewrites a line's text only when its minute changed, so the sheet's `MutationObserver → fitSheet`
  (`4805`) runs about once a minute, not every 900 ms. Below a dashed rule, a fixed-height block of dim bars (CSS
  gradients, no characters) scrolled by a CSS `@keyframes` — plainly decorative. The one-minute `mini` class and its
  CSS (`728`, `4881`) go.
- **Calm** (`index.html:593`): CSS `body.calm #code, body.calm #kbd, body.calm #codeEyes {display:none}`, both ways at
  once; the map keeps updating underneath.
- **Bar**: the notch keeps today's look (decision 5): `body.bar #code` hides the dots, icons and the decorative
  block, so only the status lines show as text.
- **Peek**: `idleActive()` (`index.html:4653-4655`) gains `CP.working()`, so a working agent brings him back from
  peek and keeps him full size, as the intent asks. (`idleShowing()` would only stop further shrinking.)
- **Switch**: with `code_panel` off (`4510`) there is no sheet, no keyboard and no code eyes; the focus `work` still
  holds the stage so nothing else stacks.

### 4. Nixi while agents work (focus `work`; not in bar, hover, calm or `goohide`)

- **Code eyes**: a new `<g id="codeEyes">` inside `#face` (after `#eR`, `index.html:814-817`): one rounded dark
  screen, sized and centred from the character's `faceBox` (`index.html:1348-1365`) at `setCharacter`, with 4–5 short
  coloured bars in a clip path scrolled by a CSS `@keyframes` (steps) and a blinking cursor. `#face` itself is never
  transformed (the eyes are redrawn as paths each frame), so `frame()` sets one `transform` on `#codeEyes` from the
  same gaze offset and size spring the pupils use — only while it shows. CSS hides `#eL`/`#eR` and shows `#codeEyes`
  under `body[data-focus=work]`, with the modes above excluded.
- **Keyboard**: a new `<g id="kbd">` after `#accFront` (`index.html:824`): a small flat keyboard below his body and
  two paw nubs tapping with a CSS animation (the `.nub` pattern of the `open` reaction). Its y is the body's bottom,
  `BODY.pivot` (snowflake 76, terminal 91, robot 82, devil 84), plus the `base` anchor, set at `setCharacter`.
- **Mood**: a new `working` mood (calm brows, round pupils, no sweat — `running` drips sweat every 1.8 s,
  `index.html:2410`), chosen in `mood()` (`1925-1938`) just above `idle`, so recording, talking, `busy` and the
  mirror still win.
- **Reduced motion**: a static rule next to `index.html:22`:
  `@media (prefers-reduced-motion:reduce){#code *, #codeEyes *, #kbd *{animation:none!important}}` — the injected
  `#stage *` rule only exists while a reaction is painted.

## Alternatives rejected

- **A scene manager that owns every layer**: rewrites ~1,000 lines of tuned drawing for the same visible result; a
  derived focus plus one guard per painter does it.
- **Queueing short events until agents finish**: notifications expire at 4 s by design (`index.html:3008`) and go to
  the desktop popup at 5 s; a queue would show stale mail minutes late.
- **Enumerating each short event's own state in the focus** (`RX`, `notifyRow`, `#mailPop`, `propOn`, nudges, `AM`):
  their lifetimes differ and some outlive what's on screen (`AM` 60 s, the reminder chip 30 s); one `evUntil` set
  where each starts is smaller and can't stick.
- **The agent ask mark as `answer`**: it can stay 60 s after you answered in the terminal, freezing the stage.
- **Server-side arbitration**: only the page sees cards, pop-outs and stages.
- **Fake code text**: rejected in the intent decisions.
- **Code-eye art per character**: one group sized from each character's `faceBox` covers all four.

## Risks

- **Existing fit tests pin the stacking** (`react_fit`, `notify_fit`, `mail_fit`, `accessories_fit`,
  `weather_fit`, `stages_fit`): they set up one situation at a time, so most keep passing; any that combine (e.g.
  music + a reaction) are updated in the same commit and listed in the PR.
- **Window sizing**: the terminal leaving via `.on` must drop `sheetWant`, or the window stays wide.
- **Keyboard and code-eye placement per character**: checked by headless screenshots of all four (`--disable-gpu`
  only: a desktop Chrome preview hung the GPU before).
- **Focus changes** come from cards, notifications, agent events, props and situation signals; each is already rate
  limited (notification 5 s, `sitOn` 3 s on / 8 s off), so `focusSync()` runs a few times a minute, not per frame.
- **Hosts**: page only; every host running the companion picks it up on the next deploy.
