# Spec: A dark system board for "system status"

Code: `olafkfreund/nixoarchy-snowflake` (the companion). File and line
references are to `main` after PR #32. The news popout (#167) is built at the
same time. **Only part 1 (`say`) is shared, word for word in both specs:**
whichever lands first adds it, and the other finds it there. Each spec adds
only its own kind to `run_stage`, `validate()` and `Store.put()`.

## Design

### 1. A plugin may give a spoken line, `say` (shared with #167)

- **Every plugin kind may carry `say`:** at most 200 characters, no control
  characters (`_str`). `validate()` keeps it.
- **`Store.put()` drops it from the page copy** (`page.pop("say", None)`; the
  stage dict itself is left alone, so the copy in `plugins._cache` keeps it
  for the next cached ask).
- **The phrase path speaks it.** `plugin_stage()` (`app/server.py:4631`)
  returns `st.get("say") or "Here you go."` in place of the fixed
  "Here you go." (`server.py:4648`). As today, that text is spoken and shown as
  his caption (`_said`, `server.py:5681`). It never goes into a prompt, and
  Nixi doesn't log it.
- **The agent path doesn't.** When the agent asks for a plugin
  (`plugin_stage_thread`, `server.py:4651`) the agent has already spoken its
  own sentence, so `say` is not used there (unchanged).
- `facts` gains `say` too, so existing plugins can use it.

### 2. The `gauges` kind

`app/plugins.py:702` accepts `got["kind"] in ("facts", "gauges")` (#167 adds
`headlines`). A general kind: hosts, each with meters, badges and short
lists. v1 plugins send one host; up to six are accepted so #168 needs no
format change.

```json
{"v": 1, "kind": "gauges", "title": "System status", "say": "All fine. One failed service.",
 "source": "this computer", "live": true,
 "hosts": [{"name": "p620", "state": "up",
   "badges": [{"k": "gen", "v": "2944 · 26.11.20261101"}, {"k": "up", "v": "3 days 4 h"}],
   "meters": [{"label": "CPU", "pct": 18, "text": "18% · 32 threads"},
              {"label": "MEM", "pct": 42, "text": "26.8 / 64 GiB"},
              {"label": "/", "pct": 61, "text": "570 / 931 GiB"},
              {"label": "STORE", "pct": 54, "text": "495 / 915 GiB"},
              {"label": "NET ↓", "pct": null, "v": 1250000, "text": "1.2 MB/s"},
              {"label": "NET ↑", "pct": null, "v": 84000, "text": "84 kB/s"}],
   "lists": [{"title": "Failed", "items": ["nixi.service"], "tone": "bad"}]}]}
```

`validate()` (`app/stages.py:76`), unknown keys dropped, any failure → `None`:

| Field | Rule |
|---|---|
| `title` | `_str(…, 80)`, required |
| `say`, `source` | optional, `_str(…, 200)` / `_str(…, 120)` |
| `live` | optional, `True`/`False` only: the page may refresh it (part 4) |
| `hosts` | list of 1–6 |
| `host.name` | `_str(…, 32)` matching `[A-Za-z0-9._-]+` |
| `host.state` | `"up"` (default), `"down"` or `"stale"` |
| `host.badges` | ≤ 6 of `{k: _str(16), v: _str(60), tone?}` |
| `host.meters` | ≤ 8 of `{label: _str(12), pct: number 0–100 or null, v?: finite number ≥ 0, text?: _str(40), tone?}`; `bool`, NaN and ±inf refused (`type(x) in (int, float)` and `math.isfinite`) |
| `host.lists` | ≤ 2 of `{title: _str(24), items: ≤ 5 × _str(80), tone?}` |
| `tone` | `"ok"`, `"warn"` or `"bad"`; when absent the page derives it from `pct` (< 70 ok, 70–89 warn, ≥ 90 bad) |

`pct: null` means unavailable, shown as "—", never as 0 (intent outcome 5).
A plugin never sends a series: the page keeps the history (part 4). The output
cap stays 64 KiB (`OUT_CAP`).

**`Store.put(stage, refresh=None)`** (`stages.py:274`) gets a `gauges` branch:
- **Copy:** one token under `page["token"]` (the key `facts` uses, so voice
  "copy that" finds it, `server.py:5705`), holding a plain summary ("p620 ·
  CPU 18% · MEM 26.8 / 64 GiB · …").
- **Refresh:** when the stage is `live` and `refresh=(pid, query)` is given
  (by `plugin_stage`, which knows both), one token under `page["refresh"]`
  holding `("refresh", {"pid", "query"})`.

### 3. Host readings: `system-status` grows (`app/plugins.py:554`)

`system_status()` keeps `generation` and `failed` (user units) and adds:

| Key | Source | Note |
|---|---|---|
| `failed_system` | `systemctl --failed --plain --no-legend` | `null` if it fails |
| `cpu_pct` | `/proc/stat` | from the difference against the previous reading |
| `mem` | `/proc/meminfo` | `{total, available}` bytes |
| `disks` | `os.statvfs` of `/` and `/nix/store` | `{path, total, used}`, used = `(f_blocks - f_bfree) * f_frsize` (as `nix-status` does) |
| `net` | `/proc/net/dev`, all interfaces but `lo` | `{rx_bps, tx_bps}` from the difference |
| `uptime_s` | `/proc/uptime` | |
| `host` | `socket.gethostname()` | |

- **Rates need two readings.** The module keeps the last `/proc/stat` and
  `/proc/net/dev` counters with their time, primed when a plugin with
  `reads: ["system-status"]` is loaded (`Plug.reload`). It falls back to
  reading twice 250 ms apart only when it has no earlier reading at all. A
  negative difference (a counter reset) gives `null`, never a negative rate.
  Any value that can't be read is `null`.
- **Bounded:** the two `systemctl` calls run at once, 1 s each, so
  `system_status()` takes at most about 1.3 s even with a hung systemd.
- **The readings can't leave the machine.** Manifest validation (`_check`,
  `app/plugins.py:145`) refuses a stage that declares both `network: true`
  and `reads: ["system-status"]` ("a plugin that reads your system status
  can't use the network"). So a plugin that gets readings has no way to send
  them anywhere. Nixi never puts them in a prompt or its log. A plugin's own
  stderr still goes to the local server log, as today (`plugins.py:694`).
- **The consent card** (`index.html:3129`) names what "system status" now
  covers: "It can read your system status (load, memory, disks, network rates,
  failed services)". A plugin already allowed is not asked again: the data
  stays on this machine (above), and that was the boundary it was allowed
  under.

### 4. Live while visible (`index.html`, `server.py`, `stages.py`)

- **Page:** while a `gauges` stage with a `refresh` token is open, the page
  posts `/api/stage/act {token, act: "refresh"}` every **5 s**. It stops when
  the stage closes or collapses to its tab (`stgState !== 'open'`), when
  `document.hidden`, when the page isn't really showing it (`stgPosted` is
  false, `index.html:2212`), after a refresh answers `ok: false`, and after
  **24 refreshes (2 minutes)**.
- **Server, `stage_act(token, "refresh")`:**
  - only for a `("refresh", …)` token of the current stage;
  - refused while the screen is locked, asked directly (`Desk.locked()`, not
    `Ambient.locked`, which stays `False` while `proactive` is off);
  - runs `plugins.run_stage(p, query, fresh=True)`: a new keyword that skips
    the cache read and the stale-result fallback, still writes the cache, and
    still refuses a second run of the same plugin;
  - `Busy` → `{"ok": True, "skipped": True}`, nothing sent (a slow refresh is
    skipped, not queued); `StageError` → `{"ok": False}` and the page stops
    refreshing (`CHANGED` also calls `Plug.reload()`, as `plugin_stage` does);
  - on success, `Store.replace(refresh_token, stage)`.
- **`Store.replace(refresh_token, stage)`** (new): under the store's lock,
  only if the current entry still holds that refresh token (otherwise it
  returns `None` and nothing is sent, so a refresh that finishes after the
  board closed, or after another stage opened, never brings it back). It
  builds the new page with the **same** refresh and copy tokens, rewrites the
  copy token's text to the new summary, and keeps the entry's time. The
  server then publishes `stage_update` (not `stage`).
- **The page's `stage_update` handler** (new, beside `stage`, `index.html:2058`)
  updates the open `term` board in place: bars, numbers, badges, lists. It
  doesn't rebuild the card, re-run the entrance, move focus, or reset the
  stage timers. If no `gauges` board is open it ignores the event.
- **History** lives in the page: per host and meter label, the last 24 values
  (`pct`, or `v` when `pct` is null), drawn as a sparkline. It starts with the
  first reading and is dropped when the stage closes.
- **Staying up:** `stageTick` (`index.html:2362`) treats `gauges` as
  interactive; while it is refreshing it collapses after **2 minutes** without
  use instead of 30 s. `idleShowing()` (`index.html:3370`) counts a refreshing
  board as showing, so Nixi doesn't shrink to the corner after 45 s
  (`IDLE_SHRINK`) under it.
- **Budget:** p95 of a refresh (request to `stage_update`) under 400 ms on
  p620 and 800 ms on razer; worst case bounded by `system_status()` (about
  1.3 s) plus the plugin limit (3 s), and then skipped, not queued.
  `nix-status` sets `cache_seconds: 4`.

### 5. The `term` set: the board's look (`index.html`)

- **A new stage set `term`,** chosen for kind `gauges` beside board / map /
  cinema / sky / desk / notebook (`index.html:2221-2223`).
- **Colours from the omarchy theme** the page already applies
  (`info.theme` through `applyThemeVars`, `index.html:960`): background and
  foreground, and `red`, `green`, `yellow` when the theme has them (they're
  optional in `colors.toml`, `server.py:298`), else fixed fallbacks
  (`#e06c75`, `#98c379`, `#e5c07b`). The panel background is the theme's
  background at 96% opacity, never the cream paper. Text in `var(--mono)`
  (`index.html:12`).
- **btop-like layout:** one panel per host, with a 1 px border in the dim
  foreground and the host name set into the top border ("┤ p620 ├", the
  corners drawn in CSS). Inside: badges on one line; each meter as a row
  `LABEL ▕████▌     ▏ 18% · text` (a CSS bar, not characters) followed by a
  braille sparkline of its history (8 levels, `⠀`–`⣿`, built from the numbers
  by the page); lists below (failed units in red).
- **Accessible:** each meter row carries its value as text ("18%", "—" when
  unavailable), so colour never carries meaning alone; the sparkline is
  `aria-hidden` and the row's `aria-label` reads "CPU 18 percent". Esc closes
  as for every stage. Text contrast ≥ 4.5:1 (#155); when the theme's pair is
  under that (a light theme), the set uses a fixed dark palette.
- **Size:** within the frame's budget (about 340 px wide beside him,
  `stagePlace`, `index.html:2214`); rows scroll inside the panel past eight
  meters.
- **Entrance, "power on":** the card opens from a 2 px line to full height
  (`scaleY`, 180 ms), the rows appear top to bottom 30 ms apart, and each bar
  fills from 0 to its value (200 ms). Updates move bars and numbers without
  the entrance. Under reduced motion (`REDUCED.matches`): no scale, stagger or
  fill; values just change.

### 6. Accessible text

`stageText()` (`index.html:2336`) gets a `gauges` branch (title, then one line
per meter) for screen readers.

### 7. `nix-status` becomes a `gauges` plugin (`plugins/examples/nix-status/`)

- `run` builds one host from `system_status` (part 3): CPU, MEM, `/`, STORE,
  NET ↓, NET ↑ meters; `gen` and `up` badges; a "Failed" list with user and
  system units (tone `bad`), or "none" (tone `ok`). It sets `live: true`. It
  still uses `os.statvfs` for the store when `disks` is missing (an older
  Nixi).
- `say`: "All fine." / "One failed service: X." / "N failed services.", plus
  "Memory is high." when MEM ≥ 90%.
- `plugin.json`: `cache_seconds: 4`; phrases, `reads` and no-network
  unchanged.
- **Hash:** the folder changes, so a user who allowed a copied `nix-status`
  sees "Changed — check it again" once; a Nix-installed one shows "Updated"
  (the #149 design). The README says so, and that it needs this Nixi version
  (an older one refuses `gauges`: "it gave something Nixi can't show").

## Alternatives rejected

- **A `sysboard` kind made only for system status** (Codex): fewer choices,
  but #168 and other number plugins (UPS, GPU, build queue) would each need
  their own kind and renderer. The user chose the general look.
- **The plugin streams, or stays running:** a long-lived process in the
  sandbox and a new protocol. Re-running per refresh reuses what #149 checks
  (hash, caps, timeout).
- **The plugin reads `/proc` itself:** inside bwrap `/proc/stat` and
  `/proc/meminfo` do show the host, but network counters are the sandbox's
  own, systemd isn't reachable, and it would be host access no consent named.
- **The plugin sends sparkline series:** a fresh sandbox has no memory of
  earlier runs, so the series would come from Nixi anyway. The page keeps it.
- **Server-side sampling on a timer:** sampling would no longer stop just
  because the page stopped asking. The page drives it.
- **A new `stage` event per refresh:** it re-runs the entrance and resets the
  timers and focus every 5 s. `stage_update` changes values in place.
- **Asking again for consent when `system-status` grows:** the network rule
  keeps the data on the machine whatever the plugin does with it, which is
  what the original consent allowed.
- **Box-drawing characters for the panels:** they break on fallback fonts and
  odd widths. CSS borders with the name notched in look the same and reflow.

## Risks

- **A sandbox start every 5 s while open.** Bounded by the 2-minute cap, the
  `Busy` skip and the budget in part 4; measured on p620 and razer.
- **CPU % on a cold first open** is a 250 ms sample, so it can be jumpy; later
  ones are 5 s averages.
- **A refresh racing a close or another stage:** `Store.replace` only updates
  the stage that asked; tested.
- **A plugin that wanted both network and system status** (none exists) is
  now refused at load, with a clear note in Settings.

## Verification

- **Unit (fork, `python3 -m unittest discover -s tests`):**
  - `validate()` for `gauges`: a full example passes; each rule in part 2's
    table refuses its bad case (7 hosts, 9 meters, `pct` 101, NaN, `True` as a
    number, a bad host name, a 61-character badge, `live: 1`); unknown keys
    are dropped; `say` over 200 characters refused.
  - `run_stage` accepts `gauges`, refuses `commands`; `fresh=True` skips the
    cache and the stale fallback.
  - `say`: the phrase path returns it; the page event has none; the cached
    stage still has it on the second ask; no `say` → "Here you go.".
  - `_check`: `network: true` with `reads: ["system-status"]` refused.
  - `system_status()` with fake `/proc` files: rates from two readings, a
    counter reset gives `null`, an unreadable file gives `null`; a `systemctl`
    that hangs returns within 1.3 s.
  - `stage_act(refresh)`: only the current stage's refresh token; refused when
    `Desk.locked()` is true; `Busy` → skipped; after a refresh the tokens are
    the same and Copy gives the new numbers; a refresh finishing after
    `close` or after another `put` changes nothing and sends nothing.
  - `nix-status` in the real sandbox (`tests/test_plugin_sandbox.py`):
    returns valid `gauges` with a `say`.
- **Page (headless Chromium, `--disable-gpu`):** a `gauges` stage renders in
  the `term` set; a `stage_update` changes bars and numbers without the
  entrance, focus moving or the timer resetting; refreshes stop on close, on
  collapse, on `ok: false` and after 24; Nixi doesn't shrink while it
  refreshes; reduced motion shows no animation; a theme without red / green /
  yellow uses the fallbacks.
- **Budget:** 24 refreshes each on p620 and razer; p95 under 400 ms and
  800 ms.
- **Live on p620:** "system status" shows the dark board with this host's
  readings and he says the spoken line; it updates for 2 minutes and
  collapses; closing it stops the refresh requests (server log); locking the
  screen stops them; a failed unit shows in red with its name.
