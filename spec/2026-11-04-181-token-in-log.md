# Spec: keep the window token out of server.log

All code is in olafkfreund/nixoarchy-snowflake.

## Design

**The window gives the page its token through a WebKit user script, not the
URL.** The window loads the plain URL (`http://127.0.0.1:<port>/?native=1`),
so whatever WebKit prints as a source URL holds no secret.

1. `app/window.py`, `_authed_url()` (around line 1252) becomes `_token()`. It
   reads the token from runtime.json with the same 5 s wait, and returns `""`
   if it can't.
2. A new `_hand_token()` method:
   - calls `ucm.remove_all_scripts()`;
   - when the token is non-empty, adds
     `WebKit2.UserScript.new(f"window.__nixiT={json.dumps(tok)};", TOP_FRAME,
     START, [f"http://127.0.0.1:{port}/*"], None)`.

   `ucm` (line 367) is kept as `self.ucm`. The allow-list limits the script
   to the companion's own origin, so a link opened in the view can't read
   the token.
3. Wherever `load_uri(self._authed_url())` appears (line 392 at start, line
   1271 on `reauth`), it becomes `self._hand_token();
   self.view.load_uri(self.url)`. On `reauth` the old script is removed first,
   so the new token replaces it.
4. `app/static/index.html`, `tokenReady` (line 948): the first branch becomes
   `if(window.__nixiT){ TOKEN=window.__nixiT; delete window.__nixiT; } else
   if(h.get('t')) …`. The `#t=` and `#ticket=` paths stay, for the page
   tests and the browser fallback.
5. Console logging (line 378) stays on.
6. **New:** `v.connect("load-failed", …)` retries after 1 s with
   `self._hand_token(); self.view.load_uri(self.url)`, and returns `True` so
   WebKit doesn't show its error page. Today the window has no retry when a
   load fails (only `web-process-terminated`, line 386). This covers a window
   that starts before the server, or one that read a `runtime.json` left over
   from an earlier run: each retry reads the token again.
7. **The script is built by a pure helper,** `token_script(tok, port)` in
   `app/window.py`. It returns `(source, allow_list)` and is unit-tested
   without GTK.

This covers the intent's cases:
- **Window starts before the server:** `_token()` waits, as now. The page
  load then fails while the server is down, and step 6 retries every second,
  reading the token again each time, until the server answers. If the
  server is up but the token was stale, the page's 403 → `reauth` path
  (`staleToken`, line 965) brings the new one through step 3.
- **Server restart:** the same `reauth` path.
- **A failed claim** can't happen: there's no claim and no expiry.
- **Nothing is ever a bearer value in a URL.**

## Alternatives rejected

- **A one-time ticket in the URL (`#ticket=`).** A ticket is a bearer
  credential until it's claimed (Codex's review of the intent): if WebKit
  prints the URL before the page claims it, a local reader of the log can
  claim it first and get the token. It also adds a request, a 60 s expiry
  and a failed-claim path, which the user script doesn't need.
- **Turning console-to-stdout off.** It would fix the leak but lose the page
  errors that `nixi-companion log` exists to show.
- **Passing the token with `evaluate_javascript` after load.** The page's
  first requests would race it; `tokenReady` would have to wait for a
  message. The user script runs before any page script, so there's no race.
- **Redacting stdout in the window or server.** WebKit's web process writes
  to the inherited fd itself, so there's nothing in between to filter
  without a pipe-and-rewrite thread. More code, and a new failure mode.

## Risks

- **The WebKit2 4.1 `UserScript` signature:**
  `new(source, injected_frames, injection_time, allow_list, block_list)`.
  A wrong enum name fails at window start, on p620 and razer alike. Step
  check: start the window from the worktree on a test port.
- **Allow-list pattern syntax.** If it doesn't match, the page gets no token,
  shows as signed out, and keeps sending `reauth`. Caught by the same live
  check: the window must work after start and after a server restart.
- **`delete window.__nixiT`** runs after `TOKEN` is set. Other user scripts
  can't read it later, and the token is still in `TOKEN` and
  `sessionStorage`, as now.
- **The browser fallback** is unchanged (it still uses `#ticket=`).
- **The user script's source holds the token.** WebKit isn't known to print
  a user script's source, and the script is one assignment that can't throw.
  The live check below looks for the token pattern itself, not only `#t=`.
  With `NIXI_COMPANION_DEVTOOLS=1`, DevTools can see the token. That's as
  now: it's an opt-in debugging switch for the user's own window.
- **`load-failed` also fires for a navigation the user starts** (a link). The
  retry only reloads `self.url` when the failed URI is under the server's
  origin.

## Verification

- **Unit test** (`tests/test_window_token.py`, no display needed):
  - `token_script("abc", 47777)` returns source `window.__nixiT="abc";` and
    allow-list `["http://127.0.0.1:47777/*"]`, and escapes a quote in the
    token;
  - with `gi` stubbed in `sys.modules` (a fake WebKit2 that records calls),
    the start path and the `reauth` and `load-failed` paths each call
    `remove_all_scripts`, then `add_script`, then `load_uri(self.url)`, with
    no `#` in the URI.
- **Page test:** the existing `*_fit` tests still pass with `#t=`. One new
  case sets `window.__nixiT` before load and checks that the page
  authenticates (a 200 from `/api/settings`) with no `#` in the URL.
- **Full suite** from `tests/` and `nix build .#nixi-companion`.
- **Live on p620,** after the bump and deploy (user-approved hosts only):
  1. note the log's size (`stat -c %s`), restart the companion and trigger
     a console line;
  2. from that offset only (`tail -c +<size+1>`), count `#t=`, `__nixiT` and
     any 32-character token-like string: all 0;
  3. the window works;
  4. `nixi-companion restart` again: the window recovers through `reauth`.
