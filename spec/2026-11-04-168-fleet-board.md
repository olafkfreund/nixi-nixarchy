# Spec: The system board shows the user's other machines

Code: `olafkfreund/nixoarchy-snowflake` (the companion; references are to the
#166 branch at baa53ca, which this builds on and which must merge first),
this repo's Home Manager module (`nix/hm-module.nix`), and the user's NixOS
config (`~/.config/nixos`). #166's `gauges` kind already takes up to six hosts
and `state: up | down | stale` (#166 spec part 2), so the plugin format
doesn't change.

Facts checked on 2026-11-04:
- `getent hosts p510` gives `192.168.1.65` (the LAN); only `razer` resolves to
  its tailnet name. Names are not a safe way to reach a peer.
- p620's tailscale reports it can't reach its DNS servers.
- `nixos-version --json` has no `configurationRevision`.
- Store paths have mtime 1 (`/run/current-system`'s target), so they can't
  date a build; `/nix/var/nix/profiles/system` has the real time.
- `_run_copy` builds the plugin's feed before its 3 s deadline starts
  (`app/plugins.py:739` vs `:766`), so anything slow in the feed adds to it.
- `_rates()` keeps one last reading with no maximum age (`plugins.py:597`).
- Plugin stderr goes to the server log (`plugins.py:784`).
- The agent's environment drops only `NOT_PASSED` (`server.py:4272`).

## Amendment needed: decision 2 can't be met as written

Decision 2 says the token is one "only Nixi's service can read". The companion
runs as the user (a Home Manager user service), so **anything Nixi can read,
any program running as the user can read too**; a file mode can't tell them
apart, and neither can a local socket. What the token does stop: other
machines on the tailnet, other users on a companion host, and anything that
can reach the port but isn't one of the user's own companions.

**Proposed amendment (recommended):** the token is readable by the user on
companion hosts and stops everything except the user's own programs. A
program running as the user can already read the user's SSH keys, browser and
mail; fleet status is less than that. **The alternative** is running the
companion as its own system user, which changes how it reaches the desktop,
audio and the user's files, and is a task of its own. Approving this spec
approves the amendment; the intent file gets a note in the same commit.

## Design

### 1. `nixi-status`: the answering service (snowflake, `app/status_serve.py`)

- **A small stdlib-Python HTTP server** (`http.server.ThreadingHTTPServer`),
  shipped in the snowflake package as `bin/nixi-status`. One endpoint,
  `GET /v1/status`; anything else → 404. Nothing it offers changes the
  machine (intent outcome 5).
- **It listens only on this host's tailnet IPv4 address** (from the fleet
  list, part 4), not `0.0.0.0`: the LAN can't even connect. If tailscale isn't
  up yet the bind fails and systemd retries (`Restart=always`,
  `RestartSec=5`).
- **What it returns** (JSON, at most 16 KiB), from `system_status(user=False)`
  (part 3): `host`, `cpu_pct`, `mem`, `disks`, `net`, `uptime_s`,
  `failed_system`, `generation`, `rev`, `built`; and `failed: null` (a system
  service has no user session to ask: "unavailable", intent outcome 2).
- **Who may ask, checked on every request:**
  1. the source address is exactly one of the allowed callers' tailnet
     addresses (from the fleet list; no DNS at all, so the short-name and
     MagicDNS problems above can't apply, and Tailscale's own `100.100.100.100`
     is never on the list);
  2. `Authorization: Bearer <token>` matches (`hmac.compare_digest`).
  Any failure → 403 with the same body; nothing is logged per request.
- **Bounded:** at most 4 requests at once (a semaphore; more → 503), threads
  with a 256 KiB stack, a 2 s socket timeout. A request takes a reading at
  most once a second; a second caller within that second gets the same one.
- **No journal line per request** (`log_message` silenced); only start-up
  and a crash are logged, never a reading or a caller.

### 2. The NixOS module (snowflake flake, `nixosModules.status`)

```nix
services.nixi-status = {
  enable = false;          # off until a host turns it on
  address = null;          # this host's tailnet IPv4; required
  port = 9188;
  allowedCallers = [ ];    # tailnet IPv4 addresses
  tokenFile = null;        # agenix path; required
};
```

- **systemd service `nixi-status`:** `DynamicUser=true`,
  `LoadCredential=token:${tokenFile}` (read from `$CREDENTIALS_DIRECTORY`,
  never the store), `ProtectSystem=strict`, `ProtectHome=true`,
  `PrivateTmp=true`, `NoNewPrivileges=true`, `CapabilityBoundingSet=`,
  `RestrictAddressFamilies=AF_INET AF_UNIX` (AF_UNIX for the system bus that
  `systemctl --failed` uses), `MemoryMax=64M`; `after` and `wants`
  `tailscaled.service`; `path` gets `systemd` (for `systemctl`).
- **Firewall:** the port goes into
  `networking.firewall.interfaces.${config.services.tailscale.interfaceName}.allowedTCPPorts`,
  never the global list.
- **Assertions:** `services.tailscale.enable`; `address`, `tokenFile` set;
  `allowedCallers` non-empty and every entry in `100.64.0.0/10` but not
  `100.100.100.100`.

### 3. Readings: `system_status()` grows twice more (`app/plugins.py`)

- **`rev` and `built`, for this host too** (so this host shows them and peers
  can be compared with it, decision 7): `rev` from
  `/run/current-system/sw/bin/nixos-version --json` (`configurationRevision`,
  `null` if unset), `built` from the mtime of `/nix/var/nix/profiles/system`
  (when this generation was made on this host). Both cached per
  `/run/current-system` target, so they cost nothing after the first read.
- **`user=False`** skips `systemctl --user` (the service has no user bus) and
  returns `failed: null`.
- **Rates with a maximum age:** a last reading older than 30 s is treated as
  none (the 250 ms double read), so the first ask after hours gives current
  load, not an 8-hour average. Two callers within a second share a reading.

### 4. The fleet list, the peers and the token (NixOS config + HM module)

- **Declared once** (decision 3) in `~/.config/nixos/hosts/common/nixos/`
  as `nixiFleet`: `{ name, address, companion }` for p620, p510 and razer,
  with their tailnet IPv4 addresses (stable per node; `tailscale ip -4`).
- **Each host enables `nixi-status` only if it is in `nixiFleet`** (by
  `networking.hostName`), never by importing `common` alone, with `address`
  its own entry and `allowedCallers` the companion hosts' addresses **except
  its own**.
- **The companion hosts** set the new HM option `services.nixi.companion.peers`
  (this repo, `nix/hm-module.nix`) to every *other* host's
  `{ name, address, port }`, and `services.nixi.companion.peerTokenFile`.
- **The HM module** writes `~/.config/nixi-companion/peers.json` with the
  peers and the token's *path* (no secret in it). No environment variable, so
  nothing new reaches the agent's environment. With `peers = [ ]` (the
  default) the file doesn't exist and nothing in this spec runs.
- **The token:** one agenix secret `nixi-status-token` (32 random bytes,
  base64) on every fleet host. On p510: owner root (read by `LoadCredential`).
  On p620 and razer: owner `olafkfreund`, mode 0400 (root reads it anyway for
  `LoadCredential`). One fleet token, not one per pair: every caller is the
  same user's companion (and see the amendment above).

### 5. The collector in Nixi (snowflake, `app/peers.py`): never in the way

- **The board never waits for a peer** (intent outcome 6). `peers.snapshot()`
  returns at once with what the collector has, and starts a round in the
  background if none is running. One round at a time, so slow peers can't
  pile threads up.
- **A round** asks every peer in parallel over plain HTTP on the tailnet
  (WireGuard encrypts and authenticates the node behind each address), with
  `http.client.HTTPConnection(address, port, timeout=1.5)` to the configured
  address (no DNS, no redirects followed: anything but 200 is a failure). The
  whole round ends by 2 s.
- **Each answer is untrusted input:** at most 16 KiB, JSON, each key checked
  against part 1's types; anything wrong → `down`, "gave an answer Nixi can't
  read".
- **Per peer:** `{name, state: "up" | "down" | "asking", status | null,
  last_ok}`; `asking` before its first answer this session; `last_ok` kept in
  memory only (decision 8).
- **When a round finishes while a live board is open,** the server refreshes
  it at once (#166's `stage_act(refresh)` path, run server-side, ending in
  `Store.replace` and `stage_update`), so peers arrive about 1.5 s after this
  host's section, not 5 s later. Later rounds start with each 5 s refresh.
- **Budget:** a refresh never waits on peers, so #166's p95 targets (400 ms
  p620, 800 ms razer) and its 3 s limit stand unchanged.

### 6. The capability, the switch and withdrawal

- **A second read, `peer-status`** (`app/plugins.py:156` accepts
  `("system-status", "peer-status")`). `_check` refuses it with
  `network: true`, as #166 does for `system-status`.
- **The "Other machines" switch** is the consent (decision: in Nixi's
  settings): a row in Settings → Plugins, off by default, shown only when
  `peers.json` lists a peer: "Let plugins show your other machines' status
  (load, memory, disks, failed services)". It is stored in Nixi's settings.
- **Asked once on the board:** while it's off and peers are configured, a
  `gauges` board from a plugin that reads `peer-status` gets one extra line
  under this host: "2 other machines · Show them · Not now". "Show them" turns
  the switch on; either button sets a remembered `peers_asked` flag, after
  which the line never shows again and only Settings changes the switch
  (asked once, intent outcome 4).
- **Feed:** `run_stage` adds `feed["peers"]` (`peers.snapshot()`) only when the
  plugin declares `peer-status`, it's allowed to run (#149), and the switch is
  on.
- **Off means gone at once:** turning the switch off stops the collector,
  discards a round in flight (a round counter; a late result is dropped),
  clears every peer result and `last_ok`, drops the plugin's cached stage
  (`plugins._cache`), and closes an open board that shows peers
  (`Store.close`), so no peer reading stays on screen or comes back.
- **Not in a log:** a plugin that declares any `reads` has its stderr dropped
  (its length is logged, not its text), so it can't print readings into the
  server log.
- **Not in a prompt:** `feed["peers"]` reaches only the sandboxed plugin. The
  agent path (`plugin_stage_thread`, `server.py:4651`) gives the agent only
  whether the stage showed; the plan checks this and changes it for `gauges`
  if it gives more.

### 7. `nix-status` shows the fleet (`plugins/examples/nix-status/`)

- `plugin.json`: `reads: ["system-status", "peer-status"]`.
- **Hosts:** this host as #166, now with `rev` and `built` badges; then each
  peer in fleet order (at most six in all):
  - `up`: CPU, MEM, `/`, STORE meters; `rev`, `built`, `up` badges; a
    "Failed (system)" list; the badge `user —` (unavailable, never "none");
  - `asking`: `state: "stale"`, one badge "asking…";
  - `down`: `state: "down"`, one badge `last` = "not seen yet" or "14:02".
- **Revisions** (decision 7): a peer's `rev` badge always shows its own 7
  characters; if it differs from this host's, the badge gets tone `warn` and
  "≠" before it ("≠ a1b2c3d"). If either side is `null`, no comparison: "—".
- **`say`, problems only, about the whole fleet** (decision 5): all problems
  in one list, this host's first with #166's wording (it may name this host's
  unit), then peers without unit names ("p510 has one failed service.", "razer
  is off.", "p510 is on another revision."). Nothing wrong anywhere and at
  least one peer up: "All machines look fine."; no peers shown: #166's line.
  Capped at 200 characters, then "and N more.". A peer still `asking` isn't a
  problem.
- The folder changes, so #149's "Changed" / "Updated" note shows once.

### 8. The board with several hosts (`index.html`, the `term` set)

- **One board** (decision 4): this host full, as #166; each peer a **compact
  panel** (name in the border, badges, one row per meter without a
  sparkline, failed count). Click or Enter expands one peer (and collapses the
  others); history is kept per host from the start, so it has sparklines once
  expanded.
- **`down` and `asking` peers** are one line each ("┤ razer ├ unreachable ·
  not seen yet", "┤ p510 ├ asking…") in the dim foreground; never empty
  meters or zeros.
- **Size:** within #166's 340 px; it scrolls inside past its maximum height.
  One full and two compact hosts fit unscrolled at 1080p.
- **Accessible:** compact panels are buttons with `aria-expanded`; rows keep
  their text values; `stageText()` reads every host, this one first. #166's
  reduced-motion, contrast and Esc rules apply.

## Alternatives rejected

- **Prometheus node exporter:** no generation, revision or failed-unit names
  without extra collectors, and far more data than the board uses.
- **The companion headless on p510:** a desktop app run on a server to answer
  one GET.
- **SSH to each peer:** a key the companion would hold, and a shell where a
  read-only answer is wanted; the intent forbids both.
- **MagicDNS names** (the first draft): `p510` resolves to the LAN, p620's DNS
  is failing today, a blocking lookup can't be timed out, and a DNS answer
  doesn't prove which node is behind it. Tailnet addresses in the config have
  none of these problems; a node re-added to the tailnet needs its address
  updated in one place.
- **`tailscale whois` to check the caller:** needs the tailscaled LocalAPI
  inside a `DynamicUser` service; an exact address list gives the same answer.
- **`tailscale serve` with identity headers:** names the tailnet user, not the
  machine, and is set up imperatively per host.
- **Collecting before the plugin runs** (the first draft): a sleeping razer
  would hold every board and refresh 1.5 s, and the feed is built before the
  plugin's deadline starts.
- **A token per pair, mTLS or HTTPS:** more secrets and renewals for the same
  callers; WireGuard already encrypts and authenticates between nodes.
- **Asking peers on a timer, "last seen" on disk:** traffic nobody looks at,
  and state the intent ruled out (decision 8).
- **Peers added by Nixi past the plugin:** the plugin then couldn't speak
  about them (decision 9).
- **A build date from the store path's mtime:** it is 1 for every store path.

## Risks

- **A tailnet address changes** (a node removed and re-added): that peer shows
  `down` and its own service refuses to start (bind fails) until the fleet
  list is updated. Fails closed.
- **Same-UID programs can use the token** (the amendment): they can read
  fleet status, nothing more; rotation is one agenix rekey and a deploy.
- **`system.configurationRevision` changes every host's closure** each
  commit (one more rebuild per host, which the intent already requires).
- **p510 is a server:** the service is a new unit; nothing else restarts.
  Memory measured under 64 MiB.
- **A stage closed by the switch** while the user reads it: intended (the
  user withdrew consent); the toast says why.

## Verification

- **Unit (snowflake, `python3 -m unittest discover -s tests`):**
  - `status_serve`: a caller address not on the list → 403; wrong or no token
    → 403; right one → 200 with the keys of part 1 and `failed: null`; `POST`
    or another path → 404; the captured log has no request lines; a fifth
    parallel request → 503.
  - `system_status(user=False)` runs no `systemctl --user`; `rev` / `built`
    read once per target; a last reading 31 s old gives a fresh sample.
  - `peers.snapshot()` returns at once; one up, one timing out and one 65 KiB
    peer end up up / down / down within 2 s; a redirect is a failure; only one
    round runs at a time; a round finishing after the switch went off changes
    nothing.
  - `_check`: `peer-status` with `network: true` refused.
  - `run_stage`: no `feed["peers"]` with the switch off; turning it off clears
    the collector and cache and closes a board with peers; a plugin with
    `reads` has its stderr text kept out of the log.
  - `nix-status` in the real sandbox: one host without peers (as #166); with
    an up, an asking and a down peer, valid `gauges` with four hosts; `say`
    names no peer unit; "All machines look fine." when all are fine; a
    different `rev` gives "≠".
- **Nix:** `nix flake check` in the snowflake (assertions fire on a missing
  `address` / `tokenFile`, an empty list, `100.100.100.100`); `nix build` of
  p620, p510 and razer.
- **Page (headless Chromium):** one full and two compact hosts; `down` and
  `asking` lines; Enter expands; "Show them" turns the switch on;
  `stageText()` reads every host.
- **Live:**
  - from p620: `curl -H "Authorization: Bearer …" http://<p510 tailnet
    IP>:9188/v1/status` → 200; without the token → 403; to
    `192.168.1.65:9188` → connection refused;
  - after 24 refreshes, `journalctl -u nixi-status` on p510 has no request
    lines;
  - "system status" on p620: this host at once with "2 other machines · Show
    them"; after "Show them", p510 within about 2 s and razer "unreachable ·
    not seen yet" while it sleeps; he says "razer is off."; switching off in
    Settings closes the board, and the next ask shows one host;
  - the same from razer, with p620 as a peer.
